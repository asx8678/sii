### Goal
Only you can use the cockpit. The cockpit can approve merges and control sessions, and anything on your machine (another program, a web page in your browser) can reach `127.0.0.1:4040`, so browser access needs a login token and strict origin checks.

### Context
`02-repo-layout.md` §5 (`$SI_HOME`). The bridge socket has its own token (T04.02) and is not affected.

### Deliverables
- `$SI_HOME/cockpit_token` (created at boot like the bridge token, mode 0600) via `Si.Paths.cockpit_token_file/0`.
- `SiWeb.LoginController` (`GET /login?token=...`), plug `SiWeb.Plugs.RequireCockpitSession`, LiveView `on_mount` hook `SiWeb.CockpitAuth`.
- CLI `si open` (prints the login URL and opens it with `open` on macOS or `xdg-open` on Linux).
- Endpoint `check_origin` restricted to `//127.0.0.1:<port>` and `//localhost:<port>`.
- Settings `cockpit.require_token` (default true; tests may set false).
- Tests `test/si_web/cockpit_auth_test.exs`.

### Specification
- `/login?token=<t>`: `Plug.Crypto.secure_compare/2` against the token file; on success put `cockpit: true` in the signed session cookie (`http_only: true`, `same_site: "Strict"`) and redirect to `/`; otherwise respond 401 with the text `Open the cockpit with: si open`.
- The browser pipeline requires the session for every route except `/health` and `/login`; without it → the same 401 page. The LiveView `on_mount` hook halts mounts without `cockpit: true` in the session.
- Phoenix CSRF protection stays on for all forms; LiveView uses the CSRF token from the page (default in Phoenix 1.8).
- `si open`: reads the token and port, prints `http://127.0.0.1:<port>/login?token=<token>`, and opens it.

### Tests
No session → 401 on `/reviews`; wrong token → 401; right token → cookie set and `/reviews` renders; LiveView mount without the session is halted; `/health` works without the session; a WebSocket connect with `Origin: http://evil.example` is refused.

### Acceptance criteria
Tests pass; `bin/ci` passes; `si open` logs you into the cockpit in a browser.

### Verify
```bash

bin/si open | sed -E 's/token=[^[:space:]]+/token=<hidden>/'   # never print the token
```

**Expected result.**
- Every browser route except `/health` and `/login` needs a session.
- The session comes from `/login?token=…`: a signed, `HttpOnly`, `SameSite=Strict` cookie.
- LiveView mounts check the session again in `on_mount`.
- WebSocket origins are limited to 127.0.0.1 and localhost.
- The token file has mode 0600.
- `si open` prints and opens the login URL.

**Checks**
1. `stat -f '%Lp' ~/.si/cockpit_token`.
   Expected: `600`.
2. With the server running, and without a session: `curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:4040/reviews`, then the same for `/health`.
   Expected: `401`, then `200`.
3. Log in without printing the token. Run `t=$(cat ~/.si/cockpit_token); curl -s -c "$TMPDIR/jar" -o /dev/null -w '%{http_code}\n' "http://127.0.0.1:4040/login?token=$t"; curl -s -b "$TMPDIR/jar" -o /dev/null -w '%{http_code}\n' http://127.0.0.1:4040/reviews`.
   Expected: `302`, then `200`.
4. `curl -s -D - -o /dev/null "http://127.0.0.1:4040/login?token=$t" | grep -ioE 'httponly|samesite=strict' | sort -u`.
   Expected: both flags. Print only the flags, never the cookie.
5. A wrong token.
   Expected: `401` and the body `Open the cockpit with: si open`.
6. `grep -rlF -f ~/.si/cockpit_token ~/.si/logs 2>/dev/null | wc -l`.
   Expected: `0` (the token is never logged).

**Redo if**
- The token is compared with `==`. Use `Plug.Crypto.secure_compare/2`.
- LiveViews rely only on the plug and have no `on_mount` check. Add the hook: both layers are required.
