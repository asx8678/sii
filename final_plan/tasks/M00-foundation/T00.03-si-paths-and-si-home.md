### Goal
One module that knows every file and directory Si uses, so no other code builds paths by hand.

### Context
`02-repo-layout.md` §5 (`$SI_HOME` layout) and §6 (environment variables).

### Deliverables
- `lib/si/paths.ex` (`Si.Paths`).
- `test/si/paths_test.exs`.
- `Si.Application.start/2` calls `Si.Paths.ensure!/0` before starting children.

### Specification
Home resolution order: `Application.get_env(:si, :home)` (explicit config; used by tests) → `System.get_env("SI_HOME")` → `Path.expand("~/.si")`. The result is always an absolute, expanded path.

Functions (all return absolute paths as strings; none of them touch the filesystem except `ensure!/0` and `write_secret!/2`):

```elixir
@spec home() :: Path.t()
@spec ensure!() :: :ok            # mkdir -p home and the fixed subdirs, chmod 0700 on home
@spec config_file() :: Path.t()   # home/config.yml
@spec db_file() :: Path.t()       # home/si.db
@spec cookie_file() :: Path.t()   # home/cookie
@spec bridge_token_file() :: Path.t()
@spec toolchains_dir() :: Path.t()
@spec toolchain_dir(String.t()) :: Path.t()
@spec profiles_dir() :: Path.t()
@spec profile_dir(String.t()) :: Path.t()
@spec sessions_dir() :: Path.t()                     # Pi session store for Si sessions (passed with --session-dir; Pi names the files)
@spec cockpit_token_file() :: Path.t()               # home/cockpit_token (T00.12)
@spec pid_file() :: Path.t()                         # home/si.pid (single-instance guard, T00.09)
@spec node_log() :: Path.t()                         # logs/node.log (T11.12)
@spec worktrees_dir(String.t()) :: Path.t()          # worktrees/<repo_id>
@spec worktree_dir(String.t(), String.t()) :: Path.t()
@spec checks_dir(String.t()) :: Path.t()             # checks/<repo_id>
@spec check_slot_dir(String.t(), non_neg_integer()) :: Path.t()
@spec queue_dir(String.t()) :: Path.t()
@spec logs_dir() :: Path.t()
@spec check_log(String.t(), String.t()) :: Path.t()  # logs/checks/<snp_id>/<check>.log
@spec session_stderr_log(String.t()) :: Path.t()     # logs/sessions/<ses_id>.stderr.log
@spec patches_dir() :: Path.t()
@spec backups_dir() :: Path.t()
@spec evals_dir() :: Path.t()
@spec write_secret!(Path.t(), iodata()) :: :ok       # atomic write (tmp + rename), mode 0600
```

`ensure!/0` creates: home, `toolchains`, `profiles`, `sessions`, `worktrees`, `checks`, `queue`, `logs/checks`, `logs/sessions`, `patches`, `backups`, `evals`. It sets `0700` on home only. It is idempotent.

`write_secret!/2`: write to `path <> ".tmp-" <> random`, `File.chmod!(tmp, 0o600)` **before** writing content (open with `File.open(tmp, [:write, :exclusive])`), `:file.datasync/1` the handle before closing it, then `File.rename!/2`. (A directory fsync is not available from the BEAM; SQLite holds all critical state. Pair F-29.)

Tests configure the home in `config/test.exs`, so it applies before the application starts (`mix test` starts the app before it loads `test_helper.exs`): `config :si, home: Path.join(System.tmp_dir!(), "si_test_home_#{:erlang.phash2(__DIR__)}_#{System.get_env("MIX_TEST_PARTITION")}")`. A test run therefore never reads or writes the real `~/.si`: your settings, pid file and database stay untouched, even while your own Si node runs. Tests that need an empty home create one (T00.11 adds `Si.Test.Home.tmp_home!/1` for this).

### Tests
`test/si/paths_test.exs`:
- `home/0` uses the application env when set.
- With the application env deleted and `SI_HOME` set (use `System.put_env` + `on_exit` restore), `home/0` returns the env value expanded.
- With neither, `home/0` ends with `/.si` (do not create it).
- `ensure!/0` creates all subdirs; home mode is `0o700` (`File.stat!(home).mode &&& 0o777`).
- `ensure!/0` twice does not fail.
- `write_secret!/2` creates a file with mode `0o600` and the exact content; overwriting keeps `0o600`.
- Every function returns an absolute path (`Path.type(p) == :absolute`).
- In the test environment, `home/0` is under `System.tmp_dir!()` before any test changes it (the suite never uses `~/.si`).

### Acceptance criteria
1. All tests pass; `bin/ci` passes.
2. No other module in `lib/` builds a path under the home by string concatenation (grep for `".si"` finds only `Si.Paths`).

### Verify
```bash
mix test test/si/paths_test.exs
grep -rn '"\.si"' lib | grep -v lib/si/paths.ex ; echo "grep_exit=$?"   # grep_exit=1 (no matches)
bin/ci
```

**Expected result.**
- `Si.Paths` is the only module that knows Si's file layout.
- `home/0` resolves, in order, the application env, then `SI_HOME`, then `~/.si`, and always returns an absolute path.
- `ensure!/0` creates the listed directories idempotently, with mode 0700 on the home.
- `write_secret!/2` writes atomically, with mode 0600 set before any content is written.
- `Si.Application` calls `ensure!/0` before starting children.
- The test suite never touches the real `~/.si`.

**Checks**
1. `SI_HOME=$(mktemp -d) mix run --no-start -e 'IO.puts Si.Paths.home()'`.
   Expected: the temporary path. With `SI_HOME=relative/x`: an absolute path ending in `/relative/x`.
2. Run `h=$(mktemp -d)/home; SI_HOME=$h mix run --no-start -e 'Si.Paths.ensure!(); Si.Paths.ensure!()'; ls "$h"; ls "$h/logs"; stat -f '%Lp' "$h"`.
   Expected:
   - `ls "$h"`: `backups checks evals logs patches profiles queue sessions toolchains worktrees`;
   - `ls "$h/logs"`: `checks sessions`;
   - `stat`: `700`.
3. Run `SI_HOME=$h mix run --no-start -e 'Si.Paths.write_secret!(Path.join(Si.Paths.home(), "s"), "x")'; stat -f '%Lp' "$h/s"; ls -a "$h" | grep -c 'tmp-'`.
   Expected: `600`, then `0` (no temporary file left).
4. The suite leaves the real home alone. Run `ls -la ~/.si 2>&1 | shasum` before and after `mix test`.
   Expected: the same checksum.
5. `grep -rnE '"\.si"|Path.join\([^)]*home' lib | grep -v lib/si/paths.ex`.
   Expected: no output.
6. `grep -n 'Si.Paths.ensure!' lib/si/application.ex`.
   Expected: it is called before `Supervisor.start_link`.

**Redo if**
- A path function other than `ensure!/0` and `write_secret!/2` reads or creates anything on disk. Rewrite those functions as pure functions.
- `write_secret!/2` writes the content before setting the mode, or writes the target file directly. Rewrite it in the order the Specification gives: exclusive create, chmod, write, `datasync`, rename.
- A test changes `SI_HOME` or the application env without restoring it. Rewrite the test with an `on_exit` restore and `async: false`.
