### Goal
A `si` command-line tool that runs commands inside the running Si node over distributed Erlang, with streamed output and proper exit codes. First commands: `si status`, `si version`, `si help`.

### Context
`04-protocols.md` §4 (CLI ↔ node) is the contract.

### Deliverables
- `cli/mix.exs`, `cli/lib/si_cli.ex` (escript; module `SiCli`), building `bin/si`.
- `bin/si-server` (bash): starts the node in dev.
- `lib/si/cli/server.ex` (`Si.CLI.Server`), `lib/si/cli/output.ex` (`Si.CLI.Output`), `lib/si/cli/commands/status.ex`, `version.ex`, `help.ex`, a `Si.CLI.Command` behaviour.
- `test/si/cli/server_test.exs`, `test/si/cli/escript_test.exs` (`@tag :slow`).

### Specification
**`bin/si-server`**
```bash
#!/usr/bin/env bash
set -euo pipefail
cd "$(dirname "$0")/.."
SI_HOME="${SI_HOME:-$HOME/.si}"; export SI_HOME
mkdir -p "$SI_HOME"; chmod 700 "$SI_HOME"
if [[ ! -s "$SI_HOME/cookie" ]]; then
  (umask 077; LC_ALL=C tr -dc 'A-Za-z0-9' </dev/urandom | head -c 32 > "$SI_HOME/cookie")
fi
mix ecto.migrate >/dev/null
exec elixir --sname "${SI_NODE_NAME:-si}" --cookie "$(cat "$SI_HOME/cookie")" -S mix phx.server
```

**Single instance.** Two Si nodes on one `$SI_HOME` would corrupt state. Guard in two layers: (1) `bin/si-server` refuses to start when `epmd -names` already lists the node name, and (2) `Si.Application.start/2` reads `Si.Paths.pid_file()`: if it names an OS pid that is alive and whose command line (`ps -o command= -p <pid>`) contains `beam` and the node name, Si logs `Si is already running as <node> (pid <pid>)` and stops; otherwise (missing or stale) it writes `<os pid> <node name>` with `Si.Paths.write_secret!/2`. The file is removed on clean shutdown; a stale file is simply overwritten (no lock can outlive its process, unlike Pair F-19).

**Escript (`cli/`)**: a separate Mix project with no dependencies other than `jason`, `escript: [main_module: SiCli, name: "si", path: "../bin/si"]`. `SiCli.main(argv)`:
1. Resolve home (`SI_HOME` or `~/.si`) and read the cookie file. Missing cookie → print `Si is not running (no cookie at <path>). Start it with bin/si-server.` to stderr, `System.halt(69)`.
2. Start distribution: `Node.start(:"si_cli_#{System.pid()}", :shortnames, 15_000)`, `:erlang.set_cookie(String.to_atom(cookie))`. Hidden node: pass `hidden: true` via `:net_kernel.start/2` options if available, otherwise accept a visible node.
3. Target: `SI_NODE` env (full atom name) or `:"si@#{short_hostname}"` where the short hostname is `:inet.gethostname/0`.
4. `Node.connect(target)`; false → the "not running" message and exit 69.
5. Spawn the call: `task = Task.async(fn -> :erpc.call(target, Si.CLI.Server, :run, [argv, ctx], :infinity) end)` with `ctx = %{cwd: File.cwd!(), caller: self(), tty: IO.ANSI.enabled?(), columns: columns()}`.
6. Loop: `{:si_cli, :stdout, data}` → `IO.write(data)`; `{:si_cli, :stderr, data}` → `IO.write(:stderr, data)`; `{:si_cli, :exit, code}` → remember code; the task reply → finish; `{:DOWN, ...}` or `:erpc` error → print `Lost connection to Si` and exit 70. Exit with the remembered code (`System.halt(code)`).

**Server (`Si.CLI.Server.run(argv, ctx)`)**
- Splits `argv` into command and args. Commands are registered in a map in `Si.CLI.Server` (`%{"status" => Si.CLI.Commands.Status, ...}`); later tasks add entries.
- `Si.CLI.Command` behaviour: `@callback run(args :: [String.t()], out :: Si.CLI.Output.t()) :: non_neg_integer()` (the exit code) and `@callback summary() :: String.t()`.
- `Si.CLI.Output` struct `%{caller: pid, tty: boolean, columns: integer}` with `puts/2`, `write/2`, `error/2`, `table/3` (column-aligned plain-text table: headers, rows; truncates cells to fit `columns` when known).
- Unknown command → usage text on stderr, exit code 2. An exception in a command → message and stacktrace summary to stderr, exit 70, and a log entry on the server.
- `run/2` always sends exactly one `{:si_cli, :exit, code}` and returns `:ok`.

**Commands**
- `si status`: prints `node`, `uptime` (from `:erlang.statistics(:wall_clock)`), `home`, `database`, `si_version` (`Application.spec(:si, :vsn)`), `elixir`, `otp`. Exit 0.
- `si version`: prints the Si version. Exit 0.
- `si help`: lists commands with their `summary/0`. Exit 0.

### Tests
`test/si/cli/server_test.exs` (call `Si.CLI.Server.run/2` directly with `caller: self()`):
- `["status"]` → receives stdout containing `node` and `home`, then `{:si_cli, :exit, 0}`.
- `["nope"]` → stderr contains `Unknown command`, exit 2.
- A test-only command (registered via `Application.put_env(:si, :extra_cli_commands, %{...})`, which `Si.CLI.Server` merges into its map) that raises → exit 70.
- Exactly one `:exit` message per call.
- Single instance: with a pid file naming the test's own OS pid and node, a second `Si.Application` start check refuses; with a pid file naming a dead pid, start proceeds and rewrites the file.

`test/si/cli/escript_test.exs` (`@tag :slow`): start a peer node with `:peer.start(%{name: :si_cli_test_node, args: [~c"-setcookie", ~c"testcookie"], connection: :standard_io})` or equivalent, load Si's code paths into it, build the escript (`cd cli && mix escript.build`), run `bin/si status` with `SI_NODE` and a temp home whose cookie is `testcookie`; assert exit 0 and output contains the peer node name; assert the round trip takes < 300 ms after the first call.

### Acceptance criteria
1. With the node running via `bin/si-server`, `bin/si status` prints the fields and exits 0.
2. With the node stopped, `bin/si status` prints the "not running" message and exits 69.
3. `bin/si nope` exits 2.
4. Tests pass; `bin/ci` passes.

### Verify
```bash
(cd cli && mix deps.get && mix escript.build)
mkdir -p tmp
bin/si-server > tmp/si-server.log 2>&1 & srv=$! ; sleep 10
bin/si status ; echo "exit=$?"     # exit=0
bin/si nope ; echo "exit=$?"       # exit=2
kill $srv ; sleep 2 ; bin/si status ; echo "exit=$?"   # exit=69 (stops only the node started above)
mix test test/si/cli
```

**Expected result.**
- The `bin/si` escript runs commands inside the running node over distributed Erlang, and streams their output.
- Exit codes: 0 for success, 2 for an unknown command, 69 when Si is not running, 70 for a lost connection or a crashed command.
- `bin/si-server` starts the node with a cookie file of mode 0600.
- Two layers keep a second node from starting on the same home: `epmd` and the pid file.

**Checks**
1. `stat -f '%Lp' ~/.si/cookie` and `stat -f '%Lp' ~/.si`.
   Expected: `600` and `700`.
2. With the node running (started as in the Verify block):
   - `bin/si status` prints all seven fields: `node`, `uptime`, `home`, `database`, `si_version`, `elixir`, `otp`;
   - `bin/si version` prints the version from `mix.exs`;
   - `bin/si help` lists `status`, `version` and `help`.
3. While the node runs, start a second one: `bin/si-server > tmp/si-server-2.log 2>&1; echo "exit=$?"`.
   Expected: a non-zero exit within a few seconds and a message that Si is already running. `bin/si status` still answers from the first node.
4. `cat ~/.si/si.pid` while it runs; after `kill $srv`, run `test -e ~/.si/si.pid; echo "exists=$?"`.
   Expected: `<os pid> si@<host>`, matching the running node; after the stop, `exists=1` (the file is removed on a clean shutdown).
5. `SI_NODE=nosuch@$(hostname -s) bin/si status; echo "exit=$?"`.
   Expected: the "not running" message and `exit=69`, within 5 s.
6. `bin/si nope 2>/dev/null | wc -c`.
   Expected: `0` (the usage text goes to stderr).
7. `time bin/si status`, run after a first call.
   Expected: real time under 1 s.
8. `git check-ignore -q bin/si && echo ignored`.
   Expected: `ignored`.

**Redo if**
- Output is collected and printed at the end instead of streamed. Rewrite the server so that it sends `{:si_cli, :stdout, data}` as the output happens.
- `System.halt/1` runs before output is flushed, so the output is cut off. Rewrite the exit path to flush stdout and stderr first.
- Only one of the two single-instance layers exists. Implement both.
