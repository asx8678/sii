### Goal
Load `$SI_HOME/config.yml` over built-in defaults, validate the result against a JSON Schema, and give fast read access everywhere.

### Context
`05-schemas-and-config.md` §1 is the full list of keys and defaults.

### Deliverables
- `priv/default_config.yml` (exactly the defaults from `05` §1).
- `protocol/config.schema.json` (JSON Schema 2020-12 describing every key; objects use `additionalProperties: false`, except `scheduler.pools[]` items and `toolchain.sources`, which list their properties explicitly).
- `lib/si/settings.ex` (`Si.Settings`, a GenServer that stores the merged map in `:persistent_term`).
- `test/si/settings_test.exs`, fixtures in `test/fixtures/config/*.yml`.
- Supervision: `Si.Settings` is the **first** child of `Si.Application`.

### Specification
```elixir
@spec get([atom() | String.t()]) :: term()          # raises KeyError if the path does not exist
@spec get([atom() | String.t()], term()) :: term()  # default when missing
@spec all() :: map()                                 # string-keyed map
@spec reload() :: {:ok, map()} | {:error, [String.t()]}   # keeps the old settings on error
@spec load(Path.t() | nil) :: {:ok, map()} | {:error, [String.t()]}   # pure: defaults + file, validated; no side effects
```
- Internal representation: maps with **string** keys (as parsed from YAML). `get/1` converts atom path segments to strings (`Atom.to_string/1`) so no atoms are created from user input.
- Merge: deep merge of maps; a list in the user file replaces the default list; a `null` in the user file removes the key (then validation may fail if required).
- YAML parsing: `YamlElixir.read_from_file/1`. An empty or missing user file means defaults only.
- Validation: build the JSV root once (`JSV.build!/1` from the decoded schema, stored in `:persistent_term`) and validate the merged map. Error strings must include the file path and the JSON pointer, e.g. `"/Users/x/.si/config.yml: /review/fix_policy: value must be one of writer, astra, auto"`. Use JSV's error normalization to produce these.
- `init/1` calls `load(Si.Paths.config_file())`; on error it **fails to start** with a message listing the errors (Si must not run with invalid settings).
- Endpoint address: `config/runtime.exs` (dev and prod) reads `http.ip` and `http.port` from `$SI_HOME/config.yml` with `YamlElixir` directly (`Si.Settings` is not running yet when `runtime.exs` is evaluated), falling back to `127.0.0.1` and `4040`, and sets `SiWeb.Endpoint`'s `http: [ip: ..., port: ...]`. This lets a second Si (the review node in T05.10) run beside the one you develop.
- `reload/0` re-reads the file; on success replaces the persistent term and broadcasts `{:settings_reloaded, map}` on PubSub topic `"settings"` (PubSub may not be started yet during T00.04; guard with `Process.whereis(Si.PubSub)`).

### Tests
- Defaults only (no user file): `get([:review, :fix_policy]) == "auto"`, `get([:http, :port]) == 4040`.
- User override of a scalar merges and keeps sibling defaults.
- A user list replaces the default list (e.g. `scheduler.pools`).
- Invalid enum value → `load/1` returns `{:error, [msg]}` whose message contains `/review/fix_policy`.
- Unknown key (`review.colour: red`) → error mentioning `/review`.
- `reload/0` with a now-invalid file returns `{:error, _}` and `get/1` still returns the old values.
- `get([:nope])` raises `KeyError`; `get([:nope], :x)` returns `:x`.
- With `http: {port: 4041}` in a temp `config.yml`, the endpoint config produced by `runtime.exs` uses port 4041 (evaluate the file with `Config.Reader.read!/2` in the test).

### Acceptance criteria
1. Every key in `05-schemas-and-config.md` §1 is present in `priv/default_config.yml` and described in the schema.
2. Si fails to boot with a readable error when `config.yml` is invalid.
3. Tests pass; `bin/ci` passes.

### Verify
```bash
mix test test/si/settings_test.exs
SI_HOME=$(mktemp -d) sh -c 'printf "review:\n  fix_policy: sometimes\n" > $SI_HOME/config.yml; mix run -e "IO.puts(:ok)"' ; echo "exit=$?"   # non-zero, error mentions /review/fix_policy
bin/ci
```

**Expected result.**
- `Si.Settings` is the first child of the application.
- It merges `priv/default_config.yml` with the user's file and validates the result with JSV against `protocol/config.schema.json`.
- It refuses to boot on invalid settings, with messages that name the file and the JSON pointer.
- It serves reads from `:persistent_term`.
- `runtime.exs` takes the endpoint's IP and port from `config.yml`.

**Checks**
1. Compare the key paths of the YAML block in `05-schemas-and-config.md` §1 with those of `priv/default_config.yml`. Copy the block into a temporary file, then flatten both maps with a short `mix run --no-start -e` script.
   Expected: the same set of key paths and the same default values.
2. For each top-level section, a `config.yml` with an unknown key inside it (for example `http: {colour: red}`) is rejected.
   Expected: `load/1` returns an error that mentions `/http` (or the section's own pointer).
3. With `SI_HOME` set to a temporary dir whose `config.yml` says `http: {port: 4041}`: `mix run -e 'IO.inspect SiWeb.Endpoint.config(:http)'`.
   Expected: `[ip: {127, 0, 0, 1}, port: 4041]`.
4. The failing boot from the Verify section.
   Expected: the error text contains the full path of `config.yml` and `/review/fix_policy`, and the exit code is non-zero.
5. `grep -n 'children = \[' -A2 lib/si/application.ex`.
   Expected: `Si.Settings` is the first child.
6. `grep -nE 'GenServer.call|File.read|YamlElixir' lib/si/settings.ex`.
   Expected: file reads happen only in `load/1` and `reload/0`, and reads go through `:persistent_term.get`.
7. `grep -nE 'String.to_atom|to_existing_atom' lib/si/settings.ex`.
   Expected: no output.

**Redo if**
- `get/1` calls the GenServer or reads the file. Rewrite reads on `:persistent_term`.
- Validation checks keys by hand instead of using JSV and the schema. Rewrite it with JSV.
- An invalid file only logs a warning and Si starts anyway. Rewrite `init/1` so that the start fails.

### Out of scope
Watching the file for changes (not needed). Settings UI (cockpit Settings page shows values read-only later).
