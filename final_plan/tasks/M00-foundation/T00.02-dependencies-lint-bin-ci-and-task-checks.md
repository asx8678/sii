### Goal
Add the base dependencies and the quality tooling. Create `bin/ci`, the single command that decides whether the repository is healthy, and `bin/task-check`, which runs the mechanical checks every later task must pass before it counts as done (`10-after-each-task.md`).

### Specification
1. Add the deps; run `mix deps.get`. `mix.lock` is committed.
2. `mix credo gen.config`, then set `strict: true`, set `Credo.Check.Readability.MaxLineLength` to `max_length: 120`, and add `~r"/test/fixtures/"` to the `excluded` file patterns: fixtures are data, and some are deliberately incomplete (this task's `undocumented.ex`, the fixture `mix.exs` files of T01.03). Fix any credo issues in the generated code (typically none or `@moduledoc` issues; add short `@moduledoc` strings rather than disabling checks).
3. `test/test_helper.exs`: `ExUnit.start(exclude: [:slow, :pi])`. Keep the generated sandbox setup.
4. `bin/ci`:
   ```bash
   #!/usr/bin/env bash
   set -euo pipefail
   cd "$(dirname "$0")/.."
   FULL=0; [[ "${1:-}" == "--full" ]] && FULL=1
   step() { printf '\n==> %s\n' "$1"; }
   step "format";  mix format --check-formatted
   step "compile"; mix compile --warnings-as-errors
   step "credo";   mix credo --strict
   step "test";    if [[ $FULL == 1 ]]; then mix test --warnings-as-errors --include slow --include pi; else mix test --warnings-as-errors; fi
   for pkg in bridge testing/pi-faux adapter; do
     if [[ -f "$pkg/package.json" ]]; then
       step "$pkg"; (cd "$pkg" && npm ci --silent && npm run --silent lint && npm run --silent typecheck --if-present && npm run --silent test --if-present)
     fi
   done
   if [[ $FULL == 1 && -x bin/contract-test ]]; then step "contract"; bin/contract-test; fi
   printf '\nPASS\n'
   ```
   `chmod +x bin/ci`.
5. OpenTelemetry: in `config/config.exs` set `config :opentelemetry, traces_exporter: :none` so nothing is exported until T13.06.
6. `bin/task-check [--final] [ID]`:
   - `ID` defaults to the one in the branch name (`task/<ID>-…`); without a task branch and without `ID` it prints a usage line and exits 2.
   - It runs every gate below in order, and does not stop at the first failure (gates that need a successful compile print `SKIP` after a failed `ci`).
   - It prints one line per gate: `<gate> PASS|WARN|FAIL|SKIP <detail>`, with `file:line` for each problem. Then it prints `RESULT: PASS`, or `RESULT: FAIL (<failed gates>)`.
   - It writes the same report to `tmp/task-check/<ID>.txt`, whose first line is `task-check <ID> HEAD <sha> final=<yes|no>`.
   - It exits 0 only when no gate failed.

   | Gate | Checks | Fails when |
   |---|---|---|
   | `task` | the task file `final_plan/tasks/*/<ID>-*.md` exists | it is missing |
   | `branch` | the current branch is `task/<ID>-…`, and `git merge-base --is-ancestor main HEAD` succeeds | another branch, or `main` has moved (rebase first) |
   | `clean` | `git status --porcelain` prints nothing | uncommitted or untracked files |
   | `scope` | each file changed since `main` (`git diff --name-only main...HEAD`) is named in the task file: its path, a parent directory with a trailing `/`, or a module defined in it (its `defmodule` names). Always allowed: `final_plan/tasks.yaml`, `final_plan/status/<ID>.md`, `final_plan/0*.md` and `final_plan/1*.md` documents, `mix.lock`, and `package-lock.json` files | never; unnamed files are a `WARN` listing them |
   | `hygiene` | lines added since `main` (`git diff -U0 main...HEAD`). Skipped paths: `final_plan/`, `docs/`, `AGENTS.md`, `.credo.exs`, `mix.lock`, `package-lock.json` files, `test/fixtures/`, `evals/`, `lib/si/checks/test_integrity/`, `test/si/checks/test_integrity_test.exs`, and `bin/task-check` itself | any of: `IO.inspect(`, `dbg(`, `IEx.pry`, `require IEx`, `TODO`, `FIXME`, `XXX`, `@tag :skip`, `@tag skip:`, `@moduletag :skip`, `.skip(`, `.only(`, `credo:disable`, `@dialyzer {:nowarn`, `@ts-ignore`, `@ts-nocheck`, `eslint-disable`, `biome-ignore`, `pkill`, `killall`; `Mix.env` in `lib/` outside `lib/mix/`; `/Users/` in `lib/`, `priv/`, `bin/`, `cli/lib/`, `bridge/src/`, `adapter/src/` or `testing/`; strings that look like secrets: a word that starts with `sk-` or `xai-` followed by 20 or more letters or digits, or with `ghp_` followed by 30 or more (match at a word start, so `task-…` names never match), and `-----BEGIN` … `PRIVATE KEY-----`. `WARN` for `Process.sleep(` or `:timer.sleep(` in `test/`, `String.to_atom(` in `lib/`, and `console.log(` in `bridge/src/` or `adapter/src/` |
   | `ci` | `bin/ci`, output saved to `tmp/task-check/<ID>-ci.log` | non-zero exit; the gate prints the failing `==>` step and the last 30 lines |
   | `docs` | `mix si.doc_check` on the changed `.ex` files under `lib/si/` (the `cli/` escript is a separate Mix project whose modules the main project cannot load) | a problem is reported |
   | `tests` | every concrete `test/…_test.exs`, `bridge/test/…`, `adapter/test/…` and `testing/…/test/…` path declared in the task's **Deliverables**, **Tests**, or **Verify** sections exists. Extract only within those sections (including their nested subsections), deduplicate paths, and exclude incidental mentions in generic gate definitions, exemption lists, context/references and other sections. This section-scoped extraction was approved by the owner after T00.02's hygiene exemption referenced a future T02.05 test. The declared Elixir test files pass three runs in a row: `mix test <files> --include slow --include pi --warnings-as-errors --repeat-until-failure 3`. Files whose module is tagged `:contract` or `:chaos` run once. | a named file is missing, or any run fails |
   | `leftovers` | after `tests`: no process whose command line contains `si_test_home_`, `si_test_repos` or `fake_pi.mjs` (`pgrep -fl`). The output of `git for-each-ref refs/heads refs/si` and `git worktree list --porcelain` is identical to a listing taken before `tests` | a leftover process, or the test runs changed this repository |
   | `final` (only with `--final`) | `final_plan/status/<ID>.md` exists in `HEAD` and contains every field of the completion-note template (`10-after-each-task.md` §8); `final_plan/tasks.yaml` in `HEAD` has `status: done` for `<ID>` | a missing note, a missing field, or another status |
7. `mix si.doc_check FILE...`:
   - It compiles the project if needed, then finds the modules defined in the given files (`defmodule` names).
   - It uses `Code.fetch_docs/1` and `Code.Typespec.fetch_specs/1` to report problems:
     - a module without `@moduledoc`: `Si.Foo: missing @moduledoc`;
     - a public function or macro without `@doc` or `@spec`: `Si.Foo.bar/2: missing @spec`.
   - Exempt: functions hidden with `@doc false` or `@impl true`, and modules with `@moduledoc false` (listed as a note).
   - It prints `ok: <n> modules, <m> functions` and exits 0, or prints one line per problem and exits 1. Without files, it prints a usage line and exits 2.

### Owner-approved Yamerl OTP 29 compatibility amendment

The owner approved this narrow repair after the required YAML dependency resolved to Yamerl 0.10.0 and its cold compilation emitted OTP 29 deprecated-catch warnings. - Add tests for ordinary/detailed YAML binary decoding, invalid binary/error behavior, optional node-module loading, source mismatch rejection, idempotence and stale-build cleanup. Prove warning-free cold dependency compilation and normal setup, then all original task gates. An upstream fix may replace the patch only after it is actually identified and vetted; the revision above is not a fix.

### Acceptance criteria
1. `bin/ci` exits 0 and its last line is `PASS`.
2. `mix credo --strict` reports no issues.
3. `mix deps.tree` lists every dependency from the deliverables list.
4. A deliberately misformatted file makes `bin/ci` exit non-zero (check manually, then revert).
5. `bin/task-check` on this branch prints `RESULT: PASS`. On a throwaway branch with an added `IO.inspect` line, it prints `hygiene FAIL` with the `file:line` and exits 1.

### Verify

bin/ci ; echo "exit=$?"                         # PASS, exit=0

mix test test/mix/tasks/si_doc_check_test.exs

### After implementing

Do this after the Verify commands pass. Run the `bin/task-check` you just wrote on this branch first, then these checks. Each check states the result you must see. Any other result means the task is not done: fix the cause in the code (never by changing what a test expects), or rewrite the part named under **Redo if**, then run `bin/task-check` and every check below again from the top. The limits on fix attempts, how to redo a task, and the evidence the completion note needs are in [10-after-each-task](../../10-after-each-task.md).

**Expected result.**
- `mix.exs` has exactly the listed dependencies with the listed version constraints, and `mix.lock` is committed.
- `.credo.exs` is strict, with a maximum line length of 120.
- `bin/ci` runs format, compile, credo and `mix test --warnings-as-errors`, then lint, typecheck and tests for each TypeScript package that exists. It ends with `PASS` and exit code 0, and exits non-zero on any failure.
- `bin/task-check` and `mix si.doc_check` exist and catch the problems they are meant to catch.
- OpenTelemetry exports nothing.

**Checks**
1. `bin/task-check` on this branch.
   Expected: `RESULT: PASS`.
2. Prove that the gates catch problems, on a throwaway branch:
   - `git checkout -b scratch/task-check`, add `IO.inspect(:x)` to a function in a `lib/` file, commit, and run `bin/task-check T00.02`. Expected: `hygiene FAIL` with that `file:line`, and exit 1.
   - Add a public function without `@doc` and `@spec`, commit, and run it again. Expected: `docs FAIL` naming `Module.fun/arity`.
   - Clean up: `git checkout task/T00.02-dependencies-lint-bin-ci-and-task-checks && git branch -D scratch/task-check`.
3. `mix deps --all | grep -cE '^\* (yaml_elixir|jsv|muontrap|req|opentelemetry_api|opentelemetry|credo|dialyxir|propcheck|stream_data|mox) '`.
   Expected: `11`, each version within its constraint. `mix deps.unlock --check-unused` exits 0.
4. `bin/ci 2>&1 | grep -E '^==> '`.
   Expected: `format`, `compile`, `credo`, `test`, in that order. The last line of `bin/ci` is `PASS`.
5. `mix test > tmp/t00.02-mix-test.log 2>&1; sed -n '1,5p' tmp/t00.02-mix-test.log` (per AGENTS, never pipe Mix output into an early-closing `head`).
   Expected: the output mentions that `:slow` and `:pi` are excluded.
6. `grep -n 'traces_exporter: :none' config/config.exs`.
   Expected: one match.
7. Make a test fail on purpose (`assert false` in a generated test), and run `bin/ci; echo "exit=$?"`. Restore the test.
   Expected: the `test` step fails and `exit=1`; after restoring, `PASS`.

**Redo if**
- `bin/ci` or `bin/task-check` exits 0 while a step failed. The usual cause is a pipeline that swallows exit codes, such as `cmd | tee`. Rewrite the script with `set -euo pipefail` and explicit exit-code handling.
- A gate reports `PASS` for the problem it exists to catch (check 2). Rewrite that gate and repeat check 2.
- A credo check was disabled instead of fixed. Remove the disabling and fix the code.
