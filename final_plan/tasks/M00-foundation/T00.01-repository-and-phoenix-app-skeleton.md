### Goal
Generate the Phoenix 1.8 application `si` (module `Si`, web module `SiWeb`) at the root of the existing repository, keeping `final_plan/` and `.pi/` unchanged and Si's text at the top of `AGENTS.md`.

### Specification
1. `cd /Users/adam2/projects/skynet && git checkout main && git pull --ff-only && git checkout -b task/T00.01-repository-and-phoenix-app-skeleton`.
2. Generate in place. Phoenix 1.8 also writes an `AGENTS.md` (its guidelines for coding agents), and answering `y` to every prompt would overwrite Si's `AGENTS.md`. So move Si's file aside first and merge the two afterwards, Si's text first:
   ```bash
   mv AGENTS.md AGENTS.si.md
   yes | mix phx.new . --app si --module Si --database sqlite3 --no-mailer --no-gettext --install
   { cat AGENTS.si.md; printf '\n# Phoenix guidelines (generated by phx.new 1.8.13)\n\n'; cat AGENTS.md; } > AGENTS.merged.md
   mv AGENTS.merged.md AGENTS.md && rm AGENTS.si.md
   ```
   The generator asks whether to continue in an existing directory; `yes |` answers it. Do **not** delete or modify `final_plan/` or `.pi/`.
3. In `config/dev.exs` set the endpoint to `http: [ip: {127, 0, 0, 1}, port: 4040]`. In `config/test.exs` keep the test port the generator chose (e.g. 4002) but make sure `server: false`.
4. Create `.tool-versions`:
   ```
   erlang 29.<patch from the installed OTP_VERSION file>
   elixir 1.20.4-otp-29
   ```
   Read the exact OTP version with `cat "$(dirname "$(dirname "$(readlink -f "$(which erl)")")")/releases/29/OTP_VERSION"` (or `erl -noshell -eval 'io:format("~s~n",[erlang:system_info(otp_release)]), halt().'` for the major version if the file path differs).
5. Append to `.gitignore`:
   ```
   /bridge/node_modules/
   /testing/**/node_modules/
   /adapter/node_modules/
   /cli/_build/
   /cli/deps/
   /bin/si
   *.db
   *.db-shm
   *.db-wal
   .DS_Store
   ```
6. Commit the generated app, the merged `AGENTS.md`, `.tool-versions` and `.gitignore` as `T00.01: Generate Phoenix app`. `final_plan/` and `.pi/` are already tracked and must not change (until the completion note and status).

#### Owner-approved bootstrap compatibility amendment (27 September 2026)

The owner approved this narrow scope extension after the exact generator produced dependency warnings on Elixir 1.20.4/OTP 29 and a fresh SQLite migration startup race. This amendment permits fixing those defects; it does not waive warnings, startup errors, tests, or any expected result below.

- Vet compatible releases or immutable upstream revisions of the existing `dns_cluster`, `phoenix_ecto`, and `phoenix_live_dashboard` dependencies. Record exact versions/revisions, source provenance and cold-build evidence in the completion note. Do not add Postgrex or another functional dependency to hide an optional-module warning. If upstream revisions are insufficient, propose a bounded, reproducible compatibility patch for review before implementing it; do not modify only the ignored `deps/` checkout.
- Initialize the generated SQLite database in WAL mode at storage creation, covering fresh test and development startup as applicable. Preserve the generated database locations, connection pool sizes and test assertions; do not hide the race with retries, sleeps, longer timeouts or error suppression.
- Preserve the configured development/test endpoint ports when `PORT` is unset; an explicit `PORT` may override them, and production keeps its generated default. This fixes the generated runtime override of the specified development port.
- Run an isolated cold compilation and bounded fresh-database lifecycle probes in addition to the original checks. No new warning suppression, weakened expectations, or unrelated dependency work is permitted. Record the blocker and authorized repair history accurately.
