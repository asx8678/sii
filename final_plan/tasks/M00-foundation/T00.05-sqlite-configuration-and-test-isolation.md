### Goal
Put the database at `$SI_HOME/si.db` with the right SQLite pragmas, and make tests use an isolated database per test partition.

### Context
`03-data-model.md` (overview). ecto_sqlite3 options: `journal_mode`, `busy_timeout`, `foreign_keys`, `synchronous`, `pool_size`.

### Deliverables
- `config/runtime.exs` (dev and prod): `config :si, Si.Repo, database: Si.Paths.db_file(), journal_mode: :wal, busy_timeout: 5_000, foreign_keys: :on, synchronous: :normal, pool_size: 5` — `Si.Paths` is available in `runtime.exs` because the app code is compiled; if not, compute the same path inline (`System.get_env("SI_HOME") || Path.expand("~/.si")`) and add a comment pointing to `Si.Paths`.
- `config/test.exs`: `database: Path.join(System.tmp_dir!(), "si_test_#{:erlang.phash2(__DIR__)}_#{System.get_env("MIX_TEST_PARTITION")}.db")`, `pool: Ecto.Adapters.SQL.Sandbox`, same pragmas, `pool_size: System.schedulers_online() * 2`. The hash of the checkout's `config/` path keeps worktrees and parallel agents from sharing one test database.
- Remove the generator's `si_dev.db` path from `config/dev.exs`.
- `test/si/repo_test.exs`.

### Specification
- `Si.Application.start/2` order: `Si.Paths.ensure!()` → children (`Si.Settings`, `Si.Repo`, ...). The DB file is created by `mix ecto.create` / automatically by ecto_sqlite3 on first connection; add `Si.Release.migrate/0` (`lib/si/release.ex`) that runs migrations, and call it from `bin/si-server` later (T00.09).
- Keep the generated `mix ecto.setup` alias working.

### Tests
`test/si/repo_test.exs` (not async, uses the sandbox in shared mode where needed):
- `PRAGMA journal_mode` returns `"wal"`.
- `PRAGMA foreign_keys` returns `1`.
- `PRAGMA busy_timeout` returns `5000`.
- Two concurrent tasks each inserting 200 rows into a temporary table (create it in the test via `Ecto.Adapters.SQL.query!`) finish without `Database busy` errors. (Run this test outside the sandbox with `@tag :slow` if the sandbox serializes writes; document which.)

### Acceptance criteria
1. In dev, after `mix ecto.create`, the database file is `~/.si/si.db` (or `$SI_HOME/si.db`).
2. Tests use a temp database named after the checkout; `MIX_TEST_PARTITION=2 mix test` uses the file ending in `_2.db`, and another worktree of this repository uses a different file.
3. `bin/ci` passes.

### Verify
```bash
SI_HOME=$(mktemp -d) mix ecto.create && ls "$SI_HOME"      # si.db present
mix test test/si/repo_test.exs
bin/ci
```

**Expected result.**
- The dev database is `$SI_HOME/si.db`, with WAL, `busy_timeout` 5000, foreign keys on and `synchronous` normal.
- Tests use a temporary database whose file name includes a hash of the checkout and the test partition, so worktrees and parallel agents never share one.
- `Si.Release.migrate/0` runs the migrations.
- The generated `si_dev.db` setting is gone.

**Checks**
1. Run `SI_HOME=$(mktemp -d) sh -c 'mix ecto.create && mix run -e "IO.inspect(Si.Repo.query!(\"PRAGMA journal_mode\").rows)" && ls "$SI_HOME"'`.
   Expected: `[["wal"]]`, and `si.db` in the listing.
2. `grep -rn 'si_dev.db' config`.
   Expected: no output.
3. `MIX_ENV=test mix run --no-start -e 'IO.puts Application.get_env(:si, Si.Repo)[:database]'`, then the same command with `MIX_TEST_PARTITION=2` set.
   Expected: a path in the temporary directory that contains the checkout hash, and the second path ends in `2.db`.
4. `SI_HOME=$(mktemp -d) mix ecto.setup; echo "exit=$?"`.
   Expected: `exit=0`.
5. In the completion note, state whether the concurrency test runs in the sandbox or as `@tag :slow`, as the task asks.
   Expected: one of the two, with the reason.

**Redo if**
- The database path is built outside `Si.Paths`, apart from the documented fallback in `runtime.exs`. Rewrite it.
- Pragmas are set with `PRAGMA` queries at runtime instead of through the ecto_sqlite3 options. Rewrite it with the options.
