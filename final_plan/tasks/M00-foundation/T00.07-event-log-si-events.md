### Goal
An append-only `events` table written in the same transaction as state changes, with PubSub notification after commit.

### Context
`01-architecture.md` §7 (state tables + event log), `03-data-model.md` §2 (events columns) and §4 (catalog).

### Deliverables
- Migration `priv/repo/migrations/<ts>_create_events.exs`.
- `lib/si/events.ex` (`Si.Events`), `lib/si/events/event.ex` (schema).
- `test/si/events_test.exs`.

### Specification
Migration:
```elixir
create table(:events, primary_key: false) do
  add :seq, :integer, primary_key: true          # INTEGER PRIMARY KEY = rowid, auto-increment
  add :id, :string, null: false
  add :stream, :string, null: false
  add :type, :string, null: false
  add :data, :map, null: false, default: "{}"
  add :run_id, :string
  add :task_id, :string
  add :session_id, :string
  add :schema_version, :integer, null: false, default: 1
  add :occurred_at, :utc_datetime_usec, null: false
end
create unique_index(:events, [:id])
create index(:events, [:stream, :seq])
create index(:events, [:type, :seq])
create index(:events, [:run_id]); create index(:events, [:task_id]); create index(:events, [:session_id])
execute "CREATE TRIGGER events_no_update BEFORE UPDATE ON events BEGIN SELECT RAISE(ABORT, 'events are append-only'); END;",
        "DROP TRIGGER events_no_update"
execute "CREATE TRIGGER events_no_delete BEFORE DELETE ON events BEGIN SELECT RAISE(ABORT, 'events are append-only'); END;",
        "DROP TRIGGER events_no_delete"
```
(If Ecto's `:integer` primary key does not produce `INTEGER PRIMARY KEY AUTOINCREMENT` semantics with ecto_sqlite3, use `add :seq, :bigserial` or create the table with `execute` SQL; verify that `seq` increases monotonically.)

API:
```elixir
@type attrs :: %{required(:stream) => String.t(), required(:type) => String.t(), optional(:data) => map(),
                 optional(:run_id) => String.t(), optional(:task_id) => String.t(), optional(:session_id) => String.t()}
@spec append(Ecto.Multi.t(), term(), attrs()) :: Ecto.Multi.t()     # adds an insert named {:event, name}
@spec transaction(Ecto.Multi.t()) :: {:ok, map()} | {:error, term(), term(), map()}   # Repo.transaction + broadcasts after commit
@spec record(attrs()) :: {:ok, Si.Events.Event.t()} | {:error, Ecto.Changeset.t()}  # single event, broadcast after insert
@spec list(String.t(), keyword()) :: [Si.Events.Event.t()]   # opts: after_seq, limit (default 500), types
@spec list_by(:run_id | :task_id | :session_id, String.t(), keyword()) :: [Si.Events.Event.t()]
@spec subscribe(:all | {:stream, String.t()} | {:type, String.t()}) :: :ok
```
- Validation in the changeset: `stream` matches `~r/^(system|[a-z]+:[a-z]+_[0-9a-z]{26})$/`; `type` matches `~r/^[a-z_]+\.[a-z_]+$/`; `data` must encode with `Jason.encode/1` (add an error otherwise).
- `id` is `Si.Id.generate("evt")`, `occurred_at` is `DateTime.utc_now()`.
- Broadcast: after a successful commit, for each inserted event broadcast `{:event, %Si.Events.Event{}}` on `"events:all"`, `"events:stream:" <> stream`, and `"events:type:" <> type` via `Phoenix.PubSub.broadcast(Si.PubSub, ...)`. Nothing is broadcast when the transaction rolls back.
- There are no functions to update or delete events.

### Tests
- `append/3` + `transaction/1` inserting an event together with another insert (use a throwaway table created in the test, or insert two events) → both present, one broadcast per event received by a subscriber.
- A multi that fails after `append/3` → no rows in `events`, no broadcast (`refute_receive`).
- `list/2` returns events in `seq` order; `after_seq` and `types` filters work.
- Updating or deleting an event with raw SQL raises an error containing `append-only`.
- Invalid `type` (e.g. `"Bad Type"`) → changeset error.

### Acceptance criteria
Tests pass; the triggers exist (`SELECT name FROM sqlite_master WHERE type='trigger'` lists both); `bin/ci` passes.

**Expected result.**
- An append-only `events` table exists: triggers reject `UPDATE` and `DELETE`.
- `Si.Events` provides `append/3`, `transaction/1`, `record/1`, `list/2`, `list_by/3` and `subscribe/1`.
- Broadcasts go out only after a commit, and there is no way to change an event.

**Checks**
1. With `SI_HOME` set to a temporary dir: `mix ecto.migrate`, then `sqlite3 "$SI_HOME/si.db" '.schema events'`.
   Expected: `seq INTEGER PRIMARY KEY`, the unique index on `id`, the five other indexes, and both triggers.
2. Insert one event with `mix run -e 'Si.Events.record(%{stream: "system", type: "demo.checked"})'`. Then run `sqlite3 "$SI_HOME/si.db" "UPDATE events SET type='x.y'"` and `sqlite3 "$SI_HOME/si.db" "DELETE FROM events"`.
   Expected: both fail with `events are append-only`.
3. `mix ecto.rollback`, then `mix ecto.migrate`, on the same temporary database.
   Expected: both exit 0, and the triggers exist again.
4. `grep -nE 'def (update|delete)' lib/si/events.ex`.
   Expected: no output.
5. The rollback test.
   Expected: it uses `refute_receive` with an explicit timeout (at least 100 ms) for every topic.

**Redo if**
- Broadcasts happen inside the transaction function. Rewrite it so that broadcasts run after `Repo.transaction` returns `{:ok, _}`.
- Any code updates or deletes events. Remove that code: events never change.
