### Goal
Run Si as a background service that starts at login, so reviews, the bridge and the cockpit work without a terminal, with `si` on your PATH and rotated logs.

### Deliverables
- Release configuration in `mix.exs` (`releases: [si: ...]`) copying `bridge/` into the release's `priv/bridge`; `Si.Profiles` resolves the bridge from `:code.priv_dir(:si)` when running as a release.
- `bin/si-install` (build the release and the escript, symlink `si` into `~/.local/bin`, write the service file).
- macOS launchd agent `~/Library/LaunchAgents/dev.si.server.plist` (`KeepAlive`, `RunAtLoad`); Linux systemd user unit `~/.config/systemd/user/si.service`.
- CLI `si service status|start|stop|restart`.
- Logger file handler writing `$SI_HOME/logs/node.log` with rotation.
- Tests.

### Specification
- Release env: `SI_HOME`, `RELEASE_DISTRIBUTION=sname`, `RELEASE_NODE=si`, `RELEASE_COOKIE` read from `$SI_HOME/cookie`, and variables from `$SI_HOME/env` when present (T12.02).
- Start sequence: backup (T11.10) when the database exists, `Si.Release.migrate/0`, then start. The single-instance guard (T00.09) applies.
- Logging: `:logger` handler `:logger_std_h` with `file: node.log`, `max_no_bytes: 10_000_000`, `max_no_files: 5`.
- `bin/si-install` prints what it did and warns when `~/.local/bin` is not on your PATH. Re-running it upgrades: build, stop the service, start the new release.
- `si service ...` wraps `launchctl bootstrap|bootout|kickstart gui/<uid> ...` on macOS and `systemctl --user ...` on Linux.

### Tests
Golden tests for the plist and the unit file. `@tag :slow`: `MIX_ENV=prod mix release si` builds; start the release in a temp `$SI_HOME` with a random node name, `bin/si status` answers, stop it.

### Acceptance criteria
Tests pass; on this machine `bin/si-install` installs the service, Si runs after a logout and login, and `si status` works from any directory.

### Verify
```bash
mix test test/si/release_test.exs --include slow
bin/si-install && si service status && si status
```
