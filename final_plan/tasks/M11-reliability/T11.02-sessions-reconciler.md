### Goal
Sessions that should be running but whose process is gone are restarted from their session files; sessions that should be gone are stopped.

### Context
Pi processes exit when Si exits (stdin EOF). This reconciler restarts them from their Pi session files after a crash or a Si restart. Keeping processes alive across Si restarts and reattaching to them is a skipped topic and is not implemented here.

### Deliverables
`lib/si/reconcilers/sessions.ex`; tests `test/si/reconcilers/sessions_test.exs` (`@tag :pi` for the restart case).

### Specification
- Desired: `sessions` with `kind: "si"` and state in `starting|idle|running|settling` whose owner (task, review thread, run, warm slot) is still active.
- Observed: controller registered, OS pid alive.
- Ops:
  - `{:restart, id}` when desired, controller missing or process dead, and the worktree exists: start a new controller with the same id, profile, model and cwd, launching Pi with the same `--session-dir`/`--session-id` flags, which reopens the session so the conversation continues; notify the owner (`{:session_restarted, id}` on `"session:<id>"`); a turn that was running is lost, so the owner decides whether to re-prompt (the task loop sends `Si restarted your session. Continue the task; call si_task if you need it again.`).
  - `{:mark_lost, id}` when the worktree is gone: state `lost`, the owner is notified (the task attempt becomes interrupted).
  - `{:stop, id}` when the owner is no longer active (task landed/cancelled, thread closed).
  - `{:kill, os_pid}` when a row is `stopped`/`lost` but its OS pid is still alive and belongs to a Pi process started by Si (check the command line with `ps -o command= -p <pid>` contains the session file path).

### Tests
Kill a faux worker with `kill -9` → restarted with a new pid, the task loop re-prompts and the task completes (`@tag :pi`); worktree removed → lost; owner finished → stopped.

### Acceptance criteria
Tests pass; `bin/ci` passes.

**Expected result.**
- Si sessions that should be running but whose process is gone are restarted with the same `--session-dir` and `--session-id`, so the conversation continues.
- Sessions whose worktree is gone are marked lost.
- Sessions whose owner finished are stopped.
- Stray Pi processes that Si started are killed. The owner's own processes are never touched.

**Checks**
1. `kill -9` a faux worker (`:pi` test).
   Expected: a new OS pid, the same session id and session file; the task loop re-prompts, and the task completes.
2. The `{:kill, os_pid}` operation.
   Expected: it runs only when `ps -o command= -p <pid>` contains that session's file path.
3. `pgrep -fl 'si_test_home_'` after the tests.
   Expected: no process.

**Redo if**
- The kill operation matches processes by name (for example "pi"). It must match the session file path, because the owner's own Pi sessions run on this machine.
