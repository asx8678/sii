### Goal
A common way to compare desired state with observed state and repair the difference, on a timer and on events, with idempotent operations.

### Context
`01-architecture.md` §7.

### Deliverables
- `lib/si/reconciler.ex` (behaviour), `lib/si/reconcilers/runner.ex` (GenServer per reconciler), `Si.Reconcilers.Supervisor`; settings `reconcilers.enabled` (list) and per-reconciler intervals; tests `test/si/reconciler_test.exs` (+ StreamData property).

### Specification
```elixir
@callback name() :: atom()
@callback interval_ms() :: pos_integer()
@callback triggers() :: [String.t()]                 # PubSub topics that trigger a run (debounced 500 ms)
@callback desired() :: term()
@callback observed() :: term()
@callback plan(desired :: term(), observed :: term()) :: [op :: term()]   # pure
@callback apply(op :: term()) :: :ok | {:error, term()}                   # idempotent
@callback op_id(op :: term()) :: String.t()
```
Runner: runs `plan` then `apply` for each op; records `reconciler.repaired` (`reconciler`, `op_id`, `action`) for successful ops; failed ops back off per `op_id` (1 s doubling to 10 minutes) and are logged; exceptions never kill the runner (caught and logged); telemetry span per run.

### Tests
A model reconciler over sets (desired, observed, ops add/remove); property: for random desired/observed, applying the plan makes the next plan empty; backoff per op; trigger debounce; exception isolation.

### Acceptance criteria
Tests pass; `bin/ci` passes.

**Expected result.**
- Reconcilers compare desired and observed state and apply idempotent operations, on a timer and on debounced triggers.
- Failed operations back off per `op_id`.
- An exception never kills the runner.

**Checks**
1. The property test with at least 500 runs.
   Expected: after one `plan` and `apply`, the next plan is empty.
2. A reconciler whose `apply` raises.
   Expected: the runner stays alive, and the error is logged.
3. Ten triggers within 500 ms.
   Expected: one run.

**Redo if**
- `apply` operations are not idempotent: running them twice changes the state twice. Rewrite them.
