### Goal
Prove that runs recover or stop cleanly when parts fail.

### Deliverables
`test/chaos/*_test.exs` (`@moduletag :chaos`, `:pi`, `:slow`); `bin/chaos` (runs `mix test --only chaos --include pi --include slow`).

### Specification
Scenarios, each ending with assertions that no orphan Pi processes exist, no task is stuck in an active state without a process, and the integration branch passed its checks:
1. `kill -9` a builder mid-turn → restarted, task lands.
2. Bridge disconnect (stop the endpoint for 5 s) → sessions continue over RPC; the bridge reconnects; no events lost beyond the buffer limit.
3. Adapter crash → restarted; seeding retried.
4. 429 storm (faux provider returns an error message that Pi treats as a 429 / overload for 20 calls) → the pool concurrency drops, then recovers; runs complete.
5. SQLite busy (a test holds a write transaction for 3 s) → no crashes; operations complete after the lock.
6. Si restart (`Application.stop(:si)` then `Application.ensure_all_started(:si)`) → runs and loops resume; sessions are restarted from their session files.

### Acceptance criteria
`bin/chaos` passes on this machine.

### Verify
```bash
bin/chaos
```

Do this after the Verify commands pass. Run `bin/task-check` first, then these checks. Each check states the result you must see. Any other result means the task is not done: fix the cause in the code (never by changing what a test expects), or rewrite the part named under **Redo if**, then run `bin/task-check` and every check below again from the top. The limits on fix attempts, how to redo a task, and the evidence the completion note needs are in [10-after-each-task](../../10-after-each-task.md).

**Expected result.** `bin/chaos` proves recovery from six failures: a killed builder, a bridge disconnect, an adapter crash, a 429 storm, SQLite busy, and a Si restart. After each scenario, no orphan Pi process remains, no task is stuck, and the integration branch passed its checks.

**Checks**
1. `bin/chaos; echo "exit=$?"`, run twice in a row.
   Expected: `exit=0` both times.
2. `pgrep -fl 'si_test_home_'` after each run.
   Expected: no process.

**Redo if**
- A scenario passes only with longer sleeps. Fix the recovery path; don't lengthen the waits.
