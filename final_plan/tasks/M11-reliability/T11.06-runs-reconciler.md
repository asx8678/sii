### Goal
Runs and task loops that should be active always have a live process.

### Deliverables
`lib/si/reconcilers/runs.ex`; tests.

### Specification
- Runs not in a terminal state without a registered `Si.Runs.Run` process → resume (respecting `on_interrupt`).
- Tasks in `assigned|running|frozen|in_review|approved|queued` without a loop process → restart the loop; a task whose session is gone and cannot be restarted → attempt `interrupted`, task `interrupted` → `ready` (new attempt) after 1 minute, or `escalated` after 3 interruptions.

### Tests
Killed run process resumes; killed loop restarts; repeated interruptions escalate.

### Acceptance criteria
Tests pass; `bin/ci` passes.

### Verify
```bash
mix test test/si/reconcilers/runs_test.exs
```

### After implementing

Any other result means the task is not done: fix the cause in the code (never by changing what a test expects), or rewrite the part named under **Redo if**, then run `bin/task-check` and every check below again from the top. The limits on fix attempts, how to redo a task, and the evidence the completion note needs are in [10-after-each-task](../../10-after-each-task.md).

**Expected result.**
- Runs and task loops that should be active always have a process.
- Interrupted tasks get a new attempt after 1 minute, and are escalated after 3 interruptions.

**Checks**
1. Kill a run process, then a task loop.
   Expected: both come back within one reconcile interval.
2. Three interruptions of the same task.
   Expected: `escalated`, with an inbox item.

**Redo if**
- A resumed loop starts a new attempt while the old one is still live. Guard it on the attempt's state.
