### Goal
Regular, verified backups of Si's database.

### Deliverables
`lib/si/backups.ex` (`Si.Backups`, scheduler); settings `backups.at` (default `"03:00"`) and `backups.keep` (7); CLI `si backup now|list|verify <file>`; `bin/si-restore <file>`; tests.

### Specification
- `now/0`: `VACUUM INTO '<backups_dir>/si-<UTC timestamp>.db'`; rotate to keep the newest `keep` files.
- Daily at `backups.at` local time; `bin/si-server` also runs a backup before `mix ecto.migrate` when the database exists.
- `verify/1`: open the file read-only (separate connection), `PRAGMA integrity_check` must return `ok`, and the key tables (`events`, `tasks`, `reviews`) must be readable; print counts.
- `bin/si-restore <file>`: refuses while the node is running (checks `bin/si status`), moves `si.db` to `si.db.bak-<timestamp>`, copies the backup into place.

### Tests
Backup file created and verifiable; rotation keeps 7; a truncated copy fails verification.

### Acceptance criteria
Tests pass; `bin/ci` passes.

**Expected result.**
- Daily verified backups made with `VACUUM INTO`, keeping 7.
- `si backup now|list|verify`.
- `bin/si-restore` refuses while the node is running.
- A backup is taken before migrations at start.

**Checks**
1. `bin/si backup now`, then `bin/si backup verify <file>`.
   Expected: `integrity_check ok`, and the counts of `events`, `tasks` and `reviews` are printed.
2. A truncated copy.
   Expected: verification fails.
3. `bin/si-restore <file>` while the node runs.
   Expected: refused, and nothing is changed.

**Redo if**
- Backups copy `si.db` while the node runs, instead of using `VACUUM INTO`. Rewrite them.
