### Goal
Models that often write failing `fabric_exec` programs run with Fabric's `fullCodeMode: false` (Pi's own tools stay direct) until their failure rate drops.

### Context
Fabric `docs/configuration.md` "Orchestration-only mode": core tools stay native; MCP, memory and agents remain available.

### Deliverables
Settings `models.orchestration_only_above` (default 0.30) and `models.code_mode_again_below` (0.15), evaluated daily over the last 200 execs per model; profile generation passes `orchestration_only: true` for such models (T03.02 option); event `model.code_mode_changed`; cockpit indicator; tests.

### Tests
Threshold crossing in both directions with hysteresis; profile content for an affected model.

### Acceptance criteria
Tests pass; `bin/ci` passes.

### Verify
```bash
mix test test/si/models/code_mode_test.exs
```

### After implementing

Do this after the Verify commands pass. Run `bin/task-check` first, then these checks. Each check states the result you must see. Any other result means the task is not done: fix the cause in the code (never by changing what a test expects), or rewrite the part named under **Redo if**, then run `bin/task-check` and every check below again from the top. The limits on fix attempts, how to redo a task, and the evidence the completion note needs are in [10-after-each-task](../../10-after-each-task.md).

**Expected result.** Models with too many `fabric_exec` failures run with `fullCodeMode: false` until their rate drops, with hysteresis between 0.30 and 0.15. This is shown in the cockpit and recorded.

**Checks**
1. Rates of 0.31, then 0.20, then 0.14.
   Expected: on, still on, then off; one `model.code_mode_changed` event per change.
2. The `fabric.json` of an affected model's profile.
   Expected: `fullCodeMode: false`.

**Redo if**
- The mode flips back and forth between the thresholds. Implement the hysteresis.
