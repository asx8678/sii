### Goal
Measure each model per role on your own work.

### Deliverables
Migration `create_model_stats` (`model`, `role`, `window` (`7d|30d`), `metrics` map, `computed_at`; unique on the first three); `lib/si/models/scoreboard.ex`; hourly recomputation; CLI `si models scoreboard [--role R]`; cockpit table; tests with fixtures.

### Specification
Builder metrics: first-try check pass rate (tasks whose first report passed all checks / tasks), median rounds to approval, cost per landed task, p50/p95 model-call latency, `fabric_exec` failures per 1,000 execs, intervention rate.
Reviewer metrics: precision (blocking findings not dismissed and not later reverted / all blocking findings), canary catch rate, first-round approval rate among tasks that later landed unchanged, cost per review.
Minimum sample sizes (e.g. 10 tasks, 5 canaries) before a metric is shown; below that, `n/a`.

### Tests
Fixture histories → exact metric values; minimum samples respected.

### Acceptance criteria
Tests pass; `bin/ci` passes.

### Verify
```bash
mix test test/si/models/scoreboard_test.exs
```

### After implementing

Do this after the Verify commands pass. Run `bin/task-check` first, then these checks. Each check states the result you must see. Any other result means the task is not done: fix the cause in the code (never by changing what a test expects), or rewrite the part named under **Redo if**, then run `bin/task-check` and every check below again from the top. The limits on fix attempts, how to redo a task, and the evidence the completion note needs are in [10-after-each-task](../../10-after-each-task.md).

**Expected result.** Per-role scoreboards over 7 and 30 days are computed hourly from the owner's own history, with minimum sample sizes. They are shown in the CLI and the cockpit.

**Checks**
1. The fixture histories.
   Expected: exact metric values.
2. A metric below its minimum sample.
   Expected: `n/a`.

**Redo if**
- Metrics are computed on each request, from all rows. Store them in `model_stats`, recomputed hourly.
