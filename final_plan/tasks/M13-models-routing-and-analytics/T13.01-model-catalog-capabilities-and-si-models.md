### Goal
Extend the catalog with what each model can do and make it inspectable.

### Deliverables
Catalog fields `context_window`, `tool_use` (boolean), `thinking_levels` (list), `verified` (boolean, prices checked by you); schema `protocol/models.schema.json` for `priv/models.yml` and `$SI_HOME/models.yml`; CLI `si models` (table: pattern, family, prices, context, verified); tests.

### Specification
Validation at load (errors name the entry); `Si.Models.Catalog.entry(model)` returns the merged entry for a model string; unverified prices are shown with `?` in the CLI and flagged in cost reports.

### Tests
Schema validation, merge precedence, CLI output.

### Acceptance criteria
Tests pass; `bin/ci` passes.

### Verify
```bash
mix test test/si/models/catalog_test.exs
```

Do this after the Verify commands pass. Run `bin/task-check` first, then these checks. Each check states the result you must see. Any other result means the task is not done: fix the cause in the code (never by changing what a test expects), or rewrite the part named under **Redo if**, then run `bin/task-check` and every check below again from the top. The limits on fix attempts, how to redo a task, and the evidence the completion note needs are in [10-after-each-task](../../10-after-each-task.md).

**Expected result.**
- The catalog gains `context_window`, `tool_use`, `thinking_levels` and `verified`, with a schema.
- `si models` shows it, marking unverified prices with `?`.

**Checks**
1. An invalid catalog entry.
   Expected: a load error that names the entry.
2. `bin/si models`.
   Expected: the owner's models, with families; prices marked `?` while `verified: false`.

**Redo if**
- `$SI_HOME/models.yml` no longer takes precedence over `priv/models.yml`. Restore the merge order.
