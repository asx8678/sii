### Goal
See review threads, rounds, findings and check results in the cockpit, and resolve inbox items there.

### Deliverables
- `SiWeb.ReviewsLive` (list), `SiWeb.ReviewLive` (`/reviews/:thread_id`), `SiWeb.InboxLive` (list + resolve), `SiWeb.LogController` (`GET /logs?path=` serving files under `$SI_HOME/logs` only; any other path → 404).
- Tests under `test/si_web/live/`.

### Specification
- Reviews list: title, repo, status badge (open, approved, escalated, closed, error), round `n/max`, reviewer model + diversity chip, last verdict, updated. Live via `"review:*"` broadcasts (subscribe to `"reviews"`; add a broadcast of `{:review_recorded, review}` on `"reviews"` in `Si.Review.record_verdict/2`).
- Review detail: rounds timeline (each: snapshot short sha, verdict, reviewer model, time), the latest findings table (severity, `file:line`, category, problem, evidence, suggested fix, status), check results per round with links to logs, links to the Astra session.
- Inbox: open items newest first; each shows kind, title, body (rendered Markdown via `Earmark` if already a dependency, else preformatted), recommended action highlighted, and one button per option; resolving calls `Si.Inbox.resolve/3` with actor `you`.
- Log viewer: resolve the requested path (`Path.expand/1`, then symlinks) and serve it only when it equals `Si.Paths.logs_dir()` or starts with `Si.Paths.logs_dir() <> "/"`; anything else is 404.

### Tests
Render with fixtures; live update on a recorded review; resolving an item from the page; log path traversal (`../../etc/passwd`), a sibling directory (`<logs_dir>-evil/x`) and a symlink inside `logs/` that points outside → 404.

### Acceptance criteria
Tests pass; `bin/ci` passes.
