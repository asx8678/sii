### Goal
Persist review threads, rounds, verdicts and findings, and turn `si_verdict` arguments into validated domain data with the evidence rule applied.

### Context
`03-data-model.md` (review tables, §3.3), `05-schemas-and-config.md` §3 (`si_verdict`).

### Deliverables
- Migrations: `review_threads`, `reviews`, `findings`, `approvals`.
- Schemas under `lib/si/review/`; `lib/si/review/verdict.ex` (`Si.Review.Verdict`); `lib/si/review.ex` (`Si.Review`, persistence functions in this task, orchestration in T05.04).
- Tests `test/si/review/verdict_test.exs`, `test/si/review_store_test.exs`.

### Specification
`Si.Review.Verdict`:
```elixir
@spec from_args(map(), [Si.Review.Finding.t()]) :: {:ok, t()} | {:error, String.t()}   # args, open findings from earlier rounds
```
- `verdict: "approve"` with any finding of severity `blocking` that has evidence → `{:error, "approve is not allowed while blocking findings remain; use revise or downgrade them to notes"}`.
- A `blocking` finding without `evidence` becomes a note with `downgraded: true`.
- Round ≥ 2: `previous` must contain every open finding id passed in; missing ids → `{:error, "previous must cover open findings: fnd_..."}`; unknown ids are ignored.
- `fingerprint` = first 16 hex chars of `sha256(file <> "|" <> category <> "|" <> normalized_problem)` where `normalized_problem` is lowercase, digits removed, whitespace collapsed.
- The error strings are returned to Astra as tool errors, so they must say how to fix the call.

`Si.Review` persistence API (used by T05.04+):
```elixir
@spec create_thread(map()) :: {:ok, Thread.t()}          # repo_id, subject_kind, task_id, title, description, base_ref, head_ref, writer_model, reviewer_model, fix_policy, max_rounds
@spec start_review(Thread.t(), Si.Evidence.Snapshot.t(), map()) :: {:ok, Review.t()}   # purpose, reviewer_session_id, reviewer_model, writer_model, diversity_level, prompt_version; increments round for purpose :review
@spec record_verdict(Review.t(), Verdict.t()) :: {:ok, Review.t()} | {:error, term()}
@spec open_findings(Thread.t()) :: [Finding.t()]
@spec running_review_for_session(String.t()) :: Review.t() | nil
@spec approve_snapshot(Si.Evidence.Snapshot.t(), String.t(), String.t() | nil) :: {:ok, Approval.t()}   # kind "review", actor, review_id
```
`record_verdict/2` in one transaction: update the review (`verdict`, `summary`, `status: recorded`, `finished_at`); insert findings (`status: open`); apply `previous` (`fixed` → status `fixed` with `resolved_in_review_id`; `fixed: false` → `unfixed`, and it stays open for the next round); if `approve`: insert an approval for the snapshot; events `review.recorded` (`verdict`, counts) and `finding.status_changed`; broadcast `{:review_recorded, review}` on `"review:<thread_id>"`.

### Tests
- Verdict rules: approve with evidenced blocking → error; blocking without evidence → downgraded note; missing previous → error with ids; fingerprint stability (same problem with different line numbers or spacing gives the same fingerprint).
- Store: thread → review round numbering; record approve creates the approval; record revise with previous marks findings; events written.

**Expected result.**
- Review threads, reviews, findings and approvals are stored.
- `si_verdict` arguments become validated verdicts:
  - evidence rule: a blocking finding without evidence is downgraded to a note;
  - approve is refused while blocking findings remain, including earlier ones reported as not fixed;
  - `previous` must cover every open finding;
  - fingerprints are stable.
- A verdict is recorded in one transaction, with events and a broadcast.

**Checks**
1. Approve with a new blocking finding that has evidence.
   Expected: the error `approve is not allowed while blocking findings remain; …`.
2. Approve in round 2 while `previous` reports an open blocking finding as `fixed: false`.
   Expected: the same error.
3. Two findings that differ only in line numbers and spacing.
   Expected: the same fingerprint.
4. The code of `record_verdict/2`.
   Expected: every insert and update happens inside one transaction.
5. The error strings.
   Expected: each says how to correct the call.

**Redo if**
- The "no approve while blocking" rule checks only the new findings. Rewrite it to include the open findings from earlier rounds.
