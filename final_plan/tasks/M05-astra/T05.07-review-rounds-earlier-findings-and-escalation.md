### Goal
Running `si review` again after fixing continues the same review thread as the next round: Astra checks every earlier finding, and Si escalates when the round limit is reached or the same issue keeps coming back.

### Context
`03-data-model.md` §3.3; `05-schemas-and-config.md` §1 (`review.max_rounds`).

### Deliverables
- `lib/si/review/thread_manager.ex` (`Si.Review.ThreadManager`), changes to the `si review` command, Astra session parking; tests `test/si/review/rounds_test.exs` (`@tag :pi`).

### Specification
- Thread lookup: an `open` thread with the same `repo_id` and subject key (`ref:<name>` or `worktree:<path>`) and the same `base_ref` is reused; otherwise a new thread. `si review --new` forces a new thread.
- Same tree as the last reviewed snapshot of the thread (no changes since) → print the last verdict again (`(unchanged since round n)`) with its exit code; no new review.
- New round: `round + 1`; Astra's checkout is moved to the new snapshot; her session is reused if still alive, else restarted (the context message includes earlier findings either way).
- Astra session lifetime: after a round, keep the session idle for `review.keep_astra_s` (default 1800; add to settings), then stop it (a timer in `ThreadManager`); a thread that is closed or approved stops it immediately. After a `{:session_large, id}` for the thread's Astra session, the next round starts a fresh session.
- Approve → thread `approved`, Astra session stopped.
- Escalation: when `round == max_rounds` ends with revise, or a blocking finding with the same fingerprint is reported unfixed in two consecutive rounds, set the thread to `escalated`, create an inbox item (`kind: "escalation"`, title `Review of <title> needs you`, body: summary of open findings and rounds, options `["continue", "close", "split"]`, recommended `continue` with text `Allow 2 more rounds`), print `Escalated: <inbox id>` and exit 1. Resolving with `continue` raises `max_rounds` by 2 and reopens the thread; `close` closes it.

### Tests
(`@tag :pi`)
- Round 1 revise → fix the file → round 2: the context contains the earlier finding; a script reporting it `fixed` + approve → thread approved; the finding status is `fixed`.
- Unchanged tree → no new review, same verdict printed.
- Same fingerprint unfixed twice → escalated with an inbox item.
- `max_rounds: 2` reached → escalated; resolving `continue` allows round 3.

**Expected result.**
- Running `si review` again continues the same open thread as the next round. The match uses the same repo, subject key and base.
- An unchanged tree prints the last verdict again, with no new review.
- Astra's session is kept for `review.keep_astra_s`, then stopped.
- Escalation creates an inbox item, and `continue` allows two more rounds.

**Checks**
1. The `reviews` table after running `si review` twice on an unchanged tree.
   Expected: one review, and the second output says `(unchanged since round 1)` with the same exit code.
2. Round 2's context.
   Expected: it lists the earlier finding, and the finding becomes `fixed` when the script reports it fixed.
3. The same blocking fingerprint reported unfixed in two consecutive rounds.
   Expected: the thread is `escalated`, with one inbox item, and the command prints `Escalated: <id>` and exits 1.
4. `review.keep_astra_s: 1` in a test.
   Expected: Astra's session is stopped after about 1 s.

**Redo if**
- A new thread is created on every invocation. Rewrite the lookup.
