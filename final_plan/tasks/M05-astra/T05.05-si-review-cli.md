### Goal
The first user-facing feature: `si review` freezes a branch or working tree, runs the checks, and has Astra review it, printing the verdict and findings with a meaningful exit code.

### Context
`01-architecture.md` §5.1; exit codes in `04-protocols.md` §4.

### Deliverables
- `lib/si/cli/commands/review.ex`; tests `test/si/cli/review_command_test.exs` (`@tag :pi`).

### Specification
```
si review [PATH] [--base REF] [--head REF] [--title TEXT] [--task-file FILE]
          [--model PROVIDER/MODEL] [--fix writer|astra|auto] [--no-checks] [--json]
```
1. Repo from `PATH` (default cwd), registered on the fly. No `.si/repo.yml` → `No repo profile. Run: si repo init` and exit 1 (unless `--no-checks`).
2. Subject:
   - `--head REF` → `Si.Evidence.freeze_ref(repo, head_sha, base_sha)`; subject key `ref:<REF>`.
   - otherwise freeze the working tree at `PATH`; subject key `worktree:<toplevel>`.
   - `--base` default: `git merge-base HEAD <default_branch>` (or `<head>` instead of `HEAD` with `--head`).
3. Thread: create one (T05.07 changes this to reuse an open thread with the same subject key). `title` from `--title`, else the head ref name or `Working tree of <repo>`; `description` from the last commit message on the head when a ref is given; `fix_policy` from `--fix` or settings; `max_rounds` from settings (`standard`).
4. Checks (unless `--no-checks`): `Si.Checks.run_all(snapshot, tier: :standard)` with streamed lines `  <check> … pass (1.2s)`. On failure print `Check failed: <check>. Log: <path>` and the last 20 lines of the log; exit 1 without calling Astra.
5. `Si.Review.Runner.run_round/4` with `progress` printing to stdout.
6. Output:
   ```
   Verdict: REVISE (round 1 of 5, reviewer openrouter/kimi-k2, other family)
   <summary>

   SEV       LOCATION              CATEGORY      PROBLEM
   blocking  src/session.ts:42     missing_test  A session that expires exactly now is treated as valid.
             evidence (input): expires_at = now returns valid=true
             fix: Use >= in the comparison and add a test for equality.
   note      src/session.ts:10     readability   ...
   ```
   Exit 0 for approve, 1 for revise, 70 for review errors (`no_verdict`, `timeout`).
7. `--json`: a single JSON object `{thread_id, review_id, round, verdict, reviewer_model, diversity, checks: [...], findings: [...]}` on stdout; same exit codes.
8. When the subject is a working tree that has files ignored by `.gitignore`, or the snapshot excluded files (`details.excluded`), print one note line, e.g. `Note: 3 ignored files (e.g. .env) and 1 excluded file are not part of this review.`

### Tests
(`@tag :pi`, fixture repo, si-faux Astra scripts through a test hook that injects faux session options)
- Approve path: exit 0, output contains `Verdict: APPROVE`.
- Revise path: exit 1, table rows with evidence lines.
- Failing check: exit 1, no Astra session started.
- `--head` on a branch vs working tree mode produce the right snapshot bases.
- `--json` is valid JSON with the listed keys.

**Expected result.**
- `si review` freezes a branch or a working tree and runs the standard checks.
- It has Astra review the result, then prints the verdict and findings in the exact format.
- Exit codes: 0 for approve, 1 for revise or a failed check, 70 for a review error.
- `--json` prints a single object.

**Checks**
1. The output of the revise-path test.
   Expected: the table matches the example layout in the Specification, including the evidence and fix lines.
2. `bin/si review <tmp repo> --json | jq -r 'keys|join(",")'` in the faux test setup.
   Expected: `checks,diversity,findings,review_id,reviewer_model,round,thread_id,verdict`.
3. A failing check.
   Expected: exit 1, `Check failed: <check>. Log: <path>`, and no Astra session started (the `sessions` table is unchanged).
4. A working tree with an ignored `.env` file.
   Expected: the note line about ignored files.

**Redo if**
- The command implements review logic itself instead of calling `Si.Checks` and `Si.Review.Runner`. Rewrite it to call them. T05.12 later moves the flow into `Si.Review.Flow`.
