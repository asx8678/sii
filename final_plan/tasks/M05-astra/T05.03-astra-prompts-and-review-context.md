### Goal
Write Astra's review prompt and build the per-round message she receives: what the change is for, the diff, check results and earlier findings, within a size budget.

### Context
`05-schemas-and-config.md` §5 (prompt files), §3 (`si_verdict`). Astra runs with read-only tools (`read`, `grep`, `find`, `ls`) in a clean checkout of the snapshot; Pi loads `AGENTS.md` from that directory automatically.

### Deliverables
- `lib/si/prompts.ex` (`Si.Prompts`), `priv/prompts/astra/review.md`, `lib/si/review/context.ex` (`Si.Review.Context`), golden tests `test/si/review/context_test.exs` with fixtures under `test/fixtures/review_context/`.

### Specification
`Si.Prompts.load(role, name) :: %{text, version, hash}`: file `priv/prompts/<role>/<name>.md` with front matter `---\nversion: <int>\n---\n`; `hash` = first 12 hex of sha256 of the text. Missing file raises.

`priv/prompts/astra/review.md` (version 1). Use this text; it is appended to Pi's system prompt through `--append-system-prompt <file>` when Astra's session starts:
```
You are Astra, the code reviewer in Si. You review one change at a time. You do not edit files.

What to check, in order:
1. Correctness: does the change do what its task or description asks, including edge cases?
2. Tests: do tests cover the changed behavior, and would they fail if the code were wrong?
3. Scope: does the change touch anything unrelated to its purpose?
4. Conventions: does it follow the repository's AGENTS.md and existing style?
5. Error handling, concurrency, performance and API contracts where they matter for this change.
6. Readability, only when it would mislead a future reader.

Rules:
- Read the changed files and anything they depend on. Use read, grep, find and ls.
- A finding is blocking only if the change should not land without fixing it.
- Every blocking finding needs evidence: a failing test you can describe exactly, a reproduction, a quoted rule from AGENTS.md or the task, or a concrete input that breaks the code. If you cannot give evidence, make it a note.
- Do not repeat what the automated checks already reported as passing. Check results are included below.
- In later rounds, first check every earlier finding and report each one in "previous" as fixed or not.
- Finish by calling si_verdict exactly once. Use approve only when no blocking finding remains.
```

`Si.Review.Context.build(thread, snapshot, checks_summary, opts) :: String.t()` (the user message for a round). Sections, in order, as Markdown:
1. `# Review request` with repo name, base ref/sha (short), head (ref or `working tree`), round `n of max`.
2. `## Purpose`: thread title and description; when `opts[:task_file]` is given, its full content (acceptance criteria are what Astra checks against).
3. `## Changed files`: `path (+added −removed, status)` from `Si.Diff`.
4. `## Diff`: unified diff (`Si.Evidence.diff/1`, 3 lines of context). Budget: 60,000 characters total for the diff section; when larger, include whole-file diffs in order of smallest first until the budget is reached, then list the remaining files under "Not included; read them yourself".
5. `## Automated checks`: one line per check (`name: pass|fail|skipped (details summary)`), including coverage percent, integrity warnings and up to 10 mutation survivors.
6. Round ≥ 2: `## Earlier findings` listing each open finding as `fnd_… · file:line · category · problem`, followed by `Report each of these in "previous".`
7. `## Your task`: `Review the change and call si_verdict once.`

### Tests
Golden files for: round 1 small diff; round 1 oversized diff (truncation and "Not included" list); round 2 with earlier findings; with a task file. Regenerate goldens only intentionally (`UPDATE_GOLDEN=1`).

### Acceptance criteria
Tests pass; `bin/ci` passes; the prompt file has `version: 1` and loads.

**Expected result.**
- `Si.Prompts` loads versioned prompt files.
- `priv/prompts/astra/review.md` is exactly the task's text, as version 1.
- `Si.Review.Context.build/4` produces the round message: its sections in order, the diff within the 60,000-character budget (smallest files first), a "Not included" list, and earlier findings from round 2 on.

**Checks**
1. Compare the body of `priv/prompts/astra/review.md` with the text in the task.
   Expected: identical, with front matter `version: 1`.
2. `git diff main...HEAD -- test/fixtures/review_context`, after any regeneration of the golden files with `UPDATE_GOLDEN=1`.
   Expected: every change is intended. Read each golden diff, and explain it in the completion note.
3. The oversized-diff golden.
   Expected: the diff section is at most 60,000 characters, whole files are included smallest first, and the rest are listed under "Not included".
4. The round-2 golden.
   Expected: it ends the findings list with `Report each of these in "previous".`

**Redo if**
- The context includes full check logs or transcripts instead of the specified summaries. Trim it to the Specification.
