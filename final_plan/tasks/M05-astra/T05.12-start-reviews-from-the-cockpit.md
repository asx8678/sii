### Goal
Si is meant to be used mainly in the browser: start a review, follow its progress, and review again from the cockpit, with the same behavior as `si review`.

### Deliverables
- `lib/si/review/flow.ex` (`Si.Review.Flow`): the `si review` logic moved out of the CLI command into a context function that both the CLI and the cockpit use.
- A "New review" form on `SiWeb.ReviewsLive`, live progress on `SiWeb.ReviewLive`, a "Review again" button; tests.

### Specification
- `Si.Review.Flow.start(opts) :: {:ok, thread_id}` runs asynchronously under `Si.TaskSupervisor` and broadcasts progress lines on `"review_flow:<thread_id>"` (the same lines the CLI prints). Options mirror the CLI flags: repo, base, head (`nil` = working tree), title, description, fix policy, model.
- Form fields: repository (registered repos), subject (branch picker from `git for-each-ref refs/heads` plus "Working tree"), base (default branch preselected), title, description (text area; acceptance criteria can be pasted here), fix policy, model override (from the catalog). Submitting redirects to the thread page, which streams check lines and Astra's status, then shows the verdict and findings.
- "Review again" on a thread: freezes the subject again and runs the next round (same rules as T05.07).
- `si review` now calls `Si.Review.Flow` and prints its progress lines; its output and exit codes do not change.

### Tests
Form validation; submit starts a flow (stub `Si.Review.Flow`) and redirects; progress lines appear on the thread page; the CLI tests from T05.05 still pass.

### Acceptance criteria
Tests pass; `bin/ci` passes; a review started from the browser produces the same thread as the CLI.
