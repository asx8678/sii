### Goal
When the fix policy allows it, Astra fixes blocking issues herself in her own checkout; a different model reviews her fix; Astra never approves her own code.

### Context
`05-schemas-and-config.md` §1 (`review.fix_policy`), blueprint "Who fixes a blocking issue". Tool switching uses `set_tools` through the bridge (T04.08). Note from Pi's docs: changing the active tool set can invalidate the provider's prompt cache on some providers; this is acceptable for occasional fixes.

### Deliverables
- `lib/si/review/policy.ex` (`Si.Review.Policy`), `lib/si/review/fix.ex` (`Si.Review.Fix`), `priv/prompts/astra/fix.md`.
- Extend the bridge role table so `astra` also gets `si_report` (additive change in `bridge/src/tools.ts` and `Si.Bridge.Tools`).
- Tests `test/si/review/policy_test.exs`, `test/si/review/fix_test.exs` (`@tag :pi`).

### Specification
`Si.Review.Policy.decide(thread, review, writer_rounds_failed) :: :writer | {:astra, [finding_id]} | :escalate`:
- `writer` policy → `:writer`.
- `astra` policy → `{:astra, all open blocking ids}`.
- `auto`: `{:astra, ids}` when all open blocking findings are small and local: categories in `correctness`, `missing_test`, `test_quality`, `error_handling`, `convention`, `readability`; each names one file; at most 3 blocking findings. Also `{:astra, ids}` after the writer failed two rounds in a row. Otherwise `:writer`.
- For `si review` (no writer session), `:writer` means "report to you" (print the findings).

`Si.Review.Fix.run(thread, review, finding_ids) :: {:ok, %{snapshot, review, delivery}} | {:error, term()}`:
1. `Si.Sessions.control(astra, :set_tools, %{tools: ["read", "grep", "find", "ls", "edit", "write", "bash", "si_report"]})`. Contract test 14 (T04.11) records whether Pi can activate tools that were not in the startup `--tools` allowlist. If it cannot, use the fallback: start Astra with `--tools read,grep,find,ls,edit,write,bash,si_verdict,si_ask,si_report` and have the bridge call `pi.setActiveTools(["read", "grep", "find", "ls", "si_verdict", "si_ask"])` on `session_start` for role `astra`, so the fix tools are registered but inactive until fix mode.
2. Prompt with `priv/prompts/astra/fix.md` (version 1):
   ```
   Fix only these findings in this checkout: <list with file:line, problem, evidence, suggested fix>.
   Keep the change minimal. Do not change anything else. Run the relevant tests with: <profile test command>.
   When done, call si_report with status done and a short summary of each fix.
   ```
3. On `si_report` (done): switch tools back to `read,grep,find,ls`; freeze Astra's checkout with `base = thread base` → the fixed snapshot; run checks; on failure, one more fix attempt with the check log, then escalate.
4. Fix review by another model: reviewer = the writer's model when known and in a different family from Astra; otherwise `models.arbiter.model`. Start a `critic`-role session (profile `reviewer`) in a separate `:astra`-purpose worktree at the fixed snapshot, `purpose: :fix_review`, with a context listing the findings and the diff **between the reviewed snapshot and the fixed snapshot**. Its verdict is recorded on the same thread.
5. Approve → approval for the fixed snapshot (actor = the fix reviewer's model), thread approved. Deliver the fix: for a ref subject, create branch `si/astra-fix/<review_id>` pointing to a commit with the fixed tree and the reviewed head as parent (`commit-tree`), and print `git merge --ff-only si/astra-fix/<id>` guidance; for a working-tree subject, write `$SI_HOME/patches/<review_id>.patch` (diff reviewed → fixed snapshot) and print `git apply <path>`.
6. Revise → counts as a round; policy decides again (writer, another Astra attempt, or escalation).

### Tests
Policy table cases. `@tag :pi` flow: Astra revise → policy auto → Astra script edits the file and calls `si_report` → checks pass → fix reviewer script approves → branch created with the fixed tree and correct parent; Astra's tools are read-only again afterwards (`get_state` or a `set_tools` ack log).

### Acceptance criteria
Tests pass with `--include pi`; `bin/ci` passes; no path lets Astra's own session approve a snapshot she edited (test: a script where Astra calls `si_verdict` approve after fixing is rejected with a tool error because her session's review is a fix, not a review).

**Expected result.**
- The policy decides between writer, Astra and escalation.
- In fix mode, Astra gets write tools only for the fix, fixes in her own checkout, and reports.
- The fixed snapshot is checked and then reviewed by another model.
- Delivery happens as a branch or a patch.
- Astra can never approve a snapshot she edited.

**Checks**
1. A faux script where Astra calls `si_verdict` approve after fixing.
   Expected: a tool error; the snapshot has no approval.
2. Astra's active tools after the fix, from the `set_tools` ack log or `get_state`.
   Expected: read-only again.
3. The fallback path.
   Expected: the one that matches contract scenario 14's recorded result (T04.11). The completion note says which.
4. The delivery branch `si/astra-fix/<id>`.
   Expected: its commit's tree is the fixed tree, and its parent is the reviewed head.

**Redo if**
- The fix review runs in Astra's own session, or reuses her conversation. Rewrite it to use a separate `critic`-role session.
