### Specification

**Review node.** Astra must never run from the working copy an agent is changing, or she would review with half-written code. `bin/review-node` manages a separate, stable Si built from `main`:
- `bin/review-node setup --astra-model PROVIDER/MODEL [--astra-thinking LEVEL]`: `git worktree add --detach "$HOME/.si-review/checkout" main` (or reuse it; detached, because a branch can be checked out in only one worktree and your working copy needs `main` for every merge), a separate home `SI_HOME=$HOME/.si-review/home` whose `config.yml` sets `http.port: 4041` and `models.astra` from the options. The Astra model is the owner's choice and must be from a different model family than the implementation agent's model; without `--astra-model` the script says so and exits 2; `mix deps.get`, `mix compile`, `(cd bridge && npm ci)` (Astra's sessions load this checkout's bridge) and the escript build in that checkout; then start it in the background with `SI_NODE_NAME=si_review bin/si-server` (logs to `$HOME/.si-review/home/logs/review-node.log`) and install its toolchain.
- `bin/review-node update`: move the detached checkout to the current `main` (`git -C "$HOME/.si-review/checkout" checkout --detach main`), run `mix deps.get`, `mix compile`, `(cd bridge && npm ci)` and the escript build, and restart the node. Run it after every merge to `main`.
- `bin/review-node status` and `bin/review-node stop`.

`bin/task-review`:
```bash
#!/usr/bin/env bash
set -euo pipefail
cd "$(dirname "$0")/.."
RN="$HOME/.si-review"
[[ -x "$RN/checkout/bin/si" ]] || { echo "No review node. Run: bin/review-node setup" >&2; exit 2; }
export SI_HOME="$RN/home" SI_NODE="si_review@$(hostname -s)"
branch=$(git rev-parse --abbrev-ref HEAD)
id=$(sed -nE 's#^task/(T[0-9]{2}\.[0-9]{2}).*#\1#p' <<<"$branch")
[[ -n "$id" ]] || { echo "Not on a task/<ID>-... branch" >&2; exit 2; }
file=$(ls final_plan/tasks/*/"$id"-*.md 2>/dev/null | head -1)
[[ -n "$file" ]] || { echo "Task file for $id not found" >&2; exit 2; }
report="tmp/task-check/$id.txt"; head_sha=$(git rev-parse HEAD)
if ! { [[ -f "$report" ]] && head -1 "$report" | grep -q "HEAD $head_sha final=yes" && grep -q '^RESULT: PASS' "$report"; }; then
  bin/task-check --final "$id" >/dev/null || { echo "bin/task-check --final failed; see $report" >&2; exit 3; }
fi
title=$(sed -n '1s/^# //p' "$file")
exec "$RN/checkout/bin/si" review . --base main --head HEAD --task-file "$file" --title "$title" "$@"
```

### Tests
A shell test (`test/bin/task_review_test.exs`, `@tag :slow`) that creates a temporary branch `task/T99.99-demo`, a temporary task file, runs `bin/task-review --no-checks` against a node configured with a si-faux Astra that approves, and expects exit 0. A second case: when `bin/task-check --final` fails, `bin/task-review` exits 3 and no review starts.

### Acceptance criteria
1. `bin/si check .` on `main` passes with Si's own profile.
2. Manual, with your real Astra model configured: create a branch `task/T99.99-planted-bug` that introduces an off-by-one in a small function covered by a weak test; `bin/task-review` returns `REVISE` with a blocking finding on that line. Record the output in the task completion note. Delete the branch afterwards.
3. From now on, the DoD's item 8 applies to every task.
4. `bin/review-node setup --astra-model <the owner's choice>` works on this machine, and `bin/review-node status` shows the review node on port 4041 next to your own Si on 4040.

### Verify
```bash
bin/si check . ; echo "exit=$?"      # exit=0 on main
git checkout -b task/T99.99-planted-bug && <introduce the bug> && git commit -am "T99.99: planted bug"
bin/task-review ; echo "exit=$?"     # REVISE, exit=1
git checkout main && git branch -D task/T99.99-planted-bug
```

**Expected result.**
- Si has its own committed profile, `.si/repo.yml`, including `test_integrity.exempt`.
- The review node is running from a separate checkout on port 4041, with the Astra model the owner chose.
- `bin/task-review` sends the current task branch to Astra, after a passing `bin/task-check --final`.
- From now on, every task is reviewed.

**Checks**
1. Ask the owner which model Astra should use. It must be from a different family than the model you run on. Then run `bin/review-node setup --astra-model <their choice>` and `bin/review-node status`.
   Expected: both nodes are listed, yours on 4040 and the review node on 4041.
2. `bin/si check . ; echo "exit=$?"` on `main`.
   Expected: `exit=0`.
3. On a scratch task branch where `bin/task-check --final` fails, run `bin/task-review; echo "exit=$?"`.
   Expected: `exit=3`, a pointer to the task-check report, and no review started.
4. The Stage A demo (07 §2) with the real Astra model. Ask the owner first: it costs tokens.
   Expected: `Verdict: REVISE` with a blocking finding on the planted line and exit 1; after the fix, round 2 gives `APPROVE` and exit 0. Record the output and delete the scratch branch.
5. `git worktree list` and then `git checkout main && git checkout -`.
   Expected: the review checkout is listed as `detached`, and your working copy can still check out `main`.
6. Astra's session stderr log in `~/.si-review/home/logs/sessions/` after a review.
   Expected: the line `si-bridge 0.1.0 loaded (role=astra, mode=control)`, so the review checkout's bridge and its npm dependencies load.
7. `bin/task-review` for this task's own branch.
   Expected: `Verdict: APPROVE`.

**Redo if**
- The review node runs from the working copy you are changing. It must be the separate checkout in `~/.si-review/checkout`.
- `bin/review-node setup` picks an Astra model by itself. Rewrite it to require `--astra-model`.
