### Goal
Machine-checkable definitions of every bridge message and every `si_*` tool payload, shared by the Elixir server and the TypeScript extension.

### Context
`04-protocols.md` §2 (all messages), `05-schemas-and-config.md` §3 (tool payloads).

### Deliverables
- `protocol/bridge/v1/`: `join.schema.json`, `join_reply.schema.json`, `event.schema.json` (envelope + `data` per `type` using `oneOf` with `const` discriminators), `events_batch.schema.json`, `slot_request.schema.json`, `slot_reply.schema.json`, `slot_release.schema.json`, `tool_request.schema.json`, `tool_reply.schema.json`, `control.schema.json`, `control_ack.schema.json`, and `examples/*.json` (one valid example per schema, taken from `04-protocols.md`).
- `protocol/tools/`: `si_task.result.schema.json`, `si_report.args.schema.json`, `si_ask.args.schema.json`, `si_ask.result.schema.json`, `si_scope.args.schema.json`, `si_scope.result.schema.json`, `si_verdict.args.schema.json`, `si_plan.args.schema.json`, `si_dispute.args.schema.json`, with examples.
- `lib/si/bridge/protocol.ex` (`Si.Bridge.Protocol`), tests `test/si/bridge/protocol_test.exs`.

### Specification
- JSON Schema draft 2020-12, `"$id"` of the form `https://si.local/protocol/bridge/v1/<name>.json`; `additionalProperties: true` on envelopes (forward compatibility) but required fields listed; enums for `role`, `mode`, `priority` (`you`, `review`, `builder`, `lead`, `background`), control `action`, event `type`.
- `si_verdict.args`: `verdict` enum, `summary` (≤ 4,000 chars), `findings[]` (each: `severity`, `file`, `line` (integer ≥ 1 or null), `category` enum from `05` §3, `problem` (≤ 2,000), `evidence` object (`kind` enum, `detail` ≤ 2,000) optional, `suggested_fix` optional), `previous[]` optional. Enforce "approve has no blocking findings" in Elixir (`Si.Review.Verdict`, T05.02), not in the schema.
- `Si.Bridge.Protocol`:
  ```elixir
  @spec supported() :: [pos_integer()]                              # [1]
  @spec validate(atom(), map()) :: :ok | {:error, [String.t()]}      # kinds: :join, :join_reply, :event, :events_batch, :slot_request, :slot_reply, :slot_release, :tool_request, :tool_reply, :control, :control_ack, {:tool_args, name}, {:tool_result, name}
  @spec event_types() :: [String.t()]
  ```
  Schemas are read at compile time (`@external_resource` for every file) and built once with `JSV.build!/1`; error strings contain the JSON pointer.

### Tests
- Every example validates.
- For each schema, at least one invalid variant fails with a pointer in the message (missing required field, wrong enum, wrong type).
- `event_types/0` equals the types in `04-protocols.md` §2.2.

### Acceptance criteria
Tests pass; `bin/ci` passes; every message in `04-protocols.md` §2 has a schema.

**Expected result.**
- Every bridge message and every `si_*` tool payload in `04-protocols.md` §2 and `05-schemas-and-config.md` §3 has a JSON Schema file (draft 2020-12) and a valid example.
- `Si.Bridge.Protocol` validates messages against those files, built once at compile time.

**Checks**
1. List the message and payload names in 04 §2 and 05 §3, and compare them with `ls protocol/bridge/v1/*.schema.json protocol/tools/*.schema.json`.
   Expected: one schema per message or payload, and one example per schema.
2. `touch protocol/bridge/v1/join.schema.json && mix compile`.
   Expected: `Si.Bridge.Protocol` recompiles (`@external_resource` works).
3. Validate an invalid variant.
   Expected: the error string contains the JSON pointer of the bad field.
4. `event_types/0`.
   Expected: exactly the types in 04 §2.2.

**Redo if**
- Schemas are written as Elixir maps instead of being read from the JSON files. Rewrite the module to read the files: Elixir and TypeScript must validate against the same files.
