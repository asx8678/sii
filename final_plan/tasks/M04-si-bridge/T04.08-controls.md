### Goal
Send controls (deliver, abort, model, thinking, tools, compact, status, pause/resume) to sessions and get acknowledgements, respecting each session's mode.

### Context
`04-protocols.md` §2.3. Pi extension API: `pi.sendUserMessage(text, {deliverAs: "steer" | "followUp"})`, `pi.sendMessage(message, {deliverAs: "nextTurn", triggerTurn})`, `ctx.abort()`, `ctx.compact()`, `pi.setModel(model)`, `ctx.modelRegistry.find(provider, id)`, `pi.setThinkingLevel(level)`, `pi.setActiveTools(names)` (names must already be registered), `ctx.ui.setStatus`. Check the exact `sendMessage` message shape in Pi's `types.ts`.

### Deliverables
- `bridge/src/controls.ts`, tests `bridge/test/controls.test.ts`.
- `Si.Sessions.control/4` and controller correlation of `control_id` → caller; tests `test/si/sessions/control_test.exs`.

### Specification
Bridge: on `control` push, check the mode (control: all actions; suggest: only `deliver` with `as: "nextTurn"`, and `status`; observe: only `status`), execute, and push `control_ack {control_id, ok, error, result}`. Unknown action → `ok: false, error: "unknown_action"`. `set_model` with an unknown model → `ok: false, error: "model_not_found"`.

Server:
```elixir
@spec control(String.t(), atom(), map(), timeout()) :: {:ok, map()} | {:error, term()}
```
Path selection:
- **Si-started sessions** use RPC for everything RPC supports (`deliver` steer/followUp → `steer`/`follow_up`; `abort`; `set_model`; `set_thinking` → `set_thinking_level`; `compact`), because RPC works even when the extension failed to load. `set_tools`, `status`, `pause`, `resume` and `deliver` with `nextTurn` require the bridge (`{:error, :bridge_required}` when disconnected).
- **User sessions** use the bridge only.
- The controller generates `control_id` (`ctl_`), stores `{control_id, from, deadline}`, pushes through the channel, and replies on `{:control_ack, ...}`; timeout → `{:error, :timeout}`.
- Events `control.sent` and `control.acked` (`ok`, `error`).

### Tests
- vitest: each action calls the right Pi API with the right arguments (mock `pi`/`ctx`); mode enforcement; unknown model.
- Elixir: control over a test channel (ChannelTest) with ack; timeout; Si session falls back to RPC when the bridge is disconnected (fake Pi records the RPC command); `set_tools` without a bridge → `{:error, :bridge_required}`.

- Controls reach sessions and are acknowledged.
- Si sessions use RPC for everything RPC supports, and the bridge for the rest.
- User sessions use only the bridge.
- Mode rules are enforced, and every control is recorded.

**Checks**

   Expected: the fake Pi records a `follow_up` RPC command.
