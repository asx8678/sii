### Goal
Prove, against the real pinned Pi (0.87.1) with scripted models, that every hook and control the bridge relies on behaves as designed, and that the bridge is cheap. This suite gates every future Pi or Fabric upgrade.

### Context
`06-quality-and-testing.md` §3 and §6.

### Deliverables
- `test/contract/bridge_contract_test.exs` (`@moduletag :contract`, `@moduletag :pi`).
- `bin/contract-test` (runs `mix test --only contract --include pi`; on success it appends a line to `protocol/compat.yml` unless an entry with the same `pi`, `fabric`, `fovea` and `bridge` versions and `result: pass` already exists, so repeated runs leave the file unchanged).
- `protocol/compat.yml` with the first entry.

### Specification
Each test starts a real session through `Si.Sessions.start/1` with si-faux scripts. Scenarios:
1. Join handshake carries the toolchain versions.
2. A simple text turn produces, in order: `session_start`, `agent_start`, `turn_start`, `model_call`, `message_end` (with the same `call_id`), `turn_end`, `agent_end`, `agent_settled`; every event validates against the schema.
3. A `write` tool call produces `tool_start`/`tool_end` with `files: ["<path>"]`.
4. `si_report` reaches a test handler and terminates the turn (no further `model_call`).
5. `deliver` follow-up while a slow faux turn is running (`tokensPerSecond` low) arrives after `agent_settled`.
6. `abort` during a slow turn → `agent_settled` within 2 s.
7. `set_model` to a second faux model id → the next `model_call` shows it.
8. `set_tools` removing `write` → a scripted `write` call fails as an unknown or inactive tool.
9. Slot gate: a delayed grant (test stub, 500 ms) → `model_call.wait_ms` ≥ 450.
10. `pause`, then a prompt: no `model_call` until `resume`.
11. Si endpoint restarted mid-session: the bridge reconnects and buffered events arrive with increasing `seq`.
12. Overhead: `/si status` stats from the bridge (handler p95 and flush p95, read through a `notice` event emitted on `session_shutdown`) are below 5 ms.
13. A builder with Fabric in full code mode (profile `builder`) can call `si_task` directly: `capture.keepVisible` works with the pinned Fabric.
14. An Astra session (profile `reviewer`, `--tools read,grep,find,ls,si_verdict,si_ask`) can call `si_verdict`. Then `set_tools` adds `edit`, which was not in the startup allowlist: record whether Pi activates it. If it does not, T05.08 uses its fallback (start Astra with the fix tools registered but inactive).
15. Stopping a session and starting it again with the same `--session-dir`/`--session-id` reopens the same session file and conversation.
16. A `prompt` that triggers compaction in its preflight (faux summarization with a slow `tokensPerSecond`) does not time out, and `compaction_start`/`compaction_end` are observed.

`bin/contract-test` on success appends (only when that combination of versions is not recorded yet):
```yaml
- {date: 2026-09-27, pi: 0.87.1, fabric: 0.97.0, fovea: 0.31.1, bridge: 0.1.0, result: pass}
```
