### Goal
Create the `bridge/` TypeScript package as a Pi extension that Pi loads with `-e`, with lint, typecheck and unit tests wired into `bin/ci`.

### Context
`02-repo-layout.md` §1 and §4. Pi loads extension TypeScript source directly (see `pi-fovea/package.json`: `"pi": {"extensions": ["./src/index.ts"]}`). Extension API reference: `/Users/adam2/projects/pair/pi/packages/coding-agent/docs/extensions.md` and `src/core/extensions/types.ts` in the same repo.

### Specification
- `src/config.ts`:
  ```ts
  export type BridgeConfig = { url: string | null; token: string | null; sessionId: string | null; role: Role;
    mode: "observe" | "suggest" | "control"; runId: string | null; taskId: string | null; parentSessionId: string | null;
    versions: { pi: string | null; fabric: string | null; fovea: string | null; bridge: string } };
  export function loadConfig(env: NodeJS.ProcessEnv, readFile: (p: string) => string | null): BridgeConfig;
  ```
  - `url`: `SI_BRIDGE_URL`, else the content of `$SI_HOME/bridge_url` (`SI_HOME` or `~/.si`), else null.
  - `token`: `SI_BRIDGE_TOKEN`, else `$SI_HOME/bridge_token`, else null.
  - `role`: `SI_ROLE` or `"user"`; `mode`: `"control"` when `SI_SESSION_ID` is set (Si-started), else `SI_BRIDGE_MODE` or `"observe"`.
  - `versions`: from `SI_VERSIONS` (JSON set by Si for its sessions) or nulls; `bridge` from package.json.
- `src/index.ts`: `export default function (pi: ExtensionAPI) { const cfg = loadConfig(process.env, safeRead); console.error(\`si-bridge ${cfg.versions.bridge} loaded (role=${cfg.role}, mode=${cfg.mode}${cfg.url ? "" : ", no Si url"})\`); }` (connection comes in T04.04). If `url` or `token` is null the extension stays inert.
- Si side: `Si.Sessions.start/1` adds `SI_VERSIONS` (JSON of the toolchain versions + bridge version read from `bridge/package.json`).

### Tests
- vitest `config.test.ts`: env precedence, file fallbacks, Si-started vs user defaults, missing everything → inert config.
- Elixir `@tag :pi` (in `test/si/bridge/load_test.exs`): a builder session started through `Si.Sessions.start/1` has `si-bridge 0.1.0 loaded (role=builder, mode=control)` in its stderr log.

`cd bridge && npm ci && npm run lint && npm run typecheck && npm test` pass; `bin/ci` runs them; the `:pi` test passes.

**Expected result.**
- `bridge/` is a Pi extension package with strict TypeScript, biome, vitest and a committed lockfile.
- It loads through `-e`, prints its load line to stderr, and stays inert without a URL and a token.
- `bin/ci` runs its lint, typecheck and tests.
- Si sets `SI_VERSIONS` for its sessions.

**Checks**
1. `(cd bridge && rm -rf node_modules && npm ci && npm run lint && npm run typecheck && npm test)`.
   Expected: all pass.
2. `bin/ci 2>&1 | grep -E '^==> bridge'`.
   Expected: the bridge step runs, and `bin/ci` ends with `PASS`.
3. `git ls-files bridge/package-lock.json`.
   Expected: the lockfile is tracked.
4. The `:pi` load test.
   Expected: the stderr log contains exactly `si-bridge 0.1.0 loaded (role=builder, mode=control)`.
5. Load the extension with no URL and no token (unit test).
   Expected: no connection attempt, and no error thrown.

**Redo if**
- The extension throws at load time when Si is not running. It must stay inert.
