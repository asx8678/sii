### Goal
Let you add the bridge to your own Pi so your terminal sessions appear in Si, in observe mode by default, with the mode always visible and changeable.

### Context
`00-overview.md` (roles: your sessions join only if you opt in). Pi packages: `/Users/adam2/projects/pair/pi/packages/coding-agent/docs/packages.md` (how to install a local package or add it to `settings.json`).

### Deliverables
- CLI `si bridge install` (prints the exact command or settings entry for your Pi, with the absolute `bridge/` path; does not modify your Pi config itself unless `--apply` is given, in which case it runs the documented `pi install <path>` command).
- `/si mode observe|suggest|control` in the bridge; a new event type `mode_changed` (`{mode}`) added to the v1 schema (additive change).
- Cockpit: user sessions show a mode badge; control buttons are disabled when the mode does not allow them.
- Tests: vitest for `/si mode`; ChannelTest for `mode_changed` updating the session row.

### Specification
- User sessions join `session:new`; the join payload's mode comes from `SI_BRIDGE_MODE` (default `observe`).
- `/si mode <m>`: updates the local mode, pushes a `mode_changed` event, updates the status line (`Si · <m> · connected`).
- Your input always wins: in `control` mode, a `deliver` with `as: "steer"` from Si is converted to `followUp` while you are typing (use `ctx.ui.getEditorText()` non-empty as the signal where available; otherwise no conversion).

### Tests
As listed; plus the CLI prints a command containing the absolute bridge path.

### Acceptance criteria
Tests pass; manual check: after `si bridge install --apply`, a new `pi` terminal session appears in the cockpit as a user session in observe mode.
