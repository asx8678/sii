### Goal
Report every `fabric_exec` outcome from Fabric's structured, versioned trace so Si can measure code-mode failures and learn from them.

### Context
Fabric docs `/Users/adam2/projects/pair/pi-fabric/docs/audit-trace.md`: the final `fabric_exec` result `details` is a bounded envelope `{success, trace, audits, phases, error}` with `trace.kind === "pi-fabric.execution"`, `trace.version === 1`, `trace.outcome` (`succeeded | failed | aborted | timed_out`), `trace.phases`, `trace.operations`, `trace.counts`.

### Deliverables
`bridge/src/fabric.ts`, fixtures `bridge/test/fixtures/fabric/*.json` (succeeded, failed in a typecheck phase, aborted, older/unknown version), tests `bridge/test/fabric.test.ts`.

### Specification
In the `tool_execution_end` handler (or `tool_result`, whichever carries `details`), when the tool name is `fabric_exec` and `details.trace?.kind === "pi-fabric.execution" && details.trace.version === 1`, emit `fabric_exec`:
- `outcome` = `trace.outcome`; `phases` = `trace.phases`; `operation_count` = `trace.operations.length`.
- `failure` (only when outcome is not `succeeded`): `stage` = the last entry of `trace.phases` (or `details.phases`), `error_class` = the leading identifier of `details.error` matching `/^([A-Za-z]+Error|[A-Za-z]+Exception)/` or `"Error"`, `message` = `details.error` truncated to 300 characters.
- Any other version or shape → no `fabric_exec` event, one `notice` per session (`"unknown fabric trace version"`).

### Tests
One test per fixture; the event validates against the schema; unknown version produces exactly one notice.

### Acceptance criteria
Tests pass; `bin/ci` passes.
