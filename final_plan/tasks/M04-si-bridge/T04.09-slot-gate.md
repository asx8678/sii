### Goal
Before each model call, the bridge asks Si for a slot and waits for it; this is the basis for scheduling, pausing and budget stops. If Si is unreachable, the session continues after a short wait.

### Context
`04-protocols.md` §2.5, `01-architecture.md` §5.3. Pi awaits `before_provider_request` handlers (`src/core/extensions/runner.ts`, `emitBeforeProviderRequest`), so an async handler can hold the request. Returning `undefined` keeps the payload unchanged.

### Deliverables
- `bridge/src/slots.ts` (`SlotGate`), tests `bridge/test/slots.test.ts`.
- `lib/si/bridge/slots.ex` (`Si.Bridge.Slots` stub admission: grant immediately; pause state per session), asynchronous replies in `SessionChannel`; `Si.Sessions.pause/1`, `resume/1` (bridge controls). Tests `test/si/bridge/slots_test.exs`.

### Specification
Bridge `SlotGate`:
- `acquire({call_id, provider, model, priority, request_bytes}): Promise<{slot_id | null, wait_ms}>`:
  1. While `paused`: wait for `resume`; if paused longer than 30 minutes → `ctx.abort()` and emit a `notice` (`"paused too long; turn aborted"`).
  2. Connected: push `slot_request` with **no client timeout**; resolve on reply. If the channel errors or disconnects while waiting, fall through to 3.
  3. Not connected: wait up to `slot_timeout_ms` for a connection (then do 2), else resolve with `slot_id: null` (proceed without a slot).
- `release({slot_id, call_id, status, latency_ms, retry_after_s})`: push `slot_release` (fire and forget; buffered if disconnected; dropped if `slot_id` is null).
- Priority: `SI_PRIORITY` env if set by Si, else by role (`astra`/`critic`/`arbiter` → `review`, `builder` → `builder`, `lead` → `lead`, `user` → `you`).
- `pause`/`resume` controls toggle `paused`.
- `wait_ms` goes into the `model_call` event (T04.05).

Server:
- `SessionChannel.handle_in("slot_request", payload, socket)` → `Si.Bridge.Slots.request(session_id, payload, socket_ref(socket))` returns `:noreply`; `Si.Bridge.Slots` replies via `Phoenix.Channel.reply(ref, {:ok, %{grant: true, slot_id: ...}})` — immediately in this task, later (M08) when the scheduler grants.
- Paused sessions (a `pause` control sent through the bridge) are marked in `Si.Bridge.Slots` so the cockpit can show them.

### Tests
- vitest (fake timers): connected grant path; delayed grant (reply after 500 ms) → `wait_ms ≈ 500`; disconnected → resolves after `slot_timeout_ms` with `slot_id: null`; paused → waits until resume; 30-minute limit aborts (fake timers).
- Elixir: `slot_request` gets an asynchronous reply; a test stub that delays grants for 300 ms does not block other channel messages.

**Expected result.**
- Before each model call, the bridge asks for a slot and waits, with no client timeout while connected.
- Without Si, it proceeds after `slot_timeout_ms`.
- While paused it holds the call, and aborts after 30 minutes.
- The server replies asynchronously, and a delayed grant never blocks the channel.

**Checks**
1. A grant delayed by 500 ms, under fake timers.
   Expected: `wait_ms` is about 500 and appears in the `model_call` event.
2. Disconnected.
   Expected: the call resolves with `slot_id: null` after `slot_timeout_ms`.
3. A server stub that delays grants by 300 ms.
   Expected: other channel messages are answered at once.
4. The return value of the `before_provider_request` handler.
   Expected: `undefined`, so the payload is unchanged.

**Redo if**
- The slot request has a client-side timeout while connected. Remove it: the scheduler decides.
