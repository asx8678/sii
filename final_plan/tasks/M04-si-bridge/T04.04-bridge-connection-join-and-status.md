### Goal
The extension connects to Si, joins its session channel with the handshake, reconnects on failure, buffers events while disconnected, shows its state in Pi's status line, and offers a `/si` command.

### Context
`04-protocols.md` §2.1 and §2.6. Phoenix JS client: `new Socket(url, {params: {token}, reconnectAfterMs})`, `socket.channel(topic, payload)`, `channel.join().receive("ok"|"error"|"timeout")`, `channel.push(event, payload).receive(...)`, `channel.on(event, cb)`.

### Deliverables
- `bridge/src/connection.ts` (`BridgeConnection`), `bridge/src/buffer.ts` (`EventBuffer`), `bridge/src/status.ts`, `bridge/src/commands.ts`; `src/index.ts` wires them.
- Tests `bridge/test/connection.test.ts`, `bridge/test/buffer.test.ts`; Elixir `@tag :pi` test `test/si/bridge/connect_test.exs`.

### Specification
- `BridgeConnection` (constructor takes the config and a socket factory for tests):
  - `start(ctxProvider)`: create the socket with `params: {token}`, `reconnectAfterMs: (tries) => [100, 500, 1000, 2000, 5000][tries - 1] ?? 5000`; join topic `session:<sessionId>` or `session:new` with the join payload (`protocol: 1`, `session_id`, `role`, `pid: process.pid`, `cwd`, `session_file` (from the extension context's session manager if available, else null — check `ExtensionContext` in Pi's `types.ts`), `versions`, `mode`, `parent_session_id`, `run_id`, `task_id`).
  - On join ok: store `session_id`, `mode`, `slot_timeout_ms`, `batch_ms`, `max_batch` from the reply; set status; flush the buffer.
  - On join error with `protocol_unsupported` or `unknown_session`: stop reconnecting, set status `Si · <reason>`, stay inert.
  - `request(event, payload, timeoutMs | null): Promise<reply>` wraps `channel.push`; rejects with `NotConnectedError` when not joined.
  - `connected(): boolean`, `onControl(cb)`, `close()`.
- `EventBuffer`: capacity 2,000; when full, drop the oldest and count; `drain(max)` returns up to `max` events; the dropped count is reported with a `notice` event (`"dropped <n> events while disconnected"`) after reconnect.
- Status (`ctx.ui.setStatus("si", text)`): `Si · <mode> · connected`, `Si · disconnected (retrying)`, `Si · off`. The latest `ExtensionContext` is captured from the first lifecycle handler (`session_start`) and refreshed from later handlers.
- `/si` command (`pi.registerCommand("si", {description: "Si bridge status and controls", handler})`): no argument or `status` → `ctx.ui.notify` with url, session id, mode, connected, events sent, events dropped; `disconnect` → close and stay off until `/si connect`; `connect` → start again.

### Tests
- vitest with a fake socket factory: join payload shape validates against `protocol/bridge/v1/join.schema.json` (ajv); status text transitions; buffer drops oldest and reports; `request` rejects when disconnected; join errors stop reconnecting.
- Elixir `@tag :pi`: a real builder session (toolchain Pi + bridge + si-faux) connects; within 5 s the session row has `bridge_status: "connected"` and the controller got `{:bridge_connected, _}`; stopping Si's endpoint (`Supervisor.terminate_child` on the endpoint in the test) flips it to disconnected and restarting reconnects.
