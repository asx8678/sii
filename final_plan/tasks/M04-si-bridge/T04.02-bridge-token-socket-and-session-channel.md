### Goal
The server side of the bridge: token authentication on `127.0.0.1`, a channel per session, the join handshake, and stubs for every client message so later tasks only fill in behavior.

### Context
`04-protocols.md` §2.1–2.3.

### Deliverables
- `lib/si/bridge/token.ex` (`Si.Bridge.Token`), `lib/si_web/channels/bridge_socket.ex` (`SiWeb.BridgeSocket`), `lib/si_web/channels/session_channel.ex` (`SiWeb.SessionChannel`).
- Endpoint: `socket "/bridge", SiWeb.BridgeSocket, websocket: [connect_info: [:peer_data]], longpoll: false`.
- On endpoint start, write `$SI_HOME/bridge_url` (e.g. `ws://127.0.0.1:4040/bridge/websocket`) so your own Pi sessions can find Si (T04.12).
- `Si.Sessions.start/1` now sets `SI_BRIDGE_URL` and `SI_BRIDGE_TOKEN` in the session env.
- Controller additions: handle `{:bridge_connected, channel_pid}` and `{:bridge_disconnected, reason}`; store the channel pid.
- Tests `test/si_web/channels/session_channel_test.exs`, `test/si/bridge/token_test.exs`.

### Specification
- `Si.Bridge.Token.ensure!/0`: create `$SI_HOME/bridge_token` with 32 random bytes as lowercase hex via `Si.Paths.write_secret!/2` if missing; `read!/0`. Called at application start.
- `BridgeSocket.connect(%{"token" => t}, socket, connect_info)`: `Plug.Crypto.secure_compare(t, Token.read!())` and the peer address is loopback (`{127,0,0,1}` or `{0,0,0,0,0,0,0,1}`); otherwise `:error`. `id/1` returns `nil`.
- `SessionChannel.join("session:" <> sid, payload, socket)`:
  1. `Protocol.validate(:join, payload)`; error → `{:error, %{reason: "invalid_join"}}`.
  2. `payload["protocol"] not in Protocol.supported()` → `{:error, %{reason: "protocol_unsupported"}}`.
  3. `sid == "new"`: insert a session row with `kind: "user"`, `role: "user"`, `state: "idle"`, `mode: payload["mode"] || "observe"`, `cwd`, `versions`, `bridge_status: "connected"`, event `session.started`; the new id is used for this channel from now on.
  4. Otherwise the session must exist with `kind: "si"`, else `{:error, %{reason: "unknown_session"}}`. Mark `bridge_status: "connected"`, send `{:bridge_connected, self()}` to its controller (via `Si.Sessions.whereis/1`), event `bridge.connected` with versions.
  5. Reply `%{session_id, mode, server_protocol: 1, slot_timeout_ms, batch_ms, max_batch}` from settings `bridge.*`.
- `terminate/2`: `bridge_status: "disconnected"`, event `bridge.disconnected` (reason), notify the controller.
- `handle_in` stubs (replaced by later tasks):
  - `"events"` → validate the batch; reply `{:ok, %{}}` (T04.06 stores them).
  - `"slot_request"` → reply later with `%{grant: true, slot_id: Si.Id.generate("slot")}` through `Si.Bridge.Slots` (stub grants immediately; T04.09 makes the reply asynchronous; T08.04 connects the scheduler).
  - `"slot_release"` → `{:reply, {:ok, %{}}, socket}`.
  - `"tool"` → `Si.Bridge.Tools.handle(session_id, name, args)` (stub returning `%{ok: false, error: "not_available"}` until T04.07).
  - `"control_ack"` → forward `{:control_ack, payload}` to the controller.
- `handle_info({:push_control, control}, socket)` → `push(socket, "control", control)`.

### Tests
(`Phoenix.ChannelTest`)
- Wrong token → connect error; right token → ok.
- Join for an existing `si` session: reply fields, row `bridge_status` connected, event recorded, the controller (a test process registered under the session id) receives `{:bridge_connected, pid}`.
- Join `session:new` creates a `user` session and returns its id.
- Invalid payload → `invalid_join`; `protocol: 2` → `protocol_unsupported`; unknown id → `unknown_session`.
- Closing the channel marks the row disconnected and records the event.
- `bridge_token` exists with mode `0600` after boot.

**Expected result.**
- The server side of the bridge works:
  - a token file (0600) and a `bridge_url` file;
  - a socket that accepts only loopback peers with the right token;
  - a channel per session with the join handshake;
  - stubs for every client message.
- Controllers learn when a bridge connects and disconnects.
- Si sessions get `SI_BRIDGE_URL` and `SI_BRIDGE_TOKEN`.

**Checks**
1. After starting the node: `stat -f '%Lp' ~/.si/bridge_token` and `cat ~/.si/bridge_url`.
   Expected: `600`, and `ws://127.0.0.1:4040/bridge/websocket`.
2. A connect with the right token but a non-loopback `peer_data` (from the test).
   Expected: refused.
3. `grep -rlF -f ~/.si/bridge_token ~/.si/logs 2>/dev/null | wc -l`.
   Expected: `0`.
4. `session:new` without a mode.
   Expected: a `user` session with `mode: "observe"`.
5. Close the channel.
   Expected: the session row shows `bridge_status: "disconnected"`, and the event `bridge.disconnected` is recorded.

**Redo if**
- The token is compared with `==`. Use `Plug.Crypto.secure_compare/2`.
- The socket listens on something other than loopback. The endpoint must bind to 127.0.0.1.
