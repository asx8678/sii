### Goal
Translate Pi's extension events into the protocol's events, summarized and batched, with pointers instead of transcript text.

### Context
`04-protocols.md` §2.2 (event table). Pi's event interfaces are in `/Users/adam2/projects/pair/pi/packages/coding-agent/src/core/extensions/types.ts` (search for `type: "turn_end"`, `"message_end"`, `"tool_execution_end"`, `"before_provider_request"`, `"after_provider_response"`, …); read them to map fields exactly.

### Deliverables
- `bridge/src/events.ts` (handlers + mapping), `bridge/src/batcher.ts`; tests `bridge/test/events.test.ts`, `bridge/test/batcher.test.ts`.

### Specification
Handlers registered with `pi.on(name, handler)`; each handler is synchronous and cheap (no awaits except where noted) and never throws (wrap in try/catch and emit a `notice` on unexpected errors):

| Pi event | Protocol event | Notes |
|---|---|---|
| `session_start` | `session_start` | model, thinking level, active tools (`pi.getActiveTools()`), session file |
| `session_shutdown` | `session_shutdown` | flush synchronously as far as possible |
| `agent_start`, `agent_end`, `agent_settled` | same names | |
| `turn_start` / `turn_end` | `turn_start` / `turn_end` | duration from start; `tool_calls` counted between; `context` from `ctx.getContextUsage()` |
| `before_provider_request` | (start of a `model_call`) | remember `call_id` (uuid), `request_bytes` (`Buffer.byteLength(JSON.stringify(payload))`), start time; the slot gate (T04.09) fills `wait_ms` |
| `after_provider_response` | `model_call` | status, latency, `retry_after_s` from headers |
| `message_end` (assistant) | `message_end` | `usage`, `stop_reason`, `model`, `entry_id` when present, and `call_id` of the most recent model call so Si can join usage to the call |
| `tool_execution_start` / `tool_execution_end` | `tool_start` / `tool_end` | duration, `ok` (not an error result), output byte size, `files` from args of `read`/`write`/`edit` (`path`), `exit_code` for `bash` when present |
| `model_select` | `model_select` | |
| `thinking_level_select` | `thinking_select` | |
| `session_compact` | `compaction` | reason, token counts when present |

- Never include message text, tool output text or file contents.
- `Batcher`: collects events with increasing `seq` (per connection, starting at 1), flushes when `max_batch` is reached or `batch_ms` elapses, pushing `events` with `{batch}`; while disconnected, events go to the `EventBuffer`.
- Measure handler time with `performance.now()`; keep running p50/p95 counters exposed by `/si status`.

### Tests
- For each row, a fake event object in → the expected protocol event out, validated against `protocol/bridge/v1/event.schema.json` with ajv.
- The `call_id` of a `model_call` matches the following `message_end`.
- Batcher (vitest fake timers): flush on size and on time; `seq` strictly increasing; disconnected events are buffered then sent in order.
- A handler that throws internally produces a `notice` and does not propagate.

### Acceptance criteria
Tests pass; no handler sends text content (a test scans emitted events for a known secret-looking string placed in the fake message text: not found).
