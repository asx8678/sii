### Goal
When a role is allowed to use Fabric child agents, count their tokens and cost toward budgets and analytics.

### Context
Fabric writes a usage-only session file per child agent (`sessionExport`, on by default); see `/Users/adam2/projects/pair/pi-fabric/docs/configuration.md` ("Usage tracking with external tools") for the location rules (`sessionExportDir`, `PI_FABRIC_AGENT_DIR`). Si workers have children disabled by default (`agents.maxDepth: 0`).

### Deliverables
- Si sets `PI_FABRIC_AGENT_DIR=$SI_HOME/profiles/<profile>/fabric-agent` for sessions whose role allows children (per-role setting `fabric.children: true`), making the location deterministic.
- Op `fabric.child_usage {dirs, since}` parsing those files; `Si.FabricUsage` poller (every 60 s) inserting `model_calls` rows with `via: "fabric_child"` attributed to the parent session (match on `cwd` and time window); tests with fixture usage files.

### Specification
- Parse each file with Pi's session format (entries with `usage`); return `{file, cwd, started_at, provider, model, input, output, cache_read, cache_write, cost}` per assistant entry.
- Deduplicate by `(file, entry id)`.
- Roles with children enabled also get `agents.maxDepth` from the role setting and `maxConcurrent`/`budgetUsd` derived from the task budget written into their `fabric.json` (T03.02 profile generation reads these role settings).

### Tests
Fixture files → rows with correct attribution; duplicates ignored; budgets include them.

### Acceptance criteria
Tests pass; `bin/ci` passes.

**Expected result.**
- For roles that are allowed Fabric child agents, the children's usage files are found in a deterministic location.
- Their usage is parsed and deduplicated, stored as `model_calls` with `via: "fabric_child"` on the parent session, and counted in budgets.

**Checks**
1. The fixture usage files, parsed twice.
   Expected: one set of rows.
2. Attribution.
   Expected: each row belongs to the parent session whose cwd and time window match.
3. The session environment for a role without children.
   Expected: no `PI_FABRIC_AGENT_DIR`, and `agents.maxDepth: 0` in its `fabric.json`.

**Redo if**
