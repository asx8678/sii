### Goal
A small Node process, supervised by Si over a length-prefixed Port, that runs the same Fabric and Fovea versions as the sessions and answers operations Si cannot do from Elixir.

### Context
`04-protocols.md` §3 (protocol), `01-architecture.md` D11.

### Deliverables
- `adapter/package.json` (`@si/adapter`, private, `"type": "module"`; dependencies `pi-fabric@0.97.0`, `pi-fovea@0.31.1` (exact), `tsx`; devDependencies `typescript`, `vitest`, `@biomejs/biome`; scripts `lint`, `typecheck`, `test`), `adapter/tsconfig.json`, `adapter/src/main.ts`, `adapter/src/framing.ts`, `adapter/src/ops/hello.ts`, `adapter/src/ops/registry.ts`.
- `lib/si/adapter.ex` (`Si.Adapter`, GenServer owning the Port) and `Si.Adapter.Supervisor`; tests `adapter/test/framing.test.ts`, `test/si/adapter_test.exs`.

### Specification
Adapter:
- Runs with `node --import tsx adapter/src/main.ts` (tsx resolves Fovea's TypeScript sources, which use `.js` import specifiers).
- `framing.ts`: `FrameReader` accumulates stdin chunks and yields complete frames (4-byte big-endian length + UTF-8 JSON); `writeFrame(obj)` writes length + JSON to stdout (honoring backpressure). Max frame 64 MiB.
- `main.ts`: on start, send the `hello` response (`id: 0`) with versions read from `node_modules/pi-fabric/package.json`, `node_modules/pi-fovea/package.json` and `process.version`; then for every request frame run the op asynchronously and write `{id, ok, result}` or `{id, ok: false, error: {code, message}}`; unknown op → `code: "unknown_op"`. Exit 0 on stdin end. Logs go to stderr only.
- Test-only op `debug.echo` (enabled when `SI_ADAPTER_TEST=1`) returns its args.

Elixir:
```elixir
@spec call(String.t(), map(), timeout()) :: {:ok, map()} | {:error, term()}
@spec ready?() :: boolean()
```
- `Port.open({:spawn_executable, node_path}, [:binary, {:packet, 4}, :exit_status, :use_stdio, args: ["--import", "tsx", main_path], cd: adapter_dir, env: [{"TMPDIR", System.tmp_dir!()} | extra]])`; wait up to 10 s for `hello`; compare its versions with the current toolchain; mismatch → log an error and stay not-ready (calls return `{:error, :adapter_version_mismatch}`).
- Requests get integer ids; replies are matched by id; per-call timeouts; a crash replies `{:error, :adapter_down}` to all pending calls; the supervisor restarts the adapter with exponential backoff (1 s … 60 s).
- stderr of the adapter is appended to `$SI_HOME/logs/adapter.log` (use the same `sh -c ... 2>>` wrapper as the runner).

### Tests
TS: frames split across chunks and multiple frames in one chunk; large frame. Elixir: hello and version check; `debug.echo` round trip including a 1 MB payload; 50 concurrent calls; kill the node process → pending calls fail with `:adapter_down` and a restart follows.

### Acceptance criteria
Tests pass; `bin/ci` passes (adapter lint and tests run).

**Expected result.**
- `si-adapter` is a Node process on a `{:packet, 4}` Port. It says hello with its versions and answers ops asynchronously by id.
- Si supervises it with exponential backoff, rejects it when the versions don't match, and fails pending calls with `:adapter_down` when it crashes.

1. `(cd adapter && rm -rf node_modules && npm ci && npm run lint && npm run typecheck && npm test)`.
   Expected: all pass. `bin/ci` runs the adapter step.
2. Kill the node process during 50 concurrent calls.
   Expected: every pending call gets `{:error, :adapter_down}`; a restart follows after the backoff.
3. `debug.echo` without `SI_ADAPTER_TEST=1`.
   Expected: `unknown_op`.
4. `ls -la ~/.si/logs/adapter.log` after a run.
   Expected: the adapter's stderr is there, and its stdout carries only frames.
