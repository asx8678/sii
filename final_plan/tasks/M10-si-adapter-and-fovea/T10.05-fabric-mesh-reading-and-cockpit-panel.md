### Goal
Show the Fabric agents, actors, messages and task keys of your own sessions' projects in the cockpit, read-only, using Fabric's own code.

### Context
Fabric's mesh lives in `<project>/.pi/fabric/mesh` (`events.jsonl`, `state.json`, `sequence`, `generation`, `.lock`) and is read without locks (`src/mesh/store.ts` in the Fabric repo). Writing is out of scope (see `08-later.md`).

### Deliverables
- Ops `fabric.mesh.members {root}`, `fabric.mesh.tail {root, cursor}`, `fabric.mesh.list {root, prefix}`; `lib/si/fabric_mesh.ex` (`Si.FabricMesh` poller per watched project); a "Fabric" panel on the session page and a project view; tests with a fixture mesh.

### Specification
- In the adapter, locate Fabric's mesh store and participant directory modules in the installed package (`node_modules/pi-fabric/dist/...`). If they are importable by file URL, use them (`MeshStore.read/tail/latestOffset`, participant listing). If the build bundles them so they can't be imported, implement read-only parsing of `events.jsonl` (cursor = generation × 2^32 + byte offset, as in `store.ts`) and `state.json` behind a version allowlist (`{"0.97.0": ...}`), and document the choice in the op's header comment.
- Watched projects: the `cwd` roots of connected user sessions with Fabric loaded (from the join versions); poll every 5 s with the saved cursor. Read a project's mesh only when that session's Fabric version equals the adapter's pinned version; otherwise show `Fabric <version> not supported by the adapter` and skip it, since a different version may use a different format.
- Cockpit: participants (label, kind, status, owner host, stale flag), the last 50 mesh events (topic, kind, from, text preview up to 120 characters), and `tasks/*` keys with their values.

### Tests
A fixture mesh directory (generate it in the TS test by calling Fabric's store module, or write files matching the format) → members, tail with cursor continuation, list by prefix; Elixir poller with a stubbed adapter updates the panel.

### Acceptance criteria
Tests pass; `bin/ci` passes; Si never writes into `.pi/fabric/mesh` (a test asserts file mtimes are unchanged after polling).

### Verify

```bash
(cd adapter && npm test)
mix test test/si/fabric_mesh_test.exs
```

**Expected result.**
- The Fabric mesh of the owner's sessions' projects is read-only: participants, events and task keys, through Fabric's own modules or a parser behind a version allowlist.
- The cockpit shows it.
- Si never writes into `.pi/fabric/mesh`.

**Checks**
1. The mtime test.
   Expected: every file in the fixture mesh has the same mtime before and after polling.
2. A session with a different Fabric version.
   Expected: `Fabric <version> not supported by the adapter`, and nothing is read.
3. The op's header comment.
   Expected: it states which approach was taken (Fabric's modules or its own parser) and why.

**Redo if**
- Any code opens mesh files for writing, or takes their lock. Rewrite it to read only.
