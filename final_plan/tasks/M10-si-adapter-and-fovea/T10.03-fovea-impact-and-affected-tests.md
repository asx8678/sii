### Goal
Use Fovea's `impact` analysis to choose the tests a change affects, and to show Astra what else a change is likely to touch.

### Context
pi-fovea exports `./ops` (`src/core/ops.ts`: `ensureState`, `impact`, …); CLI equivalent `fovea impact <root> --files a,b --base <ref> <budget>`. Read `ops.ts` to see what `impact` returns (rendered text and/or structured details) before implementing.

### Deliverables
- Op `fovea.impact {root, files, base, budget}` returning `{files: [{path, score}]}` (ranked); `Si.Fovea.affected_files/3`; test selection rule "fovea impact" in `Si.Checks.Tests.select/1` (between rules 2 and 3); a section in `Si.Review.Context`; tests.

### Specification
- Op: `ensureState(root)` then `impact` with the changed files and base; extract file paths and scores from the structured result when available, otherwise parse file paths from the rendered text (lines that start with a path present in the repo). Limit 200 files.
- Test selection: affected files that match `tests.patterns` (up to 50) → reason `fovea impact`. Skipped silently when the adapter is not ready.
- Astra context: `## Likely affected (Fovea)` with the top 20 non-test files not already in the diff.

### Tests
Adapter op against a small fixture TypeScript repo (two modules, one importing the other, with tests): changing the imported module lists the importer's test. Elixir selection and context section with a stubbed adapter.

### Acceptance criteria
Tests pass; `bin/ci` passes.
