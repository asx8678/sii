### Goal
Run the configured checks for a snapshot in a check slot, in a fixed order, stopping at the first failure, recording each result, and expose it as `si check`.

### Context
`03-data-model.md` (`check_results`), `05-schemas-and-config.md` §1 (`checks.*` settings), `01-architecture.md` §5.1.

### Deliverables
- Migration `create_check_results`.
- `lib/si/checks.ex` (`Si.Checks`), `lib/si/checks/check.ex` (behaviour), `lib/si/checks/context.ex`, `lib/si/checks/result.ex`, `lib/si/checks/summary.ex`.
- CLI `lib/si/cli/commands/check.ex` (`si check`).
- Tests `test/si/checks_test.exs`, `test/si/cli/check_command_test.exs`, fixture repos with trivial shell-based profiles.

### Specification
Behaviour:
```elixir
@callback name() :: atom()
@callback run(Si.Checks.Context.t()) :: {:pass | :fail | :skipped | :error, map(), Si.Checks.CommandResult.t() | nil}
```
`%Context{repo, profile, snapshot, slot, diff (from Si.Diff.for_snapshot/1), task (map or nil: scope, approved_scope, test_paths, tier), settings (thresholds, timeouts), log_dir}`.

Order (static checks first, cheapest first): `test_integrity, scope, format, build, lint, tests, diff_coverage, mutation`.

Default check sets by tier: `quick` → `[test_integrity, scope, format, build, lint, tests]`; `standard` and `full` → all eight. `si check` and `si review` without a task use the `standard` set but skip `scope` (no task scope).

```elixir
@spec run_all(Si.Evidence.Snapshot.t(), keyword()) :: {:ok, Summary.t()} | {:error, :no_profile | term()}
#   opts: checks (list), tier, task, stop_at_first_failure (default from settings), owner, overrides ([atom])
@spec results(Si.Evidence.Snapshot.t()) :: [Result.t()]
@spec register(atom(), module()) :: :ok      # used by later tasks; default registry maps names to modules that exist
```
- Profile: `Si.RepoProfile.load/1`; missing → `{:error, :no_profile}` (the CLI prints `No .si/repo.yml. Run: si repo init`). Unconfirmed profiles run but the summary carries `profile_confirmed: false`.
- Lease a slot (`Si.Checks.Pool.lease/3`), always release it (`try/after`).
- A check whose module is not registered yet returns `{:skipped, %{"reason" => "not available"}, nil}`.
- `overrides`: a failing check listed there is recorded as `pass` with `details.override = true`.
- Each result: insert `check_results` row + event `check.finished` (stream `repo:<id>`), broadcast `{:check_finished, result}` on `"checks:<snapshot_id>"`.
- After the loop: event `checks.finished` with `status` and `failed_check`; return `%Summary{snapshot_id, status: :pass | :fail | :error, results, failed_check, profile_confirmed}`.
- `status` is `:fail` if any check failed, `:error` if any errored (command could not run, timeout counts as `:fail` with `timed_out`), else `:pass`.

CLI `si check [path] [--ref REF] [--base REF] [--checks a,b] [--json]`:
- Repo from `path` (default cwd; registered on the fly with `Si.Repos.add/1`).
- Without `--ref`: freeze the working tree at `path`; base = `--base` or `git merge-base HEAD <default_branch>`.
- With `--ref`: `freeze_ref(repo, ref, base)`.
- Output: a table `CHECK · STATUS · TIME · LOG` streamed as each check finishes (subscribe to `"checks:<snapshot_id>"`), then `PASS` or `FAIL (<check>)`. `--json` prints the summary as JSON at the end instead. Exit 0 on pass, 1 on fail/error.

### Tests
- Fixture repo with profile commands `format: "true"`, `build: "sh build.sh"`, `tests: "sh test.sh {tests}"`: a pass run records 8 results (unimplemented ones `skipped`).
- A failing `build` stops the pipeline: later checks are not run (no rows) when `stop_at_first_failure: true`, and are run when `false`.
- `overrides: [:build]` records build as pass with `override: true`.
- Slot is released even when a check raises.
- CLI: table output lines appear in order; exit codes 0 and 1; `--json` is valid JSON with the summary keys.

### Acceptance criteria
Tests pass; `bin/ci` passes; `si check` works on a fixture repo against a running node.

### After implementing

Do this after the Verify commands pass. Run `bin/task-check` first, then these checks. Each check states the result you must see. Any other result means the task is not done: fix the cause in the code (never by changing what a test expects), or rewrite the part named under **Redo if**, then run `bin/task-check` and every check below again from the top. The limits on fix attempts, how to redo a task, and the evidence the completion note needs are in [10-after-each-task](../../10-after-each-task.md).

**Expected result.**
- `Si.Checks.run_all/2` leases a check slot, runs the checks in the fixed order and records every result and event.
- It stops at the first failure when configured, honours overrides, and always releases the slot.
- `si check` streams a table and exits 0 or 1.

**Checks**
1. Run `bin/si check <tmp repo>` against a temporary repo whose profile uses `format: "true"`, `build: "sh build.sh"` and `tests: "sh test.sh {tests}"`.
   Expected:
   - table rows in the order `test_integrity, scope, format, build, lint, tests, diff_coverage, mutation`, each printed as its check finishes;
   - checks that don't exist yet shown as `skipped`;
   - then `PASS`, and exit 0.
2. Make `build.sh` exit 1.
   Expected: `FAIL (build)` and exit 1, with no result rows after `build`.
3. `bin/si check <tmp repo> --json | jq -r 'keys|join(",")'`.
   Expected: the summary keys, including `snapshot_id`, `status` and `results`.
4. A check that raises (from the test).
   Expected: the slot is released, and the next lease succeeds immediately.
5. An unconfirmed profile.
   Expected: the summary has `profile_confirmed: false`, and the CLI prints a note saying so.

**Redo if**
- Checks run in the caller's directory or in a worker's worktree instead of a leased check slot. Rewrite them to run in the slot.
