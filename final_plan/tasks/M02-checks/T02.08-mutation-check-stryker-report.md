### Goal
Check that the tests actually catch bugs in the changed code: run the mutation tool on changed files and score only the mutants on changed lines.

### Deliverables
- `lib/si/stryker_report.ex` (`Si.StrykerReport`), `lib/si/checks/mutation.ex` (`Si.Checks.Mutation`), tests with a fixture report `test/fixtures/stryker/mutation.json` (schema: mutation-testing-report-schema, `files.<path>.mutants[]` with `status`, `mutatorName`, `replacement`, `location.start.line`, `location.end.line`).

### Specification
- Runs only for tiers `standard` and `full`; `quick` → `:skipped`.
- No `mutation` command → `:skipped` (`reason: "no command"`); languages without a configured tool simply have no command (Elixir repositories skip this check until a tool is chosen).
- Files: changed, non-deleted, non-test source files; empty → `:skipped` (`reason: "no source changes"`).
- Run with `{files}`; timeout `checks.timeouts_s.mutation`. Non-zero exit is **not** a failure by itself (Stryker exits non-zero below its own threshold); a missing report is `:error`.
- Parse `<slot>/<mutation.report_path>`. Consider mutants whose `location.start.line` is within the file's changed lines.
- Score: `(Killed + Timeout) / (Killed + Timeout + Survived + NoCoverage) * 100`; ignore `CompileError`, `RuntimeError`, `Ignored`. Denominator 0 → `:pass` (`note: "no mutants on changed lines"`).
- `:fail` when `score < checks.thresholds.mutation`.
- Details: `%{"score", "killed", "survived", "no_coverage", "survivors" => [%{"file", "line", "mutator", "replacement"}]}` (at most 20 survivors). Survivors are evidence Astra and the writer can use.

### Tests
Parser on the fixture; scoring restricted to changed lines (a survivor outside the changed lines doesn't count); quick tier skip; missing report → `:error`.

### Acceptance criteria
Tests pass; `bin/ci` passes.

**Expected result.** The mutation check runs only on the `standard` and `full` tiers, and runs the configured tool on the changed source files. It scores only the mutants on changed lines, from the Stryker JSON report, and fails below the threshold. A non-zero tool exit code alone is not a failure.

**Checks**
1. The fixture report.
   Expected: a survivor outside the changed lines doesn't change the score.
2. A tool that exits 1 but writes a report with a score above the threshold.
   Expected: `:pass`.
3. The `quick` tier.
   Expected: `:skipped`.
4. A missing report.
   Expected: `:error`.

**Redo if**
- The pass or fail result is taken from the exit code. Rewrite it to use the report.
