### Goal
Know exactly which files and which new-side lines a snapshot changed relative to its base, plus the added and removed line contents, for the checks and for Astra's context.

### Deliverables
- `lib/si/diff.ex` (`Si.Diff`), tests `test/si/diff_test.exs`.

### Specification
```elixir
@type change :: %{path: String.t(), status: :added | :modified | :deleted | :renamed | :copied | :type_changed, orig_path: String.t() | nil}
@type hunk_lines :: %{path: String.t(), orig_path: String.t() | nil, added: [{pos_integer(), binary()}], removed: [{pos_integer(), binary()}], binary: boolean()}
@spec changed_files(Path.t(), String.t(), String.t()) :: {:ok, [change()]} | {:error, term()}
@spec changed_lines(Path.t(), String.t(), String.t()) :: {:ok, %{String.t() => [Range.t()]}} | {:error, term()}
@spec hunks(Path.t(), String.t(), String.t(), [String.t()]) :: {:ok, [hunk_lines()]} | {:error, term()}
@spec parse_unified0(binary()) :: [hunk_lines()]      # pure; exposed for tests
@spec for_snapshot(Si.Evidence.Snapshot.t()) :: {:ok, %{files: [change()], lines: map(), hunks: [hunk_lines()]}}
```
- Use `Si.Git.diff_name_status/3` and `Si.Git.diff_unified0/4` with `-c core.quotepath=off` and `-M` (rename detection).
- Hunk header `@@ -a[,b] +c[,d] @@`: new-side lines are `c..c+d-1`; `d` omitted means 1; `d = 0` means no new lines. Removed lines are numbered on the old side starting at `a`.
- Lines starting with `+`/`-` inside hunks carry the content (without the prefix); ignore `\ No newline at end of file`.
- Binary files (`Binary files ... differ`) get `binary: true` and no lines.
- Deleted files appear in `changed_files` and in `hunks` (all lines removed) but not in `changed_lines`.
- Contents are kept as binaries (no UTF-8 assumption).

### Tests
- Modification at the start, middle and end of a file; pure addition; pure deletion; rename with and without edits; binary file; file without trailing newline.
- Property (StreamData): generate a random text file (1–200 lines), apply a random edit script (insertions, deletions, replacements), commit both versions in a temp repo, and assert that `changed_lines/3` equals the set of new-side line numbers the edit script inserted or replaced.

**Expected result.** `Si.Diff` reports changed files (with rename detection), new-side changed line ranges and hunks with added and removed contents. It does this from `-z` name-status output and `--unified=0` diffs, with binary files marked and no assumption that content is UTF-8.

**Checks**
1. `mix test test/si/diff_test.exs --repeat-until-failure 5`.
   Expected: the property test passes in every run.
2. A changed line containing invalid UTF-8 bytes (for example `<<0xE9>>`).
   Expected: no crash, and the bytes are kept exactly.
3. A file named `dir/ä b.txt`.
   Expected: the path appears unquoted and exact (`core.quotepath=off`).
4. Hunk headers `@@ -3 +3 @@`, `@@ -3,2 +3,0 @@` and `@@ -0,0 +1,4 @@` in `parse_unified0/1` tests.
   Expected: the new-side ranges `3..3`, none, and `1..4`.

**Redo if**
- Hunk header parsing gets an omitted count or `d = 0` wrong. Rewrite the header parser against the rules in the Specification.
