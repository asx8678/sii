### Goal
Catch changes that make tests pass by weakening them: deleted or skipped tests, removed assertions, and new lint or type-check suppressions. Only you can override this check.

### Deliverables
- `lib/si/checks/test_integrity.ex` (`Si.Checks.TestIntegrity`), rule modules under `lib/si/checks/test_integrity/`, tests `test/si/checks/test_integrity_test.exs` with diff fixtures.

### Specification
Pure analysis of `ctx.diff` (no commands). A file is a test file if it matches the profile's `tests.patterns` (or, without patterns, `**/*_test.exs`, `**/*.test.*`, `**/*.spec.*`, `test/**`).

| Rule | Applies to | Fails when |
|---|---|---|
| `deleted_test_file` | test files | a test file is deleted (status `:deleted`) and not renamed |
| `skip_added` | test files | an added line contains (TS/JS) `.skip(`, `.only(`, `xit(`, `xdescribe(`, `it.todo(`, `test.todo(`; (Elixir) `@tag :skip`, `@moduletag :skip`, `@tag skip:` |
| `assertions_removed` | test files | removed-line count of assertion tokens exceeds the added-line count in the same file. Tokens: TS/JS `expect(`, `assert.`, `assert(`; Elixir `assert `, `assert(`, `refute `, `refute(`, `assert_receive`, `assert_raise` |
| `suppression_added` | all changed files except Markdown and text files (`*.md`, `*.markdown`, `*.txt`, `*.rst`) | an added line contains `eslint-disable`, `biome-ignore`, `@ts-ignore`, `@ts-expect-error`, `@ts-nocheck`, `# credo:disable`, `@dialyzer {:nowarn` |
| `test_config_changed` | files named `vitest.config.*`, `jest.config.*`, `.eslintrc*`, `eslint.config.*`, `biome.json`, `.credo.exs`, `mix.exs` (only the `test_coverage`/`preferred_cli_env` lines) | never fails; adds a `warning` entry for Astra |

Paths listed in the repo profile's `test_integrity.exempt` (path prefixes; a trailing `/` means a directory) are skipped by every rule. Si's own profile (T05.10) exempts its rule definitions and fixtures, which contain these tokens on purpose.

Result: `:fail` if any failing rule matched; details `%{"findings" => [%{"rule", "file", "line", "text"}], "warnings" => [...]}` (at most 50 findings; `text` trimmed to 200 bytes).

### Tests
One fixture diff per rule that triggers it; an exempt path and a Markdown file produce no findings; a normal change (renaming a test and keeping its assertions, reformatting assertions across lines) produces no findings; counting is per file; binary files are ignored.

### Acceptance criteria
Tests pass; `bin/ci` passes; no false positives on this repository's own history (run the check against the last 20 commits of Si's repo as a smoke test and inspect the output manually).

**Expected result.**
- `Si.Checks.TestIntegrity` applies the five rules to the diff alone and runs no commands. The rules catch deleted tests, added skips, removed assertions and new suppressions, and warn about changed test configuration.
- Findings are capped at 50, with text trimmed to 200 bytes.
- Paths listed in the profile's `test_integrity.exempt` are skipped.
- Markdown and text files never trigger `suppression_added`.

**Checks**
1. Run the check over each of the last 20 commits of this repository (acceptance) and list the findings in the completion note.
   Expected: no findings, apart from paths that Si's profile will exempt (T05.10).
2. A diff that only rewraps `assert x == 1` across two lines.
   Expected: no `assertions_removed` finding.
3. A diff that adds `@tag :skip` inside an exempt path, and one that adds `eslint-disable` to a `.md` file.
   Expected: no findings for either.
4. A diff with 60 matching lines.
   Expected: exactly 50 findings, and each `text` is at most 200 bytes.

**Redo if**
- Rules other than `suppression_added` also look at non-test files. Rewrite the file filter.
- The check runs any command. It must be pure analysis of the diff.
