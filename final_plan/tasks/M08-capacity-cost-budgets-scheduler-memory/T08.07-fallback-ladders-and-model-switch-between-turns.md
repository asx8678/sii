### Goal
When a pool stays saturated, move the next step (or the next turn of an idle session) one rung down a per-role model ladder, never breaking the reviewer-diversity rule.

### Deliverables
- Settings `models.ladders` (map role → list of models) and `scheduler.fallback_after_s` (default 120); `lib/si/models/fallback.ex`; tests.

### Specification
- A request waiting longer than `fallback_after_s` for a session in the `idle` or `starting` state triggers a fallback decision: the next model in the role's ladder whose pool has capacity and which keeps `Si.Models.diversity(writer, reviewer)` at `other_family` (for a builder, check against the task's Astra model; for Astra, against the writer).
- Idle session → `Si.Sessions.control(id, :set_model, %{provider, model})` (RPC `set_model`); starting session → restart with the fallback model. Running turns are never switched.
- Events `model.fallback` (`from`, `to`, `reason`) and a ledger entry.

### Tests
Ladder selection with capacity and diversity constraints; a running session is not switched; an idle one is (fake Pi records `set_model`).

### Acceptance criteria
Tests pass; `bin/ci` passes.

**Expected result.**
- A request that waits longer than `fallback_after_s` moves an idle or starting session one rung down its role's ladder.
- This never breaks reviewer diversity, and running turns are never switched.

**Checks**
1. A ladder whose next rung shares the reviewer's family.
   Expected: that rung is skipped, and the next one with `other_family` is chosen.
2. A running session.
   Expected: no `set_model` is sent.
3. An idle session.
   Expected: the fake Pi records `set_model`, and a `model.fallback` event is written.

**Redo if**
- Fallback switches the model in the middle of a turn. Rewrite it to act only on idle or starting sessions.
