### Goal
Keep provider prompt caches hot the way pi-fabric-pair intended: long retention where supported, one cache identity per session, requests routed to the same replica, and cache use measured on every call.

### Context
Pi facts (0.87.1): `PI_CACHE_RETENTION=long` enables extended provider caching where supported (`docs/environment-variables.md`); OpenAI-style requests use `prompt_cache_key` tied to the session and `prompt_cache_retention: "24h"` (or `prompt_cache_options.ttl: "30m"` on GPT-5.6+) under long retention; session-affinity headers are sent by default only for OpenRouter (`x-session-id`); the `openai` affinity format sends `session_id`, `x-client-request-id` and `x-session-affinity` (`packages/ai/src/types.ts`). Pair's cache warming is inert on Pi 0.87.1 (Pair F-31: the API it used is absent), so Si does not warm caches.

### Deliverables
- Settings `cache.retention` (`long | short | none`, default `long`) and `cache.affinity` (list of `{match: {provider, models?}, header: "x-session-affinity"}` for providers where Pi does not send affinity itself, typically your vLLM or SGLang router).
- Bridge: a `before_provider_headers` handler that adds the configured header with the session id (`SI_CACHE_AFFINITY_HEADER` env set by Si per session from the matching rule; no header when no rule matches).
- `lib/si/cache.ex` (`Si.Cache`): cache share per call, session, model and provider; the cockpit sessions list shows each session's cache share.
- Tests (Elixir and vitest).

### Specification
- `Si.Sessions.start/1` sets `PI_CACHE_RETENTION` from `cache.retention` (T03.07 already reads the setting; this task adds the setting, its schema and tests) and `SI_CACHE_AFFINITY_HEADER` when a `cache.affinity` rule matches the session's provider/model.
- Bridge handler: `pi.on("before_provider_headers", (event) => { if (header) event.headers[header] = sessionId; })`. It never overrides a header Pi already set.
- `Si.Cache.share(filters)` = `cache_read_tokens / (input_tokens + cache_read_tokens)` over `model_calls`; `warm_share` excludes each session's first call.
- Stable prefixes: role prompts and lesson files are fixed per session (T05.04, T14.03), and tool-set changes are limited to Astra's fix mode. The guide lists what breaks a cache (changing the system prompt, tools or model mid-session).
- The `cache_drop` signal (T12.01) uses `Si.Cache`.

### Tests
Env and header set per settings and rules; the bridge adds the header only when configured and never overwrites; share computations on fixtures; a contract check with si-faux that the configured header reaches the provider call (inspect the headers in the faux provider's request options if exposed, otherwise assert the handler ran).

**Expected result.**
- Sessions start with `PI_CACHE_RETENTION` taken from the settings.
- The bridge adds a configured affinity header only when a rule matches, and never overwrites a header Pi already set.
- The cache share is measured per call, session, model and provider, and shown in the cockpit.

**Checks**
1. No matching rule.
   Expected: no header is added (vitest).
2. A header that Pi already set.
   Expected: unchanged.
3. `Si.Cache.share/1` and `warm_share` on the fixtures.
   Expected: exact values; `warm_share` leaves out each session's first call.

**Redo if**
- The header is added to every provider by default. Restrict it to the configured rules.
