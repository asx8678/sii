### Goal
Run several tasks at once, with worker capacity from memory, all model calls through the scheduler, and landing still serialized by the merge queue.

### Deliverables
- Dispatcher capacity = `Si.Memory.max_workers/0` (bounded by `workers.max`), check pool size `max(2, workers)`; an end-to-end test `test/si/parallel_e2e_test.exs` (`@tag :pi`, `@tag :slow`).

### Specification
- The dispatcher starts up to the capacity; each builder session's calls go through the scheduler; review sessions have priority `review`.
- The check pool grows to the new size on demand.

### Tests
Three independent tasks with faux builders and a faux Astra, a pool with `concurrency: 2` for the faux provider: all three land; the scheduler snapshot shows waits; the integration branch has three new commits in queue order.

### Acceptance criteria
Tests pass with `--include pi --include slow`; `bin/ci` passes.

### Verify
```bash
mix test test/si/parallel_e2e_test.exs --include pi --include slow
```

Any other result means the task is not done: fix the cause in the code (never by changing what a test expects), or rewrite the part named under **Redo if**, then run `bin/task-check` and every check below again from the top. The limits on fix attempts, how to redo a task, and the evidence the completion note needs are in [10-after-each-task](../../10-after-each-task.md).

**Expected result.**
- Several tasks run at once, up to `min(workers.max, Si.Memory.max_workers())`.
- Every model call goes through the scheduler.
- Landing is still serialized by the merge queue.

**Checks**
1. `mix test test/si/parallel_e2e_test.exs --include pi --include slow`, run twice.
   Expected: all three tasks land both times, the scheduler snapshot shows waits, and there are three new commits in queue order.
2. `pgrep -fl 'si_test_home_'` afterwards.
   Expected: no process.

**Redo if**
- Tasks land out of queue order, or two landings overlap. The queue is not serialized: fix the queue process.
