### Goal
One scheduler for every model call: pools per provider account and GPU server, priorities, concurrency that adapts to 429s (AIMD), and holds for pauses and budgets.

### Context
`01-architecture.md` §5.3; settings `scheduler.pools`.

### Deliverables
- `lib/si/scheduler.ex` (`Si.Scheduler`), `lib/si/scheduler/pool.ex` (pure pool state); tests `test/si/scheduler_test.exs`, `test/si/scheduler/pool_property_test.exs` (PropCheck).

### Specification
Pool config: `%{id, kind: :provider | :gpu, match: %{provider, models: [glob]}, concurrency (max), tokens_per_min (optional), gpu_rate_usd_per_s}`; calls matching no pool go to an implicit pool per provider with `scheduler.default_concurrency` (default 4; add to settings).
```elixir
@spec request(map(), (map() -> any())) :: :ok
#   request: %{session_id, run_id, task_id, provider, model, priority, request_bytes}; the reply fun is called with %{grant: true, slot_id} when granted
@spec release(String.t(), %{status: integer(), latency_ms: integer(), retry_after_s: number() | nil}) :: :ok
@spec hold({:session | :task | :run | :all, String.t() | :all}, atom()) :: :ok      # reason
@spec unhold({atom(), String.t() | :all}, atom()) :: :ok
@spec snapshot() :: map()      # pools with in_flight, current concurrency, queue lengths (for the cockpit)
```
- Grant when the pool's `in_flight < current_concurrency`, the token bucket allows `request_bytes / 4` tokens (when `tokens_per_min` is set), the pool is not in a Retry-After pause, and no hold matches the request.
- Queue order: priority `you` > `review` > `lead` > `builder` > `background`, FIFO within a priority.
- AIMD: status 429, 503 or 529 → `current_concurrency = max(1, div(current, 2))`, and if `retry_after_s` is given pause the pool until then; 10 consecutive successes → `+1` up to the configured max. Every change: event `scheduler.pool_adjusted`.
- A granted slot not released within 15 minutes is reclaimed with a warning.

### Tests
Unit: grant/queue/release; priority ordering; AIMD halving and recovery; Retry-After pause; holds.
PropCheck: random sequences of requests, releases (with random statuses), holds and unholds; invariants: `in_flight ≤ current_concurrency ≤ max`; `current ≥ 1`; a held request is never granted; when a higher-priority request is waiting in a pool, no lower-priority request in that pool is granted before it.

**Expected result.**
- One scheduler for every model call:
  - pools per provider account and per GPU server;
  - an order of priorities;
  - an optional token bucket;
  - AIMD on 429, 503 and 529, with Retry-After pauses;
  - holds;
  - reclaiming of slots after 15 minutes.

**Checks**
1. The PropCheck property with at least 1,000 cases.
   Expected: no counterexample. `in_flight ≤ current ≤ max`, current is at least 1, a held request is never granted, and priority order holds.
2. Three 429s in a row on a pool with concurrency 8.
   Expected: 8, then 4, 2, 1; then 10 successes raise it by 1. There is one `scheduler.pool_adjusted` event per change.
3. The 15-minute reclaim, with an injected clock.
   Expected: the slot is released with a warning.

**Redo if**
- Grants are decided by polling on a timer instead of on request, release and unhold. Rewrite it to be event-driven.
