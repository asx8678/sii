### Goal
Change role prompts only when the eval harness shows the new version is at least as good.

### Deliverables
CLI `si prompts list`, `si prompts try <role>/<name> --file <candidate.md> --suite <suite> [--repeat N]`, `si prompts promote <role>/<name> --file <candidate.md> --eval <evr_id>`; per-run prompt overrides in the eval runner; tests with a faux suite.

### Specification
- `list`: every prompt with version, hash and usage counts (reviews/attempts that recorded its hash).
- `try`: runs the suite twice (current vs candidate prompt, candidate injected as an override for that eval run only) and prints the comparison of all targets with CIs.
- `promote`: allowed only when no target got worse beyond its CI in the referenced comparison; writes the candidate into `priv/prompts/<role>/<name>.md` with `version + 1` on a new `task/`-style branch for review (never directly on `main`).

### Tests
Override applied only within the eval run; promote refused when a target regressed; version increment.

### Acceptance criteria
Tests pass; `bin/ci` passes.

**Expected result.**
- Prompt changes are gated by the eval harness.
- `si prompts try` compares the current prompt with a candidate through per-run overrides.
- `promote` writes version + 1 on a task branch for review, and only when no target got worse.

**Checks**
1. An override during `try`.
   Expected: used only inside that eval run; other sessions still record the current prompt's hash.
2. A comparison where one target regressed beyond its confidence interval.
   Expected: `promote` is refused.
3. `promote`.
   Expected: a new `task/…`-style branch that changes only the prompt file, with version + 1. Nothing is committed to `main`.

**Redo if**
- `promote` writes to `main`. Rewrite it to create a branch.
