### Goal
Record every code-mode failure and every blocking review finding with a fingerprint that groups repeats, and link failures to the success that followed.

### Deliverables
Migration `create_failures` (`id`, `source` (`fabric_exec|finding`), `session_id`, `task_id`, `model`, `family`, `fingerprint`, `stage_or_category`, `detail`, `resolved_by` (failure or event id, nullable), timestamps); `lib/si/learning.ex`; tests.

### Specification
- `fabric_exec` failures: fingerprint = sha256 of `stage | error_class | normalized message` (lowercase; paths, numbers, quoted identifiers and hex ids removed), first 16 hex; `detail` includes the first failing operation name when present.
- Blocking findings: the finding fingerprint (T05.02); `family` of the writer.
- Resolution: the next successful `fabric_exec` in the same session within 5 turns (for code-mode failures); the round in which the finding became `fixed` (for findings).

### Tests
Normalization examples (two messages differing only in paths/numbers share a fingerprint); resolution linking.

### Acceptance criteria
Tests pass; `bin/ci` passes.

**Expected result.**
- Code-mode failures and blocking findings are recorded, with fingerprints that group repeats.
- Each is linked to the success or fix that resolved it.

**Checks**
1. Two messages that differ only in paths, numbers, quoted identifiers and hex ids.
   Expected: the same fingerprint.
2. A failure followed by a successful `fabric_exec` within 5 turns in the same session.
   Expected: `resolved_by` is set.

**Redo if**
- Normalization depends on message positions or includes absolute paths. Rewrite it.
