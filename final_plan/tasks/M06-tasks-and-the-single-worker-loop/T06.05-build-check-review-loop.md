### Goal
One process per task drives the rounds: freeze the worker's result, run the checks, have Astra review, and route feedback to the writer or to Astra's fix mode until the task is approved or escalated.

### Context
`01-architecture.md` §5.2; review policy (T05.08); rounds and escalation (T05.07).

### Deliverables
- `lib/si/tasks/loop.ex` (`Si.Tasks.Loop`, one `:gen_statem` per task under the loop supervisor), `priv/prompts/builder/feedback.md`; tests `test/si/tasks/loop_test.exs` (`@tag :pi`).

### Specification
The loop reaches the merge queue through `Application.get_env(:si, :merge_queue, Si.MergeQueue)`. `Si.MergeQueue` arrives in T06.06, which depends on this task, so this task's tests configure a fake that records `enqueue/2` and answers with `{:landed, sha}` or `{:ejected, reason, feedback}`.

States: `:working` (worker active), `:checking`, `:reviewing`, `:fixing` (Astra fix), `:waiting` (escalated or blocked), `:done`.
1. `{:attempt_reported, ...}` with status done while `:working`: transition task `running → frozen`; `Si.Evidence.freeze(worktree, base: task base, task_id, attempt_id)`; store `snapshot_id` on the task; `:checking`. If the freeze fails (a file changed during capture, a git error), wait for a 2 s quiet period and retry, up to 3 times; then create an inbox item and wait. Never stop the worker and never discard its work because of a capture problem (Pair F-15).
   Cost cap (until M08's budgets take over): after each round, sum `get_session_stats` `cost` over the task's sessions; above `tasks.max_cost_usd` (default 3.0) abort the worker's turn, move the task to `escalated`, and create an inbox item with options `raise` / `cancel`.
2. Checks: `Si.Checks.run_all(snapshot, tier: task.tier, task: %{scope, approved_scope, test_paths, tier})`.
   - Fail → feedback text (see below); `Si.Tasks.set_feedback/2`; `next_round/1`; transition `frozen → running`; `Si.Sessions.prompt(worker, feedback, as: :follow_up)`; `:working`.
   - Pass → transition `frozen → in_review`; `:reviewing`.
3. Review: the task's review thread (create on first use: `subject_kind: "task"`, `task_id`, `title`, `description` = task description + acceptance list, `writer_model` = the worker's model, `fix_policy` = settings, `max_rounds` = settings for the tier). `Si.Review.Runner.run_round/4` with the task text as the purpose.
   - Approve → `in_review → approved → queued` and `Si.MergeQueue.enqueue/2` (T06.06); `:done` when landed (the queue reports back).
   - Revise → `Si.Review.Policy.decide/3`:
     - `:writer` → feedback from the findings; `next_round`; `in_review → running`; follow-up to the worker; `:working`.
     - `{:astra, ids}` → `:fixing`: `Si.Review.Fix.run/3`; on approval of the fix: reset the worker's worktree to the fixed snapshot commit with `Si.Worktrees.reset/2`, keeping the worktree's `base_sha` as the task base (freeze always writes the full tree with an explicit base, so the position of HEAD does not matter), tell the worker `Astra fixed: <summary>. Your working tree now includes her changes.`, set the task snapshot to the fixed snapshot, `approved → queued`.
     - `:escalate` → `in_review → escalated`; inbox item (already created by the thread manager); `:waiting`.
4. Queue ejection (`{:ejected, reason, feedback}` from T06.06) → `queued → running`, next round, follow-up to the worker with the feedback, `:working`.
5. Cancellation (`{:task, id, :cancelled}`) → stop the worker and Astra sessions; `:done`.

Feedback (`priv/prompts/builder/feedback.md`, version 1, a template filled by `Si.Tasks.Feedback.render/2`):
```
Round <n> did not pass. <cause>

<details>

Fix this, run the tests again, then call si_report.
```
- Check failure: cause `The <check> check failed.`; details: the check's details summary (integrity findings, coverage uncovered lines, scope files, mutation survivors) and the last 40 lines of its log.
- Revise: cause `Astra asked for changes.`; details: each blocking finding (`file:line`, problem, evidence, suggested fix) and the notes (marked optional).

### Tests
(`@tag :pi`, fixture repo, si-faux builder and Astra scripts)
- Happy path: report → checks pass → approve → enqueued.
- Failing test: first report fails `tests` → the worker receives feedback containing the log tail → second report passes → approve.
- Revise with `fix: writer` → feedback with findings → second round approve.
- Revise with `fix: auto` and a small finding → Astra fixes → fix reviewer approves → the worker's worktree contains the fixed file → enqueued.
- Escalation after `max_rounds`.

### Acceptance criteria
Tests pass with `--include pi`; `bin/ci` passes.

### After implementing

Do this after the Verify commands pass. Run `bin/task-check` first, then these checks. Each check states the result you must see. Any other result means the task is not done: fix the cause in the code (never by changing what a test expects), or rewrite the part named under **Redo if**, then run `bin/task-check` and every check below again from the top. The limits on fix attempts, how to redo a task, and the evidence the completion note needs are in [10-after-each-task](../../10-after-each-task.md).

**Expected result.**
- One `:gen_statem` per task drives the rounds:
  1. freeze, retrying on capture problems and never discarding the worker's work;
  2. checks;
  3. Astra's review;
  4. feedback to the writer, or Astra's fix mode;
  5. the merge queue.
- The interim cost cap escalates the task.
- Cancellation stops the task's sessions.

**Checks**
1. `mix test test/si/tasks/loop_test.exs --include pi --repeat-until-failure 3`.
   Expected: every run passes.
2. The feedback text for a failed `tests` check.
   Expected: it follows `priv/prompts/builder/feedback.md` and contains the last 40 lines of the log.
3. A freeze that fails three times (a test hook).
   Expected: an inbox item; the worker session is still alive, and its worktree is untouched.
4. `tasks.max_cost_usd: 0.0001` with a faux usage cost.
   Expected: the worker's turn is aborted, the task is `escalated`, and an inbox item offers `raise` and `cancel`.
5. The loop's states.
   Expected: exactly `working, checking, reviewing, fixing, waiting, done`.

**Redo if**
- The loop stops the worker or resets its worktree after a failed freeze. Rewrite it: capture problems never cost the worker's work.
