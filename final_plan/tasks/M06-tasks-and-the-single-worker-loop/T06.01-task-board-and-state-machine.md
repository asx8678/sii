### Goal
Durable tasks with a strict state machine, optimistic locking, attempts and rounds, and dependency promotion.

### Context
`03-data-model.md` (`tasks`, `attempts`, `scope_requests`; §3.2 task state machine).

### Deliverables
- Migrations `create_tasks`, `create_attempts`, `create_scope_requests` (add a `feedback` text column to `tasks` for the last round's feedback, and `report_round` integer to `attempts`).
- `lib/si/tasks.ex` (`Si.Tasks`), `lib/si/tasks/task.ex`, `lib/si/tasks/attempt.ex`, `lib/si/tasks/state_machine.ex`.
- Tests `test/si/tasks_test.exs`, `test/si/tasks/state_machine_property_test.exs` (PropCheck).

### Specification
```elixir
@spec create(map()) :: {:ok, Task.t()} | {:error, Ecto.Changeset.t()}      # status ready if depends_on is empty or all landed, else pending
@spec get(String.t()) :: Task.t() | nil
@spec list(keyword()) :: [Task.t()]                                          # status, repo_id, run_id
@spec transition(Task.t(), atom(), String.t(), map()) :: {:ok, Task.t()} | {:error, {:invalid_transition, atom(), atom()} | :stale}
@spec assign(Task.t(), String.t(), String.t()) :: {:ok, Task.t()} | {:error, term()}          # session_id, worktree_id: ready → assigned
@spec start_attempt(Task.t(), String.t()) :: {:ok, Attempt.t()}              # n = attempt_count + 1; assigned → running
@spec record_report(Attempt.t(), map(), non_neg_integer()) :: {:ok, :recorded | :already_reported, Attempt.t()}   # latched once per (attempt, round)
@spec interrupt(Attempt.t(), String.t()) :: {:ok, Attempt.t()}
@spec promote_dependents(Task.t()) :: [Task.t()]                             # after a task lands: pending tasks whose deps are all landed → ready
@spec set_feedback(Task.t(), String.t() | nil) :: {:ok, Task.t()}
@spec next_round(Task.t()) :: {:ok, Task.t()}                                # round + 1
```
- `Si.Tasks.StateMachine.allowed?(from, to)` implements exactly `03-data-model.md` §3.2.
- `run_id` is a plain string column without a foreign key, because the `runs` table only arrives in M09 (SQLite cannot add the constraint later without rebuilding the table).
- `transition/4` uses `Ecto.Changeset.optimistic_lock(:lock_version)`; a stale struct → `{:error, :stale}`. Writes event `task.transitioned` (`from`, `to`, `reason`) and broadcasts `{:task, id, to}` on `"tasks"` and `"task:<id>"`.
- `record_report/3`: if `attempt.report_round == round` → `{:ok, :already_reported, attempt}`; else store the report, `report_round`, `reported_at`, status `reported`; event `attempt.reported`.

### Tests
Unit: every allowed and a sample of disallowed transitions; stale update; dependency promotion (A, B → C: C becomes ready only after both land); report latch per round.
PropCheck stateful test: commands `create`, `assign`, `start_attempt`, `report`, `transition(random target)`, `land`; invariants: the stored status always follows the state machine; `attempt_count` equals the number of attempts; a pending task never becomes assigned.

**Expected result.**
- Tasks, attempts and scope requests are stored, and a state machine allows exactly the transitions in `03-data-model.md` §3.2.
- Updates use optimistic locking.
- Reports are latched once per round.
- Dependents are promoted when all their dependencies have landed.

**Checks**
1. Compare `Si.Tasks.StateMachine.allowed?/2` with §3.2: enumerate every pair of states.
   Expected: `true` exactly for the pairs in §3.2.
2. Run the PropCheck property with at least 500 cases, for example `numtests: 500` in a local run.
   Expected: no counterexample.
3. Two processes transition the same task from the same struct.
   Expected: one gets `{:ok, _}`, the other `{:error, :stale}`.
4. A report arrives twice in the same round.
   Expected: `{:ok, :already_reported, _}` the second time.

**Redo if**
