### Goal
Add tasks and talk to sessions from the browser: create, cancel and retry tasks; send follow-ups and steers; abort and stop sessions.

### Deliverables
- "New task" form on `SiWeb.TasksLive`; actions on `SiWeb.TaskLive`; a message box and action buttons on `SiWeb.SessionLive`; tests.

### Specification
- New task: repository, title, description, scope globs (one per line), test paths, acceptance criteria (one per line), tier, priority → `Si.Tasks.create/1`; redirect to the task page.
- Task actions: Cancel (any active state), Retry (from `failed` or `escalated` → `ready`), links to the review thread and sessions.
- Session page: a text box with Follow-up, Steer and Next turn buttons (shown only when the session's mode allows them: Si sessions and your sessions in `control` mode get all three, `suggest` mode only Next turn), plus Abort and Stop. Actions call `Si.Sessions.prompt/3` or `Si.Sessions.control/4`; the result (ack or error) is shown inline.

### Tests
Form validation and creation; cancel and retry transitions; each message button calls the right API with the right `as`/action (fake sessions); buttons hidden per mode.

### Acceptance criteria
Tests pass; `bin/ci` passes.

### Verify
```bash
mix test test/si_web/live/tasks_live_test.exs test/si_web/live/session_live_test.exs
```

**Expected result.**
- Tasks can be created, cancelled and retried from the browser.
- The session page has Follow-up, Steer and Next-turn buttons (as the mode allows), plus Abort and Stop, and shows each result inline.

**Checks**
1. A user session in `suggest` mode.
   Expected: only the Next-turn button is shown.
2. Each button, with fake sessions.
   Expected: it calls `Si.Sessions.prompt/3` with the right `as:`, or `Si.Sessions.control/4` with the right action.
3. Retry on a `failed` task.
   Expected: status `ready`.

**Redo if**
- Buttons are only hidden in the template, and the server does not check the mode. Add the check on the server side too.
