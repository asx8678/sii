### Goal
Create, reset and remove git worktrees for workers, Astra, checks and the merge queue, with build caches cloned copy-on-write so a new worktree doesn't compile from scratch.

### Context
`02-repo-layout.md` §5 (locations), `03-data-model.md` §2 (`worktrees`).

### Deliverables
- Migration `create_worktrees`; `lib/si/worktrees.ex` (`Si.Worktrees`), `lib/si/worktrees/worktree.ex`, `lib/si/worktrees/cow.ex` (`Si.Worktrees.Cow`).
- Tests `test/si/worktrees_test.exs`, `test/si/worktrees/cow_test.exs`.

### Specification
```elixir
@type purpose :: :worker | :astra | :check | :queue | :eval | :warm
@spec create(Si.Repos.Repo.t(), keyword()) :: {:ok, Worktree.t()} | {:error, term()}
#   opts: ref (commit-ish; default integration branch head), purpose (required), owner, branch (create this branch at ref), path (only for :check/:queue, which use fixed dirs)
@spec reset(Worktree.t(), String.t()) :: :ok | {:error, term()}          # detach at ref, discard changes, keep caches
@spec remove(Worktree.t()) :: :ok | {:error, term()}
@spec get!(String.t()) :: Worktree.t()
@spec list(Si.Repos.Repo.t(), keyword()) :: [Worktree.t()]              # opts: purpose, status
@spec set_owner(Worktree.t(), String.t() | nil) :: {:ok, Worktree.t()}
```
`create/2` (inside `Si.Git.Locks.with_lock(repo.path, ...)`):
1. Insert the row with status `creating` and a new `wt_` id. Path: `Si.Paths.worktree_dir(repo.id, id)` for worker/astra/eval/warm; the caller passes `path` for check slots and the queue.
2. `git worktree add --detach <path> <sha>` (or `-b <branch> <path> <sha>` when `branch` is given; if the branch exists, fail with `{:error, {:branch_exists, name}}`).
3. `Si.Worktrees.Cow.clone_caches(repo.path, path)`.
4. Submodules and LFS: if the worktree has a `.gitmodules` file, run `git submodule update --init --recursive` in it (a failure marks the worktree `broken` with the message, since builds would fail without them); if `.gitattributes` mentions `filter=lfs` and `git lfs` is installed, run `git lfs pull` (Si's git calls disable hooks, so LFS's post-checkout hook does not run by itself). Repo profile options `worktree.submodules` and `worktree.lfs` (`auto` by default, `false` to skip).
5. Status `ready`, `base_sha` = the resolved sha; event `worktree.created`.
6. On any failure: `git worktree remove --force`, delete the dir, delete the row, return the error.

`Si.Worktrees.Cow.clone_caches(from, to)`: for each of `_build`, `deps`, `node_modules` that exists as a directory in `from` and does not exist in `to`: macOS (`:os.type() == {:unix, :darwin}`) → `cp -cR <from>/<dir> <to>/<dir>` (APFS clonefile); Linux → `cp -R --reflink=auto`; other → skip. A failed copy logs a warning and removes the partial target; it never fails the worktree creation. Returns the list of cloned dirs.

`reset/2`: `git -C <path> checkout --detach --force <ref>` then `git -C <path> clean -ffdx -e _build -e deps -e node_modules`.

`remove/1`: status `removing` → `git worktree remove --force <path>`; if that fails because the dir is gone or broken → `rm -rf` + `git worktree prune`; status `removed`, `removed_at`; event `worktree.removed`.

### Tests
- Create detached at a given sha: `git -C path rev-parse HEAD` equals it; status `ready`.
- Create with `branch:` → branch exists and is checked out.
- Cache cloning: in the fixture repo create an ignored `node_modules/pkg/index.js` (add `node_modules/` to `.gitignore`), create a worktree → the file exists in the worktree; on macOS assert the copy used `cp -c` by checking the command log (inject the copy command through a module attribute or `Application` env for testability).
- `reset/2` discards a modified tracked file and an untracked file but keeps `node_modules`.
- `remove/1` deletes the directory and `git worktree list` no longer shows it.
- Five concurrent `create/2` calls on the same repo all succeed (locks work).
- A failing `git worktree add` (e.g. invalid ref) leaves no row and no directory.

**Expected result.**
- Worktrees are created, reset and removed under `$SI_HOME/worktrees/<repo>/<id>`, or at the fixed paths used for check slots and the queue.
- Build caches (`_build`, `deps`, `node_modules`) are cloned copy-on-write.
- Submodules and LFS are handled when present.
- A failure at any step leaves no database row, no directory and no git worktree entry.

**Checks**
1. In a temporary repo with an ignored `node_modules/` of 5,000 small files, create a worker worktree.
   Expected: the files exist in the worktree, and creation takes under 3 s. On macOS the copy command logged by the test is `cp -cR`.
2. After `remove/1`: `git -C <tmp> worktree list`.
   Expected: only the main worktree; the directory is gone.
3. Create a worktree with an invalid ref.
   Expected: an error. `Si.Worktrees.list(repo)` is empty, the directory is absent, and `git worktree list` is unchanged.
4. `reset/2` after modifying a tracked file and adding an untracked one.
   Expected: both changes are gone, and `node_modules` is still there.
5. Real cache test on this repository: with a temporary `SI_HOME`, create a worker worktree of this repository through `mix run`, time it, then remove it.
   Expected:
   - `_build` and `deps` are cloned, and creation takes under 10 s;
   - after the removal, `git worktree list` in this repository shows only the main worktree (plus `~/.si-review/checkout` from T05.10 on).
6. Five concurrent `create/2` calls (from the test).
   Expected: exactly five rows and five worktrees.

**Redo if**
- A failure path leaves a row, a directory or a worktree entry. Rewrite the cleanup in step 6 so that it runs for every failure.
- Caches are copied with plain `cp -R` on macOS. Use `cp -cR`.
