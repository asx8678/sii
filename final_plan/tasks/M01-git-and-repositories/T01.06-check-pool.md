### Goal
Checks never run in a worker's worktree. Each repository has a small pool of check worktrees; a check run leases one, it is reset to the snapshot commit, and it gets its own test partition and port range.

### Context
`03-data-model.md` (`check_slots`), `05-schemas-and-config.md` §2 (`parallel`), settings `checks.pool_size`.

### Deliverables
- Migration `create_check_slots`.
- `lib/si/checks/pool.ex` (`Si.Checks.Pool`, a GenServer per repo), `lib/si/checks/pool_supervisor.ex` (DynamicSupervisor, child of the application), `lib/si/checks/slot.ex` (struct).
- Tests `test/si/checks/pool_test.exs`.

### Specification
```elixir
@spec lease(Si.Repos.Repo.t(), Si.Evidence.Snapshot.t(), keyword()) :: {:ok, Slot.t()} | {:error, :timeout | term()}
#   opts: owner (string), timeout (ms, default 600_000)
@spec release(Slot.t()) :: :ok
@spec ensure_pool(Si.Repos.Repo.t()) :: :ok
```
`%Slot{id, repo_id, index, path, partition, port_base, env, snapshot_id}`.
- Pools are registered in `Si.Registry` under `{:check_pool, repo_id}` and started on first use via `Si.Checks.PoolSupervisor`.
- `ensure_pool/1` creates missing slots `0..pool_size-1`: worktree with `purpose: :check`, `path: Si.Paths.check_slot_dir(repo.id, index)`; row in `check_slots` with `partition = index + 1` and `port_base = ports_start + index * ports_per_slot` (from the repo profile, defaults 4100/10).
- `lease/3`: FIFO queue of waiters inside the pool process. When a slot is idle: mark `leased`, set `lease_owner`, monitor the caller, then (in the caller process, to keep the pool responsive) `Si.Worktrees.reset(worktree, snapshot.commit_sha)`. On reset failure: mark the slot `broken`, recreate its worktree once, retry; if that fails, return the error.
- `env`: the profile's `parallel.env` with `{slot}` → partition and `{port}` → port_base, plus `SI_CHECK_SLOT=<index>`, `SI_PORT_BASE=<port_base>`.
- `release/1`: slot back to `idle`; the next waiter gets it. If the leaseholder process exits, its slot is released automatically.

### Tests
- `ensure_pool/1` with `pool_size: 2` creates two check worktrees and rows.
- `lease/3` returns a slot whose HEAD is the snapshot commit and whose working files equal the snapshot tree.
- With `pool_size: 1`, a second lease waits until the first is released (assert ordering with messages).
- Killing the leaseholder releases the slot.
- `env` placeholders are expanded (`MIX_TEST_PARTITION: "{slot}"` → `"1"`).
- A deliberately corrupted slot (delete its directory) is recreated on the next lease.

**Expected result.**
- Each repository has a pool process with slots `0..pool_size-1`.
- Each slot has its own worktree, test partition and port range.
- Leases are served in FIFO order; the reset to the snapshot runs in the caller; a slot is released automatically when its holder dies.
- A broken slot is recreated.

**Checks**
1. While one lease is resetting a slow worktree, call `:sys.get_state/1` on the pool.
   Expected: it answers within 50 ms. The pool never runs git itself; check the code as well.
2. Slot 0's `env`.
   Expected: `MIX_TEST_PARTITION` = `"1"`, `SI_CHECK_SLOT` = `"0"`, `SI_PORT_BASE` = `"4100"`.
3. Kill the leaseholder while another caller waits.
   Expected: the waiter gets the slot within 1 s.
4. After the test suite, `git worktree list` of the test repositories.
   Expected: no check worktrees are left behind.

**Redo if**
- The pool process resets worktrees or waits on git. Move that work into the calling process.
