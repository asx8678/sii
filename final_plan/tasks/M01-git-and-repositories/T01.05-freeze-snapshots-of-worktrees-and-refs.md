### Goal
Freeze the exact state of a worktree (including uncommitted and untracked files) into a tree SHA and a throwaway commit whose parent is the base, without touching the worktree's own index, HEAD or files. Evidence and approvals bind to these snapshots.

### Context
`01-architecture.md` §5.1 and §5.4; `03-data-model.md` (`snapshots`). Pair's evidence capture copied the whole tree (7.5 s for 25,000 files); this design hashes only changed files.

### Deliverables
- Migration `create_snapshots`; `lib/si/evidence.ex` (`Si.Evidence`), `lib/si/evidence/snapshot.ex`.
- Tests `test/si/evidence_test.exs` (+ a `@tag :slow` performance test).

### Specification
```elixir
@spec freeze(Worktree.t() | Path.t(), keyword()) :: {:ok, Snapshot.t()} | {:error, term()}
#   opts: repo (required when given a path), base (commit sha; default: worktree.base_sha), task_id, attempt_id, force (skip dedupe)
@spec freeze_ref(Si.Repos.Repo.t(), String.t(), String.t()) :: {:ok, Snapshot.t()} | {:error, term()}   # ref, base
@spec get!(String.t()) :: Snapshot.t()
@spec diff(Snapshot.t()) :: {:ok, String.t()}             # git diff <base> <commit>
@spec changed_files(Snapshot.t()) :: {:ok, [String.t()]}
```
`freeze/2` algorithm (run in the worktree directory):
1. `git rev-parse --git-path index` → the worktree's index path (absolute or relative to the worktree; make it absolute).
2. Copy it to a temp file `tmp_index` (if missing, start with an empty temp index). Copying the existing index lets `git add -A` skip unchanged files via stat data, so only changed files are hashed.
3. Exclusions: from `git status --porcelain=v2 -z --untracked-files=all`, `lstat` every untracked path; sockets, FIFOs and device files (git cannot store them), and untracked regular files larger than `evidence.max_file_mb` (default 50), go into a temporary excludes file. Then `GIT_INDEX_FILE=tmp_index git -c core.excludesFile=<tmp excludes> add -A` (respects `.gitignore`; stages deletions). Excluded paths are recorded in the snapshot's `details.excluded` (add a `details` map column to `snapshots`) so a review can mention them (Pair F-15).
4. `GIT_INDEX_FILE=tmp_index git write-tree` → `tree_sha`.
5. Dedupe: if a snapshot with the same `repo_id`, `tree_sha` and `base_sha` exists and `force` is not set, delete the temp index and return it.
6. `git commit-tree <tree_sha> -p <base> -m "si snapshot <snp_id>\n\nSi-Snapshot: <snp_id>"` with `Si.Git.si_identity_env/0` → `commit_sha`.
7. `update_ref(repo, "refs/si/snapshots/<snp_id>", commit_sha, nil)`.
8. Insert the row and event `snapshot.frozen` in one transaction; delete the temp index (always, in an `after` block).

`freeze_ref/3`: `tree_sha = tree_of(ref)`; then steps 5–8 with `source: "ref"`.

Files ignored by `.gitignore` (for example `.env` or generated code) are never part of a snapshot, so checks and reviews never see them. This is by design and is documented in the user guide (Pair F-16).

### Tests
- Uncommitted modification, a new untracked file, and a deleted tracked file are all reflected in the snapshot tree (`git ls-tree -r <tree>`), while an ignored file is not.
- A FIFO (`mkfifo`) and an untracked file above the size limit in the worktree do not break the freeze; both appear in `details.excluded`.
- The worktree's index is untouched: `git diff --cached --name-only` and the SHA-256 of the index file are identical before and after; HEAD is unchanged; the working files are unchanged.
- Snapshot commit's parent is the base; its tree equals `tree_sha`; `refs/si/snapshots/<id>` points to it.
- Freezing twice without changes returns the same snapshot id; with `force: true` returns a new one.
- `freeze_ref/3` tree equals `git rev-parse <ref>^{tree}`.
- `@tag :slow` performance: repo with `many_files!(5000)`, modify 3 files, freeze once to warm up, modify 1 more file, second freeze completes in < 1 s.

**Expected result.**
- `freeze/2` captures a worktree's exact state into a tree SHA and a throwaway commit whose parent is the base. That state includes tracked changes and untracked files, but not ignored files, FIFOs or oversized files.
- It works through a temporary index and never changes the worktree's own index, HEAD or files.
- Snapshots are deduplicated and referenced as `refs/si/snapshots/<id>`.

**Checks**
1. Count your temporary index files in `$TMPDIR` before and after `mix test test/si/evidence_test.exs`.
   Expected: the same count.
2. The "index untouched" test.
   Expected: it compares the SHA-256 of the index file's bytes before and after, not only the output of `git diff --cached`.
3. `mix test test/si/evidence_test.exs --include slow`, run three times.
   Expected: the median time of the second freeze is under 1 s. Record the three times in the completion note.
4. `git -C <tmp> for-each-ref refs/si/snapshots` after several freezes.
   Expected: one ref per snapshot, and each commit's parent is its base.
5. `git -C <tmp> branch --contains <snapshot commit>`.
   Expected: no output. Snapshot commits are on no branch.

**Redo if**
- The implementation copies files to a temporary directory, uses `git stash`, or runs `add -A` or `write-tree` without `GIT_INDEX_FILE`. Rewrite it with the temporary index as specified.
