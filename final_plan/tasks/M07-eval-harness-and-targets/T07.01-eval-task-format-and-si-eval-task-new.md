### Goal
Define eval tasks (a repository state, instructions, and hidden tests the agents never see) and create them from real commits in your repositories.

### Deliverables
- `protocol/eval_task.schema.json`; `lib/si/evals/task_spec.ex` (`Si.Evals.TaskSpec`), `lib/si/evals.ex` (`Si.Evals` facade); migration `create_eval_tasks`.
- CLI `si eval task new`, `si eval sync`; tests `test/si/evals/task_spec_test.exs`.

### Specification
Layout in the Si repository: `evals/<suite>/<name>/task.yml`, `evals/<suite>/<name>/hidden_tests.patch` and `evals/<suite>/<name>/repo.yml` (the repo profile the task uses).
```yaml
name: fovea-impact-base-flag
repo: /Users/adam2/projects/pair/pi-fovea
base_commit: 1a2b3c4          # the parent of the commit the task was made from
instructions: |
  <commit subject and body>
  Hidden tests will check this change.
test_command: npx vitest run test/impact.test.ts
timeout_s: 1800
tier: quick
tags: [typescript]
```
`si eval task new --repo PATH --commit SHA --suite NAME [--name NAME]`:
0. Si never writes to the source repository: it is not registered (so no `si/integration` branch) and no file is written there. The profile comes from the source's `.si/repo.yml` when it has one, else from `Si.RepoProfile.Detect.detect/1` in memory; the profile used is saved as `repo.yml` next to `task.yml`.
1. `base_commit = SHA^`.
2. Hidden tests = the part of `git diff SHA^ SHA` touching files that match the repo profile's `tests.patterns`; save as `hidden_tests.patch`. No test changes → error `commit has no test changes`.
3. `test_command` = the profile's `test` command with `{tests}` = the test files in the patch.
4. Validate in a scratch clone (`git clone --local`): at `base_commit` + hidden tests the tests **fail** (or the files don't compile); at `SHA` they **pass**. Otherwise error with the outputs.
5. Write the files; print the path.
`si eval sync` loads all `evals/**/task.yml` into `eval_tasks` (upsert by suite + name), validating each against the schema.

### Tests
Fixture repository with a history: commit A (base), commit B adding a function and a test. `task new` on B creates the files (including `repo.yml`); validation passes; the source repository's status, branches and refs are unchanged; a commit without tests is rejected; a commit whose tests already pass at the base is rejected.

### Acceptance criteria
Tests pass; `bin/ci` passes.

### Verify


**Expected result.**
- An eval task is a repository state, instructions and a hidden test patch, created from a real commit and validated in a scratch clone: the tests fail at the base and pass at the commit.
- Si never writes into the source repository: it doesn't register it, doesn't create `si/integration` and doesn't write a profile there.
- When the source has no `.si/repo.yml`, the detected profile is saved as `evals/<suite>/<name>/repo.yml`.
- `si eval sync` loads the tasks.

**Checks**
1. Create an eval task from a commit of `/Users/adam2/projects/pair/pi-fovea`. Before and after, run `git -C /Users/adam2/projects/pair/pi-fovea status --porcelain` and `git -C /Users/adam2/projects/pair/pi-fovea for-each-ref refs/heads/si refs/si`.
   Expected: identical output, and no `.si/` directory created there.
2. A commit without test changes, and a commit whose tests already pass at the base.
   Expected: `commit has no test changes`, and a validation error that shows the outputs.
3. `bin/si eval sync`, then the `eval_tasks` count.
   Expected: every `task.yml` loaded, and running it twice changes nothing (upsert).

**Redo if**
- Any code path calls `Si.Repos.add/1` or `si repo init` on the source repository. Rewrite it to read only and detect in memory.
