### Goal
Cheap, rule-based warning signs computed from the bridge's events, recorded with their evidence.

### Deliverables
- Migration `create_signals` (`id`, `session_id`, `task_id`, `run_id`, `kind`, `severity` (`info|warn|critical`), `data`, `status` (`open|handled|ignored`), timestamps); `lib/si/signals.ex` (engine subscribing to `"session:*"` analytics broadcasts), `lib/si/signals/rule.ex` (behaviour), rules under `lib/si/signals/rules/`; tests with synthetic event streams.

### Specification
Rule behaviour: `name/0`, `init/1` (per session state), `handle_event(event, state) :: {[signal_attrs], state}`.
Rules:

| Kind | Fires when | Severity |
|---|---|---|
| `repeated_error` | the same tool error (normalized: lowercase, paths and numbers removed) three times in a row | warn |
| `tests_failing_repeatedly` | a test command (matching the profile's `test`/`test_all` prefix) exits non-zero in three consecutive turns | warn |
| `fabric_failure_repeat` | the same `fabric_exec` failure (stage + error class) three times within 10 turns | warn |
| `cost_spike` | one turn costs more than 5× the session's median turn cost and more than $0.20 | info |
| `no_diff_progress` | 8 consecutive turns without an `edit`/`write` tool call while the task is running | warn |
| `claimed_done_without_tests` | `si_report` done in a round in which no test command ran | warn |
| `context_pressure` | context usage above 85% of the window | info |
| `cache_drop` | after 5 warm calls, a session's cached-input share falls below half of its running average for 3 calls in a row (usually a changed prompt prefix or a lost replica affinity) | info |

- Dedupe: the same kind for the same session does not fire again within 5 turns.
- Each signal: row + event `signal.raised` + broadcast `{:signal, signal}` on `"signals"` and `"task:<id>"`.

### Tests
One synthetic stream per rule (fires exactly once), plus a stream that must not fire (near misses), and the dedupe window.

### Acceptance criteria
Tests pass; `bin/ci` passes.

### Verify
```bash
mix test test/si/signals_test.exs
```

### After implementing

Any other result means the task is not done: fix the cause in the code (never by changing what a test expects), or rewrite the part named under **Redo if**, then run `bin/task-check` and every check below again from the top. The limits on fix attempts, how to redo a task, and the evidence the completion note needs are in [10-after-each-task](../../10-after-each-task.md).

**Expected result.** Eight deterministic rules raise signals from session events, with evidence. Repeats are suppressed within 5 turns. Each signal is stored, recorded as an event and broadcast.

**Checks**
1. One synthetic stream per rule.
   Expected: exactly one signal each.
2. The near-miss streams (for example, two repeated errors instead of three).
   Expected: no signal.
3. The same rule firing again within 5 turns.
   Expected: no second signal.

**Redo if**
- Rules keep state in the database, or read events back for every event. Rewrite them with per-session state in the engine.
