### Goal
Cheap typed judgments about a builder's progress, using Fabric Foreman's ten questions, through Jev (TypeSafe) or a local judge model.

### Context
`/Users/adam2/projects/pair/pi-fabric/docs/foreman.md` (the ten questions: implementation, tests, requirements, verification, readiness, progress, stuck, off-track, instruction drift, human need) and `docs/jev.md` + `src/jev/client.ts` (request and response shape for Jev, endpoint `https://api.typesafe.ai/v1/systemone`).

### Deliverables
- Add `req_llm ~> 1.25`; `lib/si/jev.ex` (`Si.Jev` client), `lib/si/judgments.ex` (`Si.Judgments`); settings `models.judge` (`provider: jev | local`, `local_model`), `judgments.every_turns` (default 5), API key from env `TYPESAFE_API_KEY`; tests with `Req.Test` stubs.

### Specification
- `Si.Judgments.assess(session_id)`: runs on `agent_settled` for builder sessions when an open `warn` signal exists for the session or every `every_turns` settled turns.
- Input projection (bounded to 4,000 characters): the task title and acceptance criteria, the last 10 tool calls (name, files, exit code, ok), the last assistant message preview (first 500 characters, taken from the Pi session file via the pointer), the open signals.
- Output: for each of the ten questions `{answer: "yes" | "no" | "unclear", confidence: 0..1, reason}`; validated; stored in the signal's `data` or as a new signal:
  - `stuck` yes (confidence ≥ 0.7) → signal `stuck` (warn);
  - `off_track` or `instruction_drift` yes (≥ 0.7) → `drifting` (warn);
  - `readiness` no while the worker just reported done → `claimed_done_without_evidence` (warn);
  - `human_need` yes (≥ 0.7) → `needs_owner` (critical).
- Jev: mirror Fabric's client request shape; local: `ReqLLM.generate_object` (or equivalent) with a JSON Schema for the ten answers.
- Cost: recorded as a `model_calls` row for a synthetic session `role: "judge"` so budgets count it as supervision.
- Credentials for Si's own model calls (this task first, then the Lead in T12.04 and lessons in T14.02): ReqLLM reads each provider's standard environment variable (for example `OPENAI_API_KEY`, `OPENROUTER_API_KEY`), and Jev reads `TYPESAFE_API_KEY`. `bin/si-server` and the service unit (T11.12) load them from `$SI_HOME/env` (mode 0600, `KEY=value` lines) when that file exists. `si doctor` reports which configured providers have a key, without printing any key.
