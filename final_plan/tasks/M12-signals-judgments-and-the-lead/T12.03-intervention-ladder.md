### Goal
React to signals with the lightest action that works (note, hint, steer, reassign, you), with hard limits and a check of whether each intervention helped.

### Deliverables
- Migration `create_interventions`; `lib/si/interventions.ex`; hint templates `priv/prompts/hints/<kind>.md`; tests including a property test for limits.

### Specification
| Signal kind | First rung |
|---|---|
| `cost_spike`, `context_pressure` | note (for `context_pressure`, a `compact` control when the session is idle) |
| `repeated_error`, `tests_failing_repeatedly`, `fabric_failure_repeat`, `claimed_done_without_tests`, `claimed_done_without_evidence` | hint |
| `stuck`, `drifting`, `no_diff_progress` | hint, then Lead (steer or reassign) if the hint did not help |
| `needs_owner` | you (inbox) |
- Limits: hint 1 per signal kind per task round; steer 2 per task; reassign 1 per task (then you). When the supervision budget (T08.02) is exhausted, skip the Lead and go to you.
- Delivery: hint = follow-up at the next safe moment; steer = RPC `steer` during the turn.
- Measurement: after an intervention, watch the next 3 turns; `helped` when the condition clears (e.g. a test command ran and passed, the error stopped repeating, a file was edited), `not_helped` otherwise; store on the intervention; aggregate per kind in the scoreboard.
- Hint text example (`claimed_done_without_tests.md`): `You reported done, but no test command ran in this round. Run <test command> first, then call si_report again.`

### Tests
Rung selection; limits (PropCheck: random signal sequences never exceed limits); outcome measurement on synthetic streams; budget exhaustion routes to the inbox.

### Acceptance criteria
Tests pass; `bin/ci` passes.

**Expected result.**
- Signals lead to the lightest action on the ladder, within hard limits.
- Hints are delivered at safe moments.
- Outcomes are measured over the next 3 turns.
- When the supervision budget is used up, decisions go to the owner.

**Checks**
1. The PropCheck property on random signal sequences.
   Expected: no more than 1 hint per kind per round, 2 steers and 1 reassign per task.
2. A `claimed_done_without_tests` hint, followed by a test run that passes.
   Expected: the intervention is marked `helped`.
3. An exhausted supervision budget.
   Expected: an inbox item, and no Lead call.

**Redo if**
- Limits are counted in memory and reset on a restart. Count them from the `interventions` table.
