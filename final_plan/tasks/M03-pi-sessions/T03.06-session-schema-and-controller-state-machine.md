### Goal
One `:gen_statem` per Pi session that starts the process, mirrors Pi's state (idle, running, settling, …), delivers messages only at safe moments, answers extension dialogs so a headless session never hangs, and records every state change.

### Context

### Specification
Controller init args: `%{session: %Session{}, spec: %Si.Runner.Spec{}, runner: module (default Si.Runner.Local), ui_handler: module | nil}`.

States and transitions exactly as `03-data-model.md` §3.1. `callback_mode: [:handle_event_function, :state_enter]`.

Startup: in `:starting`, start the runner, then send `get_state`; on its response store `sessionFile` and `sessionId` from its data in the row, go to `:idle` and set `started_at`. No response within 30 s → stop the runner (`:kill`), state `:lost`, reason `start_timeout`.

Public API (called through `Si.Sessions`, T03.07):
```elixir
@spec prompt(pid(), String.t(), keyword()) :: :ok | {:error, term()}   # opts: as: :auto | :steer | :follow_up
@spec abort(pid()) :: :ok | {:error, term()}
@spec request(pid(), String.t(), map(), timeout()) :: {:ok, term()} | {:error, term()}   # raw RPC command
@spec state(pid()) :: atom()
@spec stop(pid(), term()) :: :ok
@spec park(pid()) :: :ok
```
Delivery rules:
- `prompt(as: :auto)`: `:idle` → send `prompt` now; `:running`/`:settling` → enqueue as a follow-up, delivered when `:idle` is reached (one queued message per settle; the next waits for the next settle).
- `as: :steer`: `:running` → send `steer`; otherwise behaves like `:auto`.
- `as: :follow_up`: always enqueue (delivered at the next `:idle`, immediately if already idle).
- A `prompt` response with `data.disposition == "handled"` does not move the state to running.

Events from Pi (via `Si.Pi.Rpc.handle_line/2`): `agent_start` → `:running`; `agent_end` → `:settling`; `agent_settled` → `:idle` (then deliver one queued message). Duplicate or out-of-order events are ignored (e.g. `agent_settled` while idle). All other events update `last_event_at` (write to DB at most once per second) and are broadcast on `"session:<id>"` as `{:pi_event, map}`.

Noise lines: log at warning level (first 200 bytes) and count; never crash.

UI requests: dialog methods (`select`, `confirm`, `input`, `editor`) are passed to `ui_handler.handle(session, request)` which returns `:cancel | {:value, v} | :defer`. The default handler (until T05.06 adds the inbox handler) records event `session.ui_request` and answers `:cancel`. Fire-and-forget methods (`notify`, `setStatus`, …) are broadcast and otherwise ignored.

Request deadlines: `prompt` and `compact` get 15 minutes, every other command 30 s. Pi can run compaction inside the `prompt` preflight before it answers, which takes 20–90 s or more (Pair F-06), so `compaction_start`/`compaction_end` events extend a pending `prompt`'s deadline. On a deadline, reply `{:error, :timeout}` to the caller and drop the id, but **never stop the session**: send `get_state` and reconcile the state from its answer.

Compaction: `compaction_start` sets a `compacting` flag and `compaction_end` clears it. No queued message is delivered while it is set (Pair F-22); the flag is broadcast for the cockpit.

Session size: after each `agent_settled`, stat the session file; above `sessions.max_file_mb` (default 64) record event `session.large` and broadcast `{:session_large, id}` so the owner starts a fresh session next time (Pair F-05). Si never sends whole-transcript commands (`get_messages`, `get_entries`) in normal operation.

Runner exit: when not in `:stopping` → `:lost` with event `session.lost` (`exit_status`); in `:stopping` → `:stopped` with event `session.stopped`. Pending requests get `{:error, :session_down}`.

Every state change: update the row (`state`, timestamps) and append `session.state_changed` (`from`, `to`) in one transaction; broadcast `{:session_state, id, to}` on `"sessions"` and `"session:<id>"`.

`fake_pi.mjs` modes (reads stdin JSONL, writes stdout JSONL, exits on stdin end):
- `normal`: `get_state` → success; `prompt` → success `{disposition: "started"}`, then `agent_start`, a `message_end` with text `ok`, `agent_end`, `agent_settled` (with small delays).
- `noise`: like normal but prints `garbage line` and a partial JSON line before every event.
- `slow_settle`: waits 1 s between `agent_end` and `agent_settled`.
- `dialog`: after `prompt`, emits an `extension_ui_request` `confirm` and waits for the response before settling; echoes the response into a `message_end` text.
- `crash_after_prompt`: exits with status 7 after `agent_start`.
- `no_ready`: never answers `get_state`.
- `compaction_preflight`: on `prompt`, emits `compaction_start`, waits `FAKE_PI_DELAY_MS`, emits `compaction_end`, then answers and runs normally.
- `oversized`: before its normal events, writes one line longer than the limit the test configures.

### Tests
(All with `fake_pi.mjs` run through `node`, no real Pi.)
- Start → `:idle`; prompt → `:running` → `:settling` → `:idle` with the matching events in the `events` table.
- A prompt while running is queued and delivered after the settle (fake records received commands; assert order).
- `as: :steer` while running sends `steer`.
- Noise lines are counted and the session keeps working.
- Dialog: default handler answers `cancelled: true`; the fake echoes it.
- Crash → `:lost` with exit status 7; pending request gets `{:error, :session_down}`.
- `no_ready` → `:lost` with `start_timeout` (use a short timeout via init arg in the test).
- `compaction_preflight` with a 3 s delay and a 2 s prompt deadline: the compaction events extend the deadline, no timeout, the session reaches idle.
- `oversized`: the line is skipped and counted; the session keeps working.
- A follow-up queued while `compacting` is set is delivered only after `compaction_end`.
- The row's `session_file` comes from `get_state`.
- Performance: 10,000 synthetic event lines handled in < 10 s total and p95 < 1 ms per line (measure `handle_event` time with `:timer.tc` in a loop against the state functions, not the process mailbox).
