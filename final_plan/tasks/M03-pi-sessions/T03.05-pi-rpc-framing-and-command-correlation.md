### Goal
Pure, well-tested building blocks for Pi's RPC protocol: strict JSONL framing and request/response correlation. The session controller (T03.06) uses them.

### Context
`04-protocols.md` §1 (framing rules, commands). Pi `docs/rpc.md`, `docs/rpc-commands.md`, `docs/json.md`, `docs/rpc-extension-ui.md`.

### Deliverables

### Specification
`Si.Pi.Jsonl` (pure):
```elixir
@spec new(pos_integer()) :: t()                         # max record bytes, default 64 MiB
@spec feed(t(), binary()) :: {:ok, [binary() | {:oversized, non_neg_integer()}], t()}
@spec encode(map()) :: iodata()                         # Jason.encode_to_iodata!(map) ++ "\n"
```
Splits only on byte `\n`; strips one trailing `\r`; keeps the partial tail; empty lines are skipped. A record that grows beyond the limit is **skipped, not fatal**: bytes are discarded until the next `\n`, and the record is reported as `{:oversized, size}` so the controller can log and count it (Pair F-05 killed workers at a 16 MiB frame limit). Never splits on U+2028/U+2029 (they are multi-byte UTF-8 sequences, so splitting on `\n` bytes is enough; add a test proving it).

`Si.Pi.Rpc` (pure state):
```elixir
@spec new() :: t()
@spec command(t(), String.t(), map(), term()) :: {id :: String.t(), iodata(), t()}   # type, params, tag (e.g. the gen_statem `from`)
@spec handle_line(t(), binary()) ::
        {{:response, id :: String.t(), tag :: term(), {:ok, term()} | {:error, String.t()}}, t()}
        | {{:event, map()}, t()}
        | {{:ui_request, map()}, t()}
        | {{:noise, binary()}, t()}
@spec ui_response(String.t(), :cancelled | {:value, term()}) :: iodata()
@spec pending(t()) :: [{String.t(), term(), integer()}]       # id, tag, sent_at (monotonic ms) for timeout sweeps
@spec drop(t(), String.t()) :: t()
```
- Ids: `"r1"`, `"r2"`, ... per session.
- A line that is not valid JSON, or valid JSON that is not an object → `{:noise, first 200 bytes}`.
- `type == "response"`: known id → `{:response, id, tag, result}` where `result` is `{:ok, data}` when `success` is true, else `{:error, error}`; unknown id → `{:noise, ...}`.
- `type == "extension_ui_request"` → `{:ui_request, record}`.
- Anything else → `{:event, record}`.
- `ui_response/2` builds `{"type": "extension_ui_response", "id": id, "cancelled": true}` or `{..., "value": v}`.

### Tests
- Jsonl: one record split into many chunks (property test with random chunk boundaries over a list of random JSON objects, including strings containing ` ` and ` ` and CRLF endings) yields exactly the original records in order.
- Jsonl: a record larger than the limit is skipped and reported as `{:oversized, bytes}`, and the records after it still parse (also when the oversized record arrives in many chunks).
- Rpc: responses are matched by id even when out of order; `success: false` gives `{:error, msg}`; unknown id and garbage lines are noise; UI requests are classified; `ui_response/2` output decodes to the documented shape.
