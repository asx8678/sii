### Goal
Si never runs your global `pi`. It installs pinned versions of Pi, Fabric and Fovea into `$SI_HOME/toolchains/<id>/` and resolves the binary and extension paths from there.

### Context
`01-architecture.md` D5, `02-repo-layout.md` §5, `05-schemas-and-config.md` §1 (`toolchain`). Facts (27 Sep 2026): `@earendil-works/pi-coding-agent` 0.87.1 has `bin.pi = dist/bundle/cli.js` and needs Node ≥ 22.19; `pi-fabric` 0.97.0 (extension entry `./dist/index.js`, Node ≥ 24); `pi-fovea` 0.31.1 (extension entry `./src/index.ts`, bin `fovea`). All three are on npm. Local Node is 24.21.0, npm 11.19.0.

### Deliverables
- Migration `create_toolchains`; `lib/si/toolchains.ex` (`Si.Toolchains`, GenServer serializing installs), `lib/si/toolchains/toolchain.ex` (schema + struct with resolved paths).
- CLI: `si doctor`, `si toolchain install [--force]`.
- Tests `test/si/toolchains_test.exs` with a fake `npm` (and one `@tag :pi` real install test).

### Specification
```elixir
@spec current() :: {:ok, Toolchain.t()} | {:error, term()}   # for the versions in settings; installs if needed (blocking, serialized)
@spec ensure(%{pi: String.t(), fabric: String.t(), fovea: String.t()}) :: {:ok, Toolchain.t()} | {:error, term()}
@spec paths(Toolchain.t()) :: %{pi_bin: Path.t(), fabric_ext: Path.t(), fovea_ext: Path.t(), fovea_bin: Path.t(), node_modules: Path.t()}
@spec doctor() :: [%{check: String.t(), ok: boolean(), detail: String.t()}]
```
Install (`ensure/1` when no `ready` row exists for the versions):
1. Insert a row (`installing`) with a new `tc_` id; dir `Si.Paths.toolchain_dir(id)`.
2. Write `package.json`:
   ```json
   {"name": "si-toolchain", "private": true,
    "dependencies": {"@earendil-works/pi-coding-agent": "0.87.1", "pi-fabric": "0.97.0", "pi-fovea": "0.31.1"}}
   ```
   For a `path:<dir>` source: run `npm pack --pack-destination <tmp>` in that dir (this runs the package's own `prepack`, which for pi-fabric requires Bun), verify the packed version equals the pinned version, and use `file:<tarball>` as the dependency spec.
3. `npm install --omit=dev --no-audit --no-fund --prefix <dir>` via `MuonTrap.cmd` (timeout 15 min), output to `$SI_HOME/logs/toolchain-<id>.log`. The npm executable is `Application.get_env(:si, :npm_cmd, "npm")` (tests inject a fake).
4. Verify: `<dir>/node_modules/.bin/pi --version` prints the pinned Pi version; `node_modules/pi-fabric/package.json` and `node_modules/pi-fovea/package.json` versions match; `node --version` major ≥ 24.
5. Status `ready`, event `toolchain.ready` (stream `system`). On failure: status `failed`, `error` set, and `{:error, reason}` with the log path.

Test override: when `Application.get_env(:si, :toolchain_dir)` is set (tests only), `current/0` returns a `%Toolchain{}` for that directory after the version checks of step 4, without a database row and without installing. `Si.Test.Toolchain` (T03.03) uses it so `:pi` tests share one installed toolchain.

`si doctor` prints one line per check with `ok`/`FAIL`: node version (≥ 24), npm present, git version, toolchain status and versions, bridge token file present (from T04.02; `missing` is a warning until then), database reachable. Exit 0 when all required checks pass, else 1.

### Tests
- Fake npm script (written by the test into a temp dir) that creates `node_modules/.bin/pi` (a shell script printing `0.87.1`), `node_modules/pi-fabric/package.json` (`{"version":"0.97.0"}`), `node_modules/pi-fovea/package.json`: `ensure/1` produces a `ready` row and correct `paths/1`.
- A fake npm that exits 1 → status `failed` and the log path in the error.
- A fake `pi` printing a different version → `{:error, {:version_mismatch, "pi", ...}}`.
- Concurrent `current/0` calls install only once.
- With `:toolchain_dir` set to a directory holding the fake install, `current/0` returns it without calling npm.
- `@tag :pi` `@tag :slow`: real install from npm; `pi --version` is `0.87.1`.

### Acceptance criteria
Tests pass; `bin/ci` passes; `bin/si toolchain install` completes on this machine and `bin/si doctor` prints all checks `ok` (except the bridge token warning).

**Expected result.**
- Si installs the pinned Pi, Fabric and Fovea into `$SI_HOME/toolchains/<id>/` with npm, one install at a time.
- It verifies their versions and records the toolchain.
- It never uses a global `pi`.
- `si doctor` and `si toolchain install` work.
- In tests, `Application.get_env(:si, :toolchain_dir)` points `current/0` at an existing directory, with no install.

**Checks**
1. `bin/si doctor; echo "exit=$?"`.
   Expected: one line per check, all `ok` except the bridge token warning, and `exit=0`.
2. `~/.si/toolchains/*/node_modules/.bin/pi --version`.
   Expected: `0.87.1`.
3. `grep -rnE 'find_executable\("pi"\)|System.cmd\("pi"' lib`.
   Expected: no output.
4. `ls ~/.si/logs/toolchain-*.log`.
   Expected: the install log exists.
5. `time bin/si toolchain install`, run a second time.
   Expected: it reports the toolchain as already ready, and takes under 2 s. With `--force`, it installs again.
6. The concurrency test.
   Expected: two parallel `current/0` calls cause one install, which the fake npm's call log shows.
7. The override test.
   Expected: with `:toolchain_dir` set to a verified directory, `current/0` returns it without calling npm and without a database row.

**Redo if**
- Two installs can run at the same time. Rewrite so that installs are serialized through the GenServer.
- Verification checks only exit codes. Rewrite it to compare the versions.
