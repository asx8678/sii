### Goal
Workflows as data: a JSON Schema, built-in templates, `extends` with deterministic merging, a small safe condition language, and a content hash that identifies each exact workflow.

### Context
`05-schemas-and-config.md` §4. Blueprint: workflows are YAML/JSON validated with JSON Schema; runs pin the content hash.

### Deliverables

- Tests `test/si/workflows_test.exs`, `test/si/workflows/expr_test.exs`.

### Specification
Top-level keys: `extends` (template name), `name`, `inputs` (`name → {type: string|number|boolean, default?}`), `tier` (`quick|standard|full`), `acceptance` (`from_intake` or a list), `repo_profile` (path, default `.si/repo.yml`), `roles` (`name → {profile, route: {prefer: [model], differ_from: role, family: other|any}, fabric: {agents: {maxDepth}, mesh: {enabled}, fullCodeMode}, fovea: on|off|impact_only, worktree: boolean}`), `steps` (`key → step`), `budget` (`{total: "$6" | 6.0, supervision_share}`), `delivery` (`{target: branch|pr|patch|merge_local|none}`), `on_interrupt` (`ask|resume|cancel`).

Step fields (a step's kind is given by `kind:`; templates set it explicitly):

| kind | fields |
|---|---|
| `plan` | `by` (role), `output: plan_graph`, `critique: {by}`, `gate: auto|lead|you` |
| `build` | `needs`, `for_each: plan.steps` or `task: "<text with {{inputs.x}}>"`, `spawn` (role), `order: depends_on`, `max_parallel`, `sticky`, `checks: [...]`, `review: {by, until: approved, max_rounds, fix: writer|astra|auto}`, `integrate: merge_queue` |
| `accept` | `needs`, `review: {by}`, `final_reviewer: auto|always|never` |
| `review` | `by`, `subject: {head: "{{inputs.head}}", base: "{{inputs.base}}"}`, `max_rounds`, `fix` |
| `gate` | `needs`, `by: you|lead`, `text` |
| `deliver` | `needs`, `target`, `gate: you|none` |
| `notify` | `needs`, `text` |
| `loop` | `needs`, `body: [step keys]`, `until: <expr>`, `max_rounds` |

Merge (`extends`, depth ≤ 3): maps merge recursively, lists replace, `null` deletes the key.
Canonical form: merged map → JSON with keys sorted recursively → `hash = sha256 hex`. `workflows` row upserted by hash with `origin` (`builtin`, `repo` (from `.si/workflows/`), `user` (`$SI_HOME/workflows/`), `agent`); `approved` is true except for `agent` origin.
`Si.Workflows.Expr`: parse and evaluate conditions over a context map without `Code.eval`: literals (strings, numbers, booleans, null), paths (`steps.build.status`, `run.round`), `==`, `!=`, `<`, `<=`, `>`, `>=`, `and`, `or`, `not`, parentheses. Unknown paths evaluate to `null`. Parse errors are validation errors.
```elixir
@spec load(String.t() | Path.t()) :: {:ok, %{workflow: map(), hash: String.t()}} | {:error, [String.t()]}
@spec template(String.t()) :: {:ok, map()} | {:error, :not_found}
@spec approve(String.t(), String.t()) :: :ok      # hash, actor
```
Templates must implement: `quick` (one build step from `inputs.goal`, quick checks, Astra review, merge queue, deliver branch), `standard` (plan with critique and Lead gate → build for_each → accept → deliver), `full` (standard + `gate: you` for the plan + `final_reviewer: always`), `review-only`, `fix-tests` (see T09.11).

### Tests
Every template loads and validates; `extends` merge semantics (map merge, list replace, null delete); hash stability (key order does not matter; any value change changes the hash); expression parser and evaluator (precedence, unknown paths, errors).

**Expected result.**
- Workflows are validated data:
  - a JSON Schema;
  - five built-in templates;
  - deterministic `extends` merging: maps merge, lists replace, `null` deletes;
  - a canonical SHA-256 hash;
  - a safe condition language evaluated without `Code.eval`.

**Checks**
1. `grep -rnE 'Code\.eval|Code\.string_to_quoted' lib/si/workflows`.
   Expected: no output.
2. Two templates that differ only in key order.
   Expected: the same hash. Change one value, and the hash changes.
3. `mix run -e 'for t <- ~w(quick standard full review-only fix-tests), do: IO.inspect(Si.Workflows.template(t) |> elem(0))'`.
   Expected: `:ok` five times.
4. Expression precedence: `a or b and not c` with a set of values.
   Expected: the same result as `a or (b and (not c))`.

**Redo if**
- The expression language is evaluated with Elixir's evaluator. Rewrite it as a parser and evaluator over the context map.
