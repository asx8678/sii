### Goal
Execute a workflow as a durable run: one `:gen_statem` per run that executes steps in dependency order, records every step change, pins versions, and resumes after a node restart.

### Context
`03-data-model.md` §3.5 (run states); `01-architecture.md` §7.

### Deliverables
- Migrations `create_runs`, `create_run_steps`; `lib/si/runs.ex` (`Si.Runs`), `lib/si/runs/run.ex` (`Si.Runs.Run`), step executors under `lib/si/runs/steps/` (`build`, `gate`, `notify`, `loop`; `plan`, `accept`, `deliver`, `review` are completed by T09.04–T09.11 and start as stubs that fail with `not implemented`); `Si.Runs.Supervisor`; `si workflow check --dry-run`; tests `test/si/runs_test.exs`.

### Specification
```elixir
@spec start(String.t() | Path.t(), map(), Si.Repos.Repo.t(), keyword()) :: {:ok, String.t()} | {:error, term()}   # workflow, inputs, repo, opts (budget, tier)
@spec get(String.t()) :: Run.t() | nil
@spec cancel(String.t()) :: :ok
@spec resume_all() :: :ok        # called at boot
```
- `start/4`: load + validate the workflow; refuse unapproved workflows (`{:error, :workflow_not_approved}` with an inbox item for approval); insert `runs` with `versions` = `%{toolchain_id, pi, fabric, fovea, bridge, workflow_hash}` and `base_sha` (integration head now); create `run_steps` rows (`pending`); start the gen_statem.
- Scheduling: a step becomes `running` when all `needs` are `done`; independent steps run concurrently. Step results are stored in `run_steps.data`.
- `build` step without `for_each`: creates one task from `task` (template rendered with `inputs`), `run_id`, tier, checks, review settings; waits for `landed` (step done) or `escalated`/`failed` (step `blocked` → the run waits; an inbox item exists from the task).
- Sessions started for a run use the run's toolchain (by `toolchain_id`), even if settings changed later.
- Every step change: update the row and append `run.step_changed` (`step`, `from`, `to`) — one transaction.
- Resume: `resume_all/0` starts a gen_statem for each run not in `done|failed|cancelled` and rebuilds its state from `run_steps` rows; running steps re-attach to their tasks (tasks are durable and their loops restart on boot: add `Si.Tasks.resume_loops/0` for tasks in active states).
- `on_interrupt: ask` → after a restart the run pauses and creates an inbox item (`resume` / `cancel`); `resume` → continue; `cancel` → cancel.
- `si workflow check --dry-run <name|file>`: creates a scratch fixture repo (a tiny Elixir or shell-based project with a `.si/repo.yml` using trivial commands), generates faux scripts per role (Lead plans two steps via `si_plan`; builders write a file and report; Astra approves; critic approves) and runs the workflow end to end; prints each step change; exit 0 when the run reaches `done`.

### Tests
- A `quick` run lands its task and reaches `done` (faux, `@tag :pi`).
- Parallel independent steps run concurrently.
- Kill the run process and restart it through `resume_all/0` → it continues from the recorded steps.
- `on_interrupt: ask` creates the inbox item.
- Pinned toolchain id is used after settings change.

### Acceptance criteria
Tests pass (including `--include pi`); `si workflow check --dry-run quick` exits 0.

**Expected result.**
- Runs are durable `:gen_statem`s. They execute steps in dependency order, run independent steps concurrently, and record every step change in one transaction.
- Runs pin their toolchain and workflow hash, and resume after a restart, with `on_interrupt` respected.
- `si workflow check --dry-run` runs a template end to end with scripted roles.

**Checks**
1. `bin/si workflow check --dry-run quick; echo "exit=$?"`.
   Expected: the step changes are printed, and `exit=0`.
2. Kill a run process in the middle of a step, then call `resume_all/0`.
   Expected: it continues from the recorded steps; no step runs twice.
3. Change `toolchain.pi` in the settings during a run.
   Expected: the run's sessions keep using the pinned toolchain id.
4. The stub steps (`plan`, `accept`, `deliver`, `review`).
   Expected: they fail with `not implemented` until their tasks exist.

**Redo if**
- Run state lives only in process memory, and a restart loses progress. Rewrite it so that the state is rebuilt from `run_steps` rows.
