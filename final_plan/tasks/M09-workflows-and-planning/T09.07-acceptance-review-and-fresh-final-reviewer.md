### Goal
When every step has landed, check the whole result against the acceptance criteria; on full runs and risky changes, add a reviewer that has seen nothing before.

### Deliverables
- Accept step executor; prompts `priv/prompts/astra/acceptance.md`; tests `test/si/runs/accept_step_test.exs` (`@tag :pi`).

### Specification
- Snapshot: `freeze_ref(repo, integration head, run base)`.
- Acceptance review: Astra (a new thread, `purpose: :acceptance`), context = criteria list + the whole run diff + check results of the landing snapshot; instructions: for each criterion, say where it is satisfied (file, test) or raise a blocking finding with evidence.
- Revise → create one fix task per blocking finding (title `Fix: <problem>`, scope = the finding's file, description = problem + evidence + suggested fix), run them through the normal build flow, then acceptance round 2; at most 2 rounds, then escalate.
- Final reviewer when `final_reviewer: always`, or `auto` and any changed file matches `risky_paths`: a new session (role `critic`, profile `reviewer`) whose model differs in family from the writers and, when possible, from Astra's model; `purpose: :final`; fresh context (no earlier rounds). Revise → fix tasks as above.

### Tests
(`@tag :pi`) Approve path; revise creates fix tasks that land and a second round approves; risky path triggers the final reviewer with a different model.

### Acceptance criteria
Tests pass; `bin/ci` passes.

```bash
mix test test/si/runs/accept_step_test.exs --include pi
```

### After implementing

Do this after the Verify commands pass. Run `bin/task-check` first, then these checks. Each check states the result you must see. Any other result means the task is not done: fix the cause in the code (never by changing what a test expects), or rewrite the part named under **Redo if**, then run `bin/task-check` and every check below again from the top. The limits on fix attempts, how to redo a task, and the evidence the completion note needs are in [10-after-each-task](../../10-after-each-task.md).

**Expected result.**
- When every step has landed, Astra reviews the whole result against the acceptance criteria.
- A revise verdict creates fix tasks, followed by a second round.
- A fresh final reviewer from another family reviews full and risky runs.

**Checks**
1. A revise verdict with two blocking findings.
   Expected: two fix tasks, each scoped to its finding's file.
2. A risky path changed in a standard run with `final_reviewer: auto`.
   Expected: a final reviewer whose family differs from the writers' family and, when possible, from Astra's.
3. The final reviewer's context.
   Expected: no earlier rounds.

**Redo if**
- The final reviewer reuses Astra's thread or session. Rewrite it with a new thread and a new session.
