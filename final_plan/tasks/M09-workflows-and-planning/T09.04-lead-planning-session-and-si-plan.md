### Goal
The Lead turns a goal into acceptance criteria and a dependency graph of steps, validated before anything is built.

### Deliverables
- `priv/prompts/lead/system.md`, `priv/prompts/lead/plan.md`; `lib/si/plan.ex` (`Si.Plan`), `lib/si/plan/graph.ex` (`Si.Plan.Graph`); migration `create_plan_revisions`; the plan step executor; the `si_plan` tool handler; tests `test/si/plan/graph_test.exs`, `test/si/runs/plan_step_test.exs` (`@tag :pi`).

### Specification
Plan step:
1. Worktree `purpose: :worker` at the run base, owner = run id (read-only use).
2. Lead session: role `lead`, profile `lead` (Fovea + bridge, read-only tools), model `models.lead`, `--append-system-prompt lead/system.md`.
3. Prompt (`lead/plan.md`, version 1): the goal, the tier, the repo profile commands, the risky paths, and the instructions: explore the code, then call `si_plan` with 2–6 acceptance criteria (each checkable by a test, a command or an observable behavior) and steps (small, independently testable, with `depends_on`, `files` globs, `test_paths`, and the indexes of the criteria each step serves).
4. `si_plan` handler → `Si.Plan.Graph.validate(args)`:
   - ids unique and matching `^s[0-9]+$`; `depends_on` reference existing ids; acyclic;
   - 2 ≤ acceptance count ≤ 6; every criterion served by at least one step; every step has `files` and either `test_paths` or at least one criterion;
   - steps with overlapping `files` globs and no path between them in the graph get an added edge (lower id first); record the added edges in the result as notes.
   Errors → tool error listing every problem (the Lead fixes and calls again). Success → `plan_revisions` row `n = 1`, `status: proposed`, `graph` = normalized plan, reply `%{recorded: true, revision: 1, notes: [...]}`.
5. Stop the Lead session (short activations: later decisions use the ledger, not this chat).
`Si.Plan` API: `current(run_id)`, `revisions(run_id)`, `record(run_id, graph, attrs)`.

### Tests
Graph validation cases (cycle, missing dependency, unserved criterion, overlap → added edge); `@tag :pi` plan step with a faux Lead: first `si_plan` call cyclic (tool error), second valid → revision recorded; run proceeds to the next step.

### Acceptance criteria

**Expected result.**
- The plan step starts a read-only Lead session.
- `si_plan` is validated:
  - ids and dependencies;
  - no cycles;
  - 2–6 acceptance criteria, each served by at least one step;
  - an added edge wherever file globs overlap.
- A valid plan is stored as revision 1, and the Lead session is stopped.

**Checks**
1. A cyclic plan, then a valid plan (`:pi` faux).
   Expected: a tool error that lists every problem, then `recorded: true, revision: 1`.
2. Two independent steps whose `files` overlap.
   Expected: an edge is added from the lower id to the higher one, and reported in `notes`.
3. The Lead session after the plan is recorded.
   Expected: `stopped`.

**Redo if**
- Validation errors are reported one at a time. Rewrite it to report every problem in one tool error.
