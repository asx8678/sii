### Goal
Start a run from a goal in the browser and follow it step by step.

### Deliverables
"New run" form on `SiWeb.RunsLive`, run page `SiWeb.RunLive` (`/runs/:id`); tests.

### Specification
- Form: repository, goal (text area), template or workflow file from the repo's `.si/workflows/`, tier, budget → `Si.Intake` (T09.08), which may first create an estimate approval in the inbox.
- Run page: the step list with live status, the current plan revision (steps with dependencies), tasks with their status, cost so far against the budget, and buttons Cancel run and Open inbox items for this run.

### Tests
Form submission starts intake (stub); live step updates; cancel.

### Acceptance criteria
Tests pass; `bin/ci` passes.

### Verify
```bash
mix test test/si_web/live/runs_live_test.exs
```

### After implementing

Do this after the Verify commands pass. Run `bin/task-check` first, then these checks. Each check states the result you must see. Any other result means the task is not done: fix the cause in the code (never by changing what a test expects), or rewrite the part named under **Redo if**, then run `bin/task-check` and every check below again from the top. The limits on fix attempts, how to redo a task, and the evidence the completion note needs are in [10-after-each-task](../../10-after-each-task.md).

**Expected result.**
- Runs can be started from the browser through `Si.Intake`.
- The run page shows steps, the plan, tasks and cost against the budget, live, with Cancel.

**Checks**
1. Submit the form with an estimate above the threshold.
   Expected: an inbox approval before the run starts.
2. Live step updates.
   Expected: they appear without a reload.
3. Cancel.
   Expected: the run is `cancelled`, and its active tasks are cancelled.

**Redo if**
- The LiveView starts runs directly. Rewrite it to go through `Si.Intake`.
